org.duckdns.hjow.swingwebpanel.js.num
Class NumberConversion

java.lang.Object
  org.duckdns.hjow.swingwebpanel.js.num.NumberConversion

public final class NumberConversion
extends java.lang.Object

ECMAScript 2015 number conversions on plain Java doubles: Number::toString (radix 10 and other radixes), Number.prototype.toFixed / toExponential / toPrecision, StringToNumber, parseInt, parseFloat and the integer conversion abstract operations ToInteger, ToInt32, ToUint32, ToUint16 and ToLength.

Assumptions (the ECMA-262 text could not be fetched, so these follow the ES2015 algorithms from knowledge): toString radix other than 10 follows the V8 algorithm (the spec leaves it implementation dependent); toFixed checks the digit range before NaN while toExponential/toPrecision check NaN and Infinity first; ties in toFixed/toExponential/toPrecision choose the larger n (round half up on the magnitude). Methods that the spec defines as RangeError throw NumberRangeException. All methods are static, stateless and thread-safe.

순수 Java double 위의 ECMAScript 2015 숫자 변환: Number::toString(10진 및 다른 진법), Number.prototype.toFixed / toExponential / toPrecision, StringToNumber, parseInt, parseFloat, 정수 변환 추상 연산 ToInteger, ToInt32, ToUint32, ToUint16, ToLength.

가정(ECMA-262 본문을 조회하지 못해 ES2015 알고리즘에 대한 지식을 따랐다): 10진이 아닌 진법의 toString 은 V8 알고리즘을 따른다(규격은 구현 정의). toFixed 는 자릿수 범위를 NaN 보다 먼저 검사하고, toExponential/toPrecision 은 NaN 과 Infinity 를 먼저 검사한다. toFixed/toExponential/toPrecision 의 동점은 큰 n 을 고른다(크기에 대한 반올림). 규격이 RangeError 로 정한 경우 NumberRangeException 을 던진다. 모든 메서드는 정적이고 상태가 없으며 스레드 안전하다.
