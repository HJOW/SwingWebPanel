Class PromiseJobs

java.lang.Object

public final class PromiseJobs
extends java.lang.Object

Where promise jobs go and who is told about unhandled rejections. Promise jobs (PromiseReactionJob, PromiseResolveThenableJob) are never run synchronously: they are put on the job queue of the realm and run when the host drains the queue (the event loop of the browser, or runAll() in tests).

The queue is chosen in this order: a queue installed with setQueue(JsRealm, JobQueue); the queue of the realm itself if the realm class offers getJobQueue() (the engine core adds it; it is looked up by reflection so that this package does not depend on it); otherwise a private SimpleJobQueue that the host must drain with drain(JsRealm). The per-realm data lives in a hidden intrinsic, so it is released together with the realm.

promise 작업이 어디로 가는지, 처리되지 않은 거부를 누구에게 알리는지 정한다. promise 작업(PromiseReactionJob, PromiseResolveThenableJob)은 절대 동기적으로 실행되지 않는다. realm 의 작업 큐에 넣어 두었다가 호스트가 큐를 비울 때(브라우저의 이벤트 루프, 시험에서는 runAll()) 실행한다.

큐는 다음 순서로 고른다: setQueue(JsRealm, JobQueue) 로 설치한 큐, realm 클래스가 getJobQueue() 를 제공하면 realm 자신의 큐(엔진 코어가 추가하며 이 패키지가 코어에 의존하지 않도록 리플렉션으로 찾는다), 그 밖에는 호스트가 drain(JsRealm) 으로 비워야 하는 비공개 SimpleJobQueue. realm 별 자료는 숨겨진 내장 객체에 있으므로 realm 과 함께 해제된다.
