public class JsException
extends java.lang.RuntimeException

A JavaScript exception travelling through Java code. It carries either an arbitrary thrown JavaScript value (throw 42) or a lazily created native error (kind + message) so that Java built-ins can throw JsException.typeError("...") without needing a realm; the error object is created when the exception is caught by JavaScript code via getValue(JsRealm). Java stack traces are disabled for speed; position information of syntax errors is kept in getLine(), getColumn() and getSourceName().

Java 코드를 통과하는 JavaScript 예외. 임의로 던진 JavaScript 값(throw 42)이나, 늦게 생성하는 기본 오류(종류 + 메시지)를 담는다. 덕분에 Java 내장 함수는 realm 없이 JsException.typeError("...") 를 던질 수 있고, JavaScript 코드가 예외를 잡을 때 getValue(JsRealm) 로 오류 객체가 만들어진다. 속도를 위해 Java 스택 추적은 끄며, 구문 오류의 위치 정보는 getLine(), getColumn(), getSourceName() 에 둔다.

recordThrowSite

public void recordThrowSite(java.lang.String source,
                            int atLine,
                            int atColumn)
Remembers where in a script the exception was first seen. The interpreter calls it for every expression that the exception leaves, so the first call (from the innermost expression that was being evaluated) wins and later calls do nothing. Unlike getLine() (a position of a syntax error that is part of getMessage()) this position never changes the message; it only lets a host report where a runtime error happened.

예외가 스크립트의 어디에서 처음 관찰되었는지 기억한다. 인터프리터가 예외가 빠져나가는 모든 표현식에서 호출하므로 첫 호출(평가 중이던 가장 안쪽 표현식)이 이기고 이후 호출은 아무것도 하지 않는다. 구문 오류의 위치(getLine(), getMessage() 에 포함됨)와 달리 이 위치는 메시지를 바꾸지 않으며, 호스트가 런타임 오류가 어디서 났는지 알려 주는 데에만 쓴다.

Parameters:
source - the script name / 스크립트 이름
atLine - the 1-based line / 1부터 시작하는 줄
atColumn - the 1-based column / 1부터 시작하는 열
