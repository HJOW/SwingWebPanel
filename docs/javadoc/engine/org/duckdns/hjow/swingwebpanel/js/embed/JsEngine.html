org.duckdns.hjow.swingwebpanel.js.embed
Class JsEngine

java.lang.Object
  org.duckdns.hjow.swingwebpanel.js.embed.JsEngine

public final class JsEngine
extends java.lang.Object

A self contained JavaScript engine targeting ECMAScript 2026 that any Java program can use, with or without the browser component. It needs nothing but the JRE (Java 6 or later): no external library, no native code, no other script engine. One JsEngine owns one realm: a global object with the complete set of standard built-in objects (Object, Array, Promise, Map, JSON, RegExp, typed arrays, Proxy ...). Engines are independent of each other. 

 JsEngine engine = new JsEngine();
 engine.put("name", "world");
 Object r = engine.eval("`hello ${name}`.toUpperCase()");        // "HELLO WORLD"
 engine.eval("function twice(x) { return x * 2; }");
 Object d = engine.call("twice", Integer.valueOf(21));           // Double 42.0

Global names (stand-alone mode)

The global object has the standard built-ins of ECMA-262 6th edition, globalThis, console (see below) and print(...) (a convenience that writes the arguments as one line of level log). It has no window, document, DOM, fetch, XMLHttpRequest, storage, and no timers (setTimeout and friends): a stand-alone engine has no event loop. A host that needs timers registers its own functions with putFunction(String, JsHostFunction) and runs its own loop; the engine only guarantees that promise jobs (microtasks) run: after every top-level eval, call and evalModule the engine runs all pending jobs, like the microtask checkpoint of a browser. A script reaches Java code only through functions that the host registered.

Errors

A syntax error, a throw and a runtime error of the script that nobody catches are thrown as JsScriptError (name, message, script name, line and column, thrown value). A host function that throws an exception gives the script an Error; if the script does not catch it, it reaches the caller as JsScriptError whose cause is the original exception. A script that the engine stops (step limit, time limit, cancel()) throws ScriptAbortedException, which a script cannot catch. A promise that is rejected and that nobody handles by the end of the jobs is reported to the console hook as an error (Uncaught (in promise) ...), so it does not vanish silently.

Threads

Every method (and every handle) locks the engine, which is the monitor of this object: the engine can be used from any thread but runs one script operation at a time, and operations on the same thread may nest (a host function may call the engine again). A caller that needs several calls to be one atomic step can synchronized (engine) around them. Only cancel() does not lock: it may be called from any thread to stop a running script.

Limits

getLimits() returns the ExecutionLimits of the engine: a step limit per task (default 200 million), an optional time limit (default none), the nesting of calls (default 400) and the length of strings. Set a time limit before running code that you do not trust.

브라우저 컴포넌트 유무와 관계없이 Java 프로그램에서 쓸 수 있는 ECMAScript 2026 대상 엔진. JRE(Java 6 이상) 외에는 아무것도 필요 없다. 외부 라이브러리, 네이티브 코드, 다른 스크립트 엔진을 쓰지 않는다. JsEngine 하나는 realm 하나를 가진다. 표준 내장 객체 (Object, Array, Promise, Map, JSON, RegExp, 타입 배열, Proxy ...)를 모두 갖춘 전역 객체이며 엔진끼리는 서로 독립이다. 사용 예는 위 코드를 본다.

전역 이름(독립 실행 모드)

전역 객체에는 ECMA-262 6판의 표준 내장 객체, globalThis, console(아래 참조), print(...)(인수를 log 수준의 한 줄로 쓰는 편의 함수)가 있다. window, document, DOM, fetch, XMLHttpRequest, 저장소는 없고 타이머도 없다(setTimeout 등). 독립 실행 엔진에는 이벤트 루프가 없기 때문이다. 타이머가 필요한 호스트는 putFunction(String, JsHostFunction) 로 자기 함수를 등록하고 자기 루프를 돌린다. 엔진이 보장하는 것은 promise 작업(마이크로태스크)의 실행뿐이다: 최상위 eval, call, evalModule 이 끝날 때마다 대기 중인 작업을 모두 실행한다(브라우저의 마이크로태스크 체크포인트와 같다). 스크립트는 호스트가 등록한 함수로만 Java 코드에 닿는다.

Java 값과 스크립트 값의 변환

위 표를 따른다. Java 에서 스크립트로: null, UNDEFINED, Boolean, 모든 Number(doubleValue() 로 숫자. 253 을 넘는 long 은 정밀도 손실), 문자열류와 Character와 Enum(name())은 문자열, Map 은 새 일반 객체(복사), Collection 과 모든 배열은 새 배열(복사), JsHostFunction 은 함수, JsHandle 은 스크립트 객체 자체, 그 밖의 것은 IllegalArgumentException(Java 객체, 클래스, 날짜, 스트림은 스크립트로 넘어가지 않는다). 스크립트에서 Java 로: undefined 는 UNDEFINED, null 은 null, 불리언은 Boolean, 숫자는 항상 Double(Integer/Long 이 아님. NaN, 무한대, -0 유지), 문자열은 String, 심볼은 Symbol(x) 형태의 문자열, 배열은 JsArrayHandle(살아 있는 List), 함수는 JsFunctionHandle, 그 밖의 객체(Date, RegExp, Map, promise, 오류 객체 포함)는 JsObjectHandle(살아 있는 Map). 복사본이 필요하면 toPlain(Object) 가 List 와 Map 으로 깊게 복사한다.

오류

아무도 잡지 않은 스크립트의 구문 오류, throw, 런타임 오류는 JsScriptError(이름, 메시지, 스크립트 이름, 줄, 열, 던진 값)로 던져진다. 예외를 던진 호스트 함수는 스크립트에 Error 를 주고, 스크립트가 잡지 않으면 원래 예외를 원인으로 가진 JsScriptError 로 호출자에게 닿는다. 엔진이 멈춘 스크립트(단계 수 제한, 시간 제한, cancel())는 스크립트가 잡을 수 없는 ScriptAbortedException 을 던진다. 거부되었고 작업이 끝날 때까지 아무도 처리하지 않은 promise 는 콘솔 연결에 오류(Uncaught (in promise) ...)로 보고되어 조용히 사라지지 않는다.

스레드

모든 메서드(와 모든 핸들)는 엔진, 즉 이 객체의 모니터를 잠근다. 엔진은 어느 스레드에서나 쓸 수 있지만 스크립트 연산을 한 번에 하나씩 실행하며, 같은 스레드의 연산은 중첩될 수 있다(호스트 함수가 엔진을 다시 호출해도 된다). 여러 호출을 한 단계로 묶으려면 synchronized (engine) 으로 감싼다. cancel() 만 잠그지 않으며, 실행 중인 스크립트를 멈추려고 어느 스레드에서나 호출할 수 있다.

제한

getLimits() 는 엔진의 ExecutionLimits 를 돌려준다: 작업당 단계 수(기본 2억), 선택적 시간 제한(기본 없음), 호출 중첩(기본 400), 문자열 길이. 믿을 수 없는 코드를 실행하기 전에 시간 제한을 지정한다.
