Class Lexer

java.lang.Object
  org.duckdns.hjow.swingwebpanel.js.parser.Lexer

public final class Lexer
extends java.lang.Object

The lexical analyzer (ECMA-262 6th edition clause 11). It converts source text into Tokens on demand: Unicode identifiers with escapes, numeric literals (decimal, 0x, 0o, 0b, legacy octal), string literals with all escapes, template literal parts, comments, line terminators (LF, CR, CRLF, LS, PS) and punctuators.

Two things depend on the syntactic context and are therefore requested by the parser: a regular expression literal (rescanRegExp(Token) re-reads a / or /= token as a regex) and the continuation of a template after } (rescanTemplateContinuation(Token)). saveState() and restoreState(State) support the parser's speculation and lookahead. Lexical errors are thrown as SyntaxError JsExceptions carrying line and column.

ECMAScript 2016-2022 additions recognized by the grammar include the exponentiation punctuators, optional chaining, nullish operators, numeric separators and BigInt literals.

어휘 분석기(ECMA-262 6판 11장). 소스 텍스트를 필요할 때마다 Token 으로 바꾼다: 이스케이프가 있는 유니코드 식별자, 숫자 리터럴(10진, 0x, 0o, 0b, 레거시 8진), 모든 이스케이프가 있는 문자열 리터럴, 템플릿 리터럴 조각, 주석, 줄 끝(LF, CR, CRLF, LS, PS), 구두점.

구문 문맥에 따라 달라지는 두 가지는 파서가 요청한다: 정규식 리터럴(rescanRegExp(Token) 이 / 또는 /= 토큰을 정규식으로 다시 읽음)과 } 뒤의 템플릿 이어짐(rescanTemplateContinuation(Token)). saveState(), restoreState(State) 는 파서의 추측 파싱과 미리 보기에 쓴다. 어휘 오류는 줄/열을 가진 SyntaxError JsException 으로 던진다.

문법이 인식하는 ECMAScript 2016~2022 추가 요소에는 거듭제곱 구두점, optional chaining, nullish 연산자, 숫자 구분자와 BigInt 리터럴이 포함된다.
