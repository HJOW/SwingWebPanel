Class JsScriptEngine

java.lang.Object

All Implemented Interfaces:
javax.script.Compilable, javax.script.Invocable, javax.script.ScriptEngine
public final class JsScriptEngine
extends javax.script.AbstractScriptEngine
implements javax.script.Compilable, javax.script.Invocable

The Java Scripting API (JSR 223) engine of this project, built on JsEngine: it implements ScriptEngine (through AbstractScriptEngine), Compilable and Invocable. Obtain it with new ScriptEngineManager().getEngineByName("swingwebpanel-js") or from JsScriptEngineFactory.getScriptEngine().

Variables and contexts

The ENGINE_SCOPE bindings of the default context are a live view of the global object (JsGlobalBindings): engine.put("x", 1) makes x a global variable, and the vars and functions that a script declares are visible through engine.get("x"). When eval gets other ENGINE_SCOPE bindings (a Bindings argument, or a context that was given other bindings), those bindings get a global scope of their own: this script engine keeps one complete, independent global object (realm) for every Bindings object it has seen, copies the entries of the bindings into it before the script runs, and copies the globals that the script created or changed back afterwards; the same Bindings object therefore keeps its variables from one eval to the next, and different bindings never see each other's variables. The GLOBAL_SCOPE bindings (shared by the engines of a ScriptEngineManager) are consulted for a name that the script scope does not have; they are read only (an assignment goes to the engine scope). Values follow the conversion rules of JsEngine, except that undefined becomes null; a Java object that is not convertible is refused (ScriptException for an eval), because scripts never get Java objects. To let scripts call Java code put a JsHostFunction into the bindings. let, const and class declarations at the top level of a script are not entries of the bindings (they live in the declarative scope of the realm), but later scripts of the same scope see them; declaring the same name twice is a SyntaxError, as in a browser.

Output

print and console.log/info/debug write a line to ScriptContext.getWriter(), console.warn/error to getErrorWriter() of the context that runs the script.

Errors

An error of the script is a ScriptException with the message Name: message, the script name (the attribute ScriptEngine.FILENAME of the context, or <eval>), the line and the column (-1 when unknown) and the JsScriptError as its cause. A script that the engine stopped (see getJsEngine() for the limits) is a ScriptException whose cause is the ScriptAbortedException.

Results

The result of eval is the completion value converted by the rules of JsEngine: a number is always a Double, an object is a live Map, an array a live List, a function a JsCallable; undefined and a script without a value give null. Promise jobs run before eval returns; there are no timers.

Threads

The engine may be used from several threads (THREADING is MULTITHREADED); the operations on one global scope are serialized.

이 프로젝트의 Java Scripting API(JSR 223) 엔진. JsEngine 위에 만들었으며 ScriptEngine(AbstractScriptEngine 로), Compilable, Invocable 을 구현한다. new ScriptEngineManager().getEngineByName("swingwebpanel-js") 나 JsScriptEngineFactory.getScriptEngine() 으로 얻는다.

변수와 컨텍스트

기본 컨텍스트의 ENGINE_SCOPE 바인딩은 전역 객체의 살아 있는 보기(JsGlobalBindings)이다. engine.put("x", 1) 은 x 를 전역 변수로 만들고, 스크립트가 선언한 var 와 함수는 engine.get("x") 로 보인다. eval 이 다른 ENGINE_SCOPE 바인딩(Bindings 인수, 또는 다른 바인딩을 준 컨텍스트)을 받으면 그 바인딩은 자신만의 전역 스코프를 가진다. 이 스크립트 엔진은 본 Bindings 객체마다 완전하고 독립된 전역 객체(realm)를 하나씩 두고, 스크립트를 실행하기 전에 바인딩의 항목을 그 안으로 복사하고, 실행한 뒤 스크립트가 만들거나 바꾼 전역을 다시 복사해 온다. 그래서 같은 Bindings 객체는 eval 사이에 변수를 유지하고 다른 바인딩은 서로의 변수를 보지 못한다. GLOBAL_SCOPE 바인딩 (ScriptEngineManager 의 엔진들이 공유)은 스크립트 스코프에 없는 이름을 찾을 때 참조하며 읽기 전용이다(대입은 엔진 스코프로 간다). 값은 JsEngine 의 변환 규칙을 따르되 undefined 는 null 이 된다. 변환할 수 없는 Java 객체는 거부한다(eval 에서는 ScriptException). 스크립트는 Java 객체를 받지 않기 때문이다. 스크립트가 Java 코드를 호출하게 하려면 바인딩에 JsHostFunction 을 넣는다. 스크립트 최상위의 let, const, class 선언은 바인딩의 항목이 아니지만(realm 의 선언적 스코프에 있다) 같은 스코프의 이후 스크립트는 그것을 본다. 같은 이름을 두 번 선언하면 브라우저처럼 SyntaxError 이다.

출력

print 와 console.log/info/debug 는 스크립트를 실행하는 컨텍스트의 ScriptContext.getWriter() 에, console.warn/error 는 getErrorWriter() 에 한 줄씩 쓴다.

오류

스크립트의 오류는 Name: message 형태의 메시지, 스크립트 이름(컨텍스트의 ScriptEngine.FILENAME 속성, 없으면 <eval>), 줄과 열(모르면 -1), 원인 JsScriptError 를 가진 ScriptException 이다. 엔진이 멈춘 스크립트(제한은 getJsEngine() 참조)는 원인이 ScriptAbortedException 인 ScriptException 이다.

결과

eval 의 결과는 JsEngine 의 규칙으로 바꾼 완료 값이다: 숫자는 항상 Double, 객체는 살아 있는 Map, 배열은 살아 있는 List, 함수는 JsCallable. undefined 와 값이 없는 스크립트는 null 이다. promise 작업은 eval 이 반환하기 전에 실행되며 타이머는 없다.

스레드

엔진은 여러 스레드에서 쓸 수 있다(THREADING 은 MULTITHREADED). 같은 전역 스코프의 연산은 직렬화된다.
