org.duckdns.hjow.swingwebpanel.dom.edit
Class Editor

java.lang.Object
  org.duckdns.hjow.swingwebpanel.dom.edit.Editor

public final class Editor
extends java.lang.Object

The editing engine of one document (plan item P20-06): it changes the DOM the way the browsers do when the user types, deletes, breaks a line, formats, cuts, pastes or drops in an editing host (contenteditable or design mode), and it is the implementation of document.execCommand(). The selection of the document is the place where it works. Every operation sends the cancelable beforeinput event to the editing host first (Input Events, with the inputType, the data and the target ranges), does nothing when a listener cancels it, then changes the DOM as one step of the undo history and sends input. The engine needs no layout: where it must know what is a block or whether white space is preserved it asks the Editor.Environment, whose default decides by the names of the elements.

Inside this engine a position is a node and an offset, as in a range. Text is inserted into text nodes (white space is rebalanced with no-break spaces so that every typed space stays visible, as the browsers do for white-space: normal), a deletion works on character units, a line break inside a block is a br, a paragraph break splits the block (the new block is a copy of the old one, a div after a heading, a new item in a list), an empty block keeps a placeholder br, and the end of a block is joined to the next one when the deletion crosses it.

한 문서의 편집 엔진(계획 P20-06): 편집 호스트(contenteditable 이나 디자인 모드) 안에서 사용자가 글자를 입력하고, 지우고, 줄을 바꾸고, 서식을 정하고, 잘라내고, 붙여넣고, 놓을 때 브라우저가 하는 대로 DOM 을 바꾸며, document.execCommand() 의 구현이다. 문서의 선택이 일하는 자리이다. 모든 작업은 먼저 취소할 수 있는 beforeinput 이벤트를 편집 호스트에 보내고(Input Events: inputType, data, 대상 범위), 리스너가 취소하면 아무것도 하지 않으며, 아니면 DOM 을 되돌리기 이력의 한 단계로 바꾼 뒤 input 을 보낸다. 엔진은 레이아웃이 필요 없다. 무엇이 블록인지, 공백이 보존되는지 알아야 할 때는 Editor.Environment 에 묻고, 기본 구현은 요소 이름으로 정한다.

이 엔진 안에서 위치는 범위처럼 노드와 오프셋이다. 텍스트는 텍스트 노드에 넣고(입력한 공백이 모두 보이도록 NBSP 로 공백을 재조정한다. white-space: normal 에서 브라우저가 하는 대로), 지우기는 글자 단위로 하며, 블록 안의 줄바꿈은 br, 문단 나누기는 블록을 쪼개고(새 블록은 옛 블록의 복사본이고 제목 뒤에서는 div, 목록에서는 새 항목), 빈 블록은 자리표시 br 을 가지며, 지우기가 블록의 끝을 넘으면 다음 블록과 합친다.

compose

public boolean compose(java.lang.String committed,
                       java.lang.String composing)
Applies what an input method reports (Java: an InputMethodEvent): the text that it has committed and the text that it is still composing. The composed text is shown in the DOM at the caret as it is composed (each change is an insertCompositionText with compositionupdate and isComposing); the committed text replaces it and ends the composition (compositionend); the text that is still composed after the committed part starts the next composition (as when Hangul letters finish a syllable and start the next). Both empty ends a running composition without text (the user cancelled it). A composition is one step of the undo history.

입력기가 알리는 것(Java: InputMethodEvent)을 적용한다: 확정한 텍스트와 아직 조합 중인 텍스트. 조합 중인 텍스트는 조합되는 대로 캐럿 자리의 DOM 에 보인다(변경마다 compositionupdate 와 isComposing 이 있는 insertCompositionText). 확정된 텍스트는 그것을 바꾸고 조합을 끝낸다(compositionend). 확정된 부분 뒤에 아직 조합 중인 텍스트는 다음 조합을 시작한다(한글이 한 음절을 마치고 다음 음절을 시작할 때처럼). 둘 다 비면 진행 중인 조합을 텍스트 없이 끝낸다(사용자가 취소했다). 조합 하나는 되돌리기 이력의 한 단계이다.

Parameters:
committed - the text that the input method committed / 입력기가 확정한 텍스트
composing - the text that is still composed / 아직 조합 중인 텍스트
Returns:
true if the DOM was changed or a composition ended / DOM 이 바뀌었거나 조합이 끝났으면 true
