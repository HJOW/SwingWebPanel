Class HttpFetcher

java.lang.Object
  org.duckdns.hjow.swingwebpanel.net.HttpFetcher

public class HttpFetcher
extends java.lang.Object

HTTP and HTTPS client built on HttpURLConnection with everything the browser needs done by hand:

  • Request layer: the same code path adds the User-Agent, the component's extra headers, cookies, referrer, Origin and cache headers for main documents and for every sub-resource (images, audio, CSS, scripts).
  • Redirects are followed manually (relative Location, loops, a maximum count, POST turns into GET on 301/302/303, 307/308 keep method and body, http<->https switches allowed, only http(s) targets are allowed from http). The effective final URL is reported. Authorization and Proxy-Authorization extra headers are not forwarded when the origin changes or after an https-to-http downgrade; other extra headers are.
  • Bodies are decompressed (gzip, deflate; only these are advertised), limited in memory (FetchLimits.getMaxMemoryBytes()) and checked against Content-Length (a short body is FailureKind.TRUNCATED); error statuses keep their body. A ResponseHandler can redirect the body to a stream without a size limit.
  • SSL: SslConfigurer.configureSsl(HttpsURLConnection) runs for every https connection. If an https attempt fails at connect or TLS level (never for an HTTP error status), one retry is made over http to the same host (default port 443 becomes 80, an explicit other port is kept). The result reports the real http URL and ResourceResponse.isHttpFallbackUsed(). Secure cookies are naturally not sent on the plain request and the sensitive extra headers above are dropped. Certificate and host name errors also count as TLS failures, as the project requires.
  • CORS: a request that carries Origin (a cross-origin request of a CORS purpose, every POST/PUT/PATCH/DELETE with an initiating origin) is sent through the socket based SocketHttpURLConnection/SocketHttpsURLConnection because the JRE drops that restricted header (not when a JVM proxy applies). A cross-origin request with a method or a page header that is not safelisted first gets a preflight (OPTIONS, see OriginPolicy.checkPreflight(org.duckdns.hjow.swingwebpanel.net.Origin, int, org.duckdns.hjow.swingwebpanel.net.ResourceResponse, boolean)); a denial is FailureKind.CORS and the request is not sent.
  • Cancellation: the request's CancelToken disconnects the connection; streams and connections are closed on every path.
No JVM-wide state is changed (no default cookie handler, authenticator, SSL context or host name verifier). A fetch never throws for network problems; it returns a ResourceResponse with a FailureKind. Instances are thread safe; one fetch runs in the calling thread.

HttpURLConnection 위에 만든 HTTP/HTTPS 클라이언트로, 브라우저가 필요로 하는 것을 직접 처리한다.

  • 요청 계층: 주 문서와 모든 하위 리소스(이미지, 오디오, CSS, 스크립트)에 같은 코드 경로로 User-Agent, 컴포넌트의 추가 헤더, 쿠키, 참조 페이지, Origin, 캐시 헤더를 붙인다.
  • 리디렉션은 직접 따라간다(상대 Location, 순환, 최대 횟수, 301/302/303 에서 POST 는 GET 으로, 307/308 은 메서드와 본문 유지, http<->https 전환 허용, http 에서는 http(s) 대상만 허용). 최종 유효 URL 을 보고한다. 오리진이 바뀌거나 https 에서 http 로 내려가면 Authorization, Proxy-Authorization 추가 헤더는 전달하지 않으며 다른 추가 헤더는 전달한다.
  • 본문은 압축을 풀고(gzip, deflate 만 광고), 메모리 크기를 제한(FetchLimits.getMaxMemoryBytes())하며 Content-Length 와 대조한다(짧으면 FailureKind.TRUNCATED). 오류 상태도 본문을 유지한다. ResponseHandler 로 본문을 크기 제한 없는 스트림으로 보낼 수 있다.
  • SSL: 모든 https 연결에 SslConfigurer.configureSsl(HttpsURLConnection) 를 호출한다. https 시도가 연결 또는 TLS 수준에서 실패하면(HTTP 오류 상태는 해당 없음) 같은 호스트로 http 재시도를 한 번 한다(기본 443 포트는 80 으로, 명시한 다른 포트는 유지). 결과에는 실제 http URL 과 ResourceResponse.isHttpFallbackUsed() 가 보고된다. 평문 요청에는 Secure 쿠키가 자연히 가지 않고 위의 민감한 추가 헤더도 빠진다. 프로젝트 요구대로 인증서/호스트 이름 오류도 TLS 실패로 본다.
  • CORS: Origin 을 싣는 요청(CORS 목적의 교차 오리진 요청, 시작한 오리진이 있는 모든 POST/PUT/PATCH/DELETE)과 JRE 가 거부하는 PATCH 는 JRE 가 그 제한 헤더를 버리므로 소켓 기반 SocketHttpURLConnection/SocketHttpsURLConnection 으로 보낸다(JVM 프록시가 적용되면 제외). 안전 목록에 없는 메서드나 페이지 헤더를 가진 교차 오리진 요청은 먼저 사전 요청(OPTIONS, OriginPolicy.checkPreflight(org.duckdns.hjow.swingwebpanel.net.Origin, int, org.duckdns.hjow.swingwebpanel.net.ResourceResponse, boolean) 참조)을 받으며, 거부되면 FailureKind.CORS 이고 요청은 보내지 않는다.
  • 취소: 요청의 CancelToken 이 연결을 끊는다. 스트림과 연결은 모든 경로에서 닫는다.
JVM 전역 상태(기본 쿠키 처리기, 인증기, SSL 컨텍스트, 호스트 이름 검증기)는 바꾸지 않는다. 가져오기는 네트워크 문제로 예외를 던지지 않고 FailureKind 가 있는 ResourceResponse 를 돌려준다. 인스턴스는 스레드 안전하며 가져오기 한 번은 호출한 스레드에서 실행한다.
