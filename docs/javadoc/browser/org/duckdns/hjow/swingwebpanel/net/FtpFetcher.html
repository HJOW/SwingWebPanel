Class FtpFetcher

java.lang.Object
  org.duckdns.hjow.swingwebpanel.net.FtpFetcher

public final class FtpFetcher
extends java.lang.Object

Fetches ftp:// URLs for the browser through FtpClient (anonymous access only).

  • Directory or file? A URL whose path is empty, "/" or ends with "/" is a directory. For any other path the server's CWD decides: if the change succeeds the URL is a directory (the reported final URL then ends with "/" so that relative links resolve correctly), otherwise the path is retrieved as a file.
  • Directory: the answer is the generated HTML listing (FtpListing) with media type text/html, charset UTF-8, flagged by ResourceResponse.isDirectoryListing().
  • File: the media type is guessed from the file name (MimeTypes); unknown files are application/octet-stream, which the content layer routes to the download popup instead of showing them. The body goes to the ResponseHandler stream when it asks for one, else into memory (size limited).
  • Failures (connect, login, missing path, unparsable or failed listing, failed transfer) are reported as status 404 with FailureKind.FTP_FAILURE - the project shows a 404 page for FTP problems. Cancellation, memory limit and invalid paths have their own kinds. A path with CR, LF or NUL is refused with FailureKind.INVALID_URL before any connection.

ftp:// URL 을 FtpClient 로 가져온다(익명 접근만).

  • 디렉터리인가 파일인가? 경로가 비었거나 "/" 이거나 "/" 로 끝나면 디렉터리이다. 그 밖의 경로는 서버의 CWD 가 정한다. 이동이 성공하면 디렉터리이고(상대 링크가 올바르게 풀리도록 보고하는 최종 URL 은 "/" 로 끝난다), 실패하면 파일로 받는다.
  • 디렉터리: 생성한 HTML 목록(FtpListing)을 미디어 타입 text/html, UTF-8 로 답하며 ResourceResponse.isDirectoryListing() 으로 표시한다.
  • 파일: 미디어 타입은 파일 이름으로 추정하고(MimeTypes) 모르면 application/octet-stream 이며 콘텐츠 계층은 이를 표시하지 않고 다운로드 팝업으로 보낸다. ResponseHandler 가 스트림을 요구하면 본문을 그쪽으로, 아니면 메모리(크기 제한)로 받는다.
  • 실패(연결, 로그인, 없는 경로, 해석 못한/실패한 목록, 전송 실패)는 상태 404 와 FailureKind.FTP_FAILURE 로 보고한다. 프로젝트는 FTP 문제를 404 화면으로 보여 준다. 취소, 메모리 제한, 잘못된 경로는 각자의 종류를 가진다. CR, LF, NUL 이 든 경로는 연결하기 전에 FailureKind.INVALID_URL 로 거부한다.
