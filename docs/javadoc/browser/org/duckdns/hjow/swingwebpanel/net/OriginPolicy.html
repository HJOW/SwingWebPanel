org.duckdns.hjow.swingwebpanel.net
Class OriginPolicy

java.lang.Object
  org.duckdns.hjow.swingwebpanel.net.OriginPolicy

public final class OriginPolicy
extends java.lang.Object

Same-origin policy and the CORS decision for cross-origin requests, separated by RequestPurpose.

  • Same origin: everything is allowed, including script access to the response body.
  • Cross origin, "no-cors" purposes (image, audio, style sheet, script, frame, document, download, other): the response may be displayed or executed but its body is never exposed to scripts.
  • Cross origin, CORS purposes (XHR/fetch and web fonts): the response must carry Access-Control-Allow-Origin equal to the requesting origin (or * without credentials); with credentials it must also carry Access-Control-Allow-Credentials: true and may not use *. A request that is not simple needs a CORS preflight first (see checkPreflight(org.duckdns.hjow.swingwebpanel.net.Origin, int, org.duckdns.hjow.swingwebpanel.net.ResourceResponse, boolean)); see isSimpleRequest(String, Map).

동일 출처 정책과 교차 오리진 요청의 CORS 판정을 RequestPurpose 별로 구분한다.

  • 같은 오리진: 응답 본문의 스크립트 접근을 포함해 모두 허용한다.
  • 교차 오리진 "no-cors" 목적(이미지, 오디오, 스타일시트, 스크립트, 프레임, 문서, 다운로드, 기타): 응답을 표시하거나 실행할 수는 있지만 본문을 스크립트에 절대 노출하지 않는다.
  • 교차 오리진 CORS 목적(XHR/fetch, 웹 글꼴): 응답에 요청 오리진과 같은 Access-Control-Allow-Origin (자격 증명이 없으면 * 도 가능)이 있어야 한다. 자격 증명을 쓰면 Access-Control-Allow-Credentials: true 도 있어야 하고 * 는 쓸 수 없다. 단순하지 않은 요청은 CORS 사전 요청이 필요하다(checkPreflight(org.duckdns.hjow.swingwebpanel.net.Origin, int, org.duckdns.hjow.swingwebpanel.net.ResourceResponse, boolean) 참조). isSimpleRequest(String, Map) 참조.

checkPreflight

public static OriginPolicy.PreflightGrant checkPreflight(Origin initiator,
                                                         int status,
                                                         ResourceResponse response,
                                                         boolean withCredentials)
Checks the response of a CORS preflight and returns what it grants: the status must be 2xx, the Access-Control-Allow-Origin and Access-Control-Allow-Credentials headers must permit the requesting origin as for the actual request (corsAllows(org.duckdns.hjow.swingwebpanel.net.Origin, java.lang.String, java.lang.String, boolean)), and the method and header lists are read from Access-Control-Allow-Methods and Access-Control-Allow-Headers.

CORS 사전 요청의 응답을 검사하고 그것이 허용하는 것을 반환한다: 상태가 2xx 이어야 하고, Access-Control-Allow-Origin 과 Access-Control-Allow-Credentials 가 본 요청과 똑같이(corsAllows(org.duckdns.hjow.swingwebpanel.net.Origin, java.lang.String, java.lang.String, boolean)) 요청 오리진을 허용해야 하며, 메서드와 헤더 목록은 Access-Control-Allow-Methods 와 Access-Control-Allow-Headers 에서 읽는다.

Parameters:
initiator - requesting origin / 요청한 오리진
status - status code of the preflight response / 사전 요청 응답의 상태 코드
response - the preflight response (for its headers) / 사전 요청 응답(헤더용)
withCredentials - whether the actual request sends credentials / 본 요청이 자격 증명을 보내는지
Returns:
what the response grants, or null if it denies the request / 응답이 허용하는 것. 요청을 거부하면 null
