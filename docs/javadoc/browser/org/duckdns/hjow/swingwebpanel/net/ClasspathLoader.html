Class ClasspathLoader

java.lang.Object
  org.duckdns.hjow.swingwebpanel.net.ClasspathLoader

public final class ClasspathLoader
extends java.lang.Object

Loads classpath://path resources through ClassLoader.getResourceAsStream. The class path is the only source: the address is never turned into a file: or jar: URL that is then opened, so a class path address cannot be used to reach arbitrary files, and resources inside JAR files work exactly like files in directories.

  • Path rules: the text after classpath:// is the resource path relative to the class path root. It is percent-decoded exactly once (spaces as %20, UTF-8 file names), "." segments are skipped, ".." removes the previous segment and a ".." that would climb above the root makes the resource not found; backslashes, NUL and other control characters are refused. A path that is empty or ends with "/" is a directory and never loaded.
  • Result: status 200 with the media type guessed from the file name (MimeTypes), or status 404 with FailureKind.NOT_FOUND when the resource does not exist, is a directory or has an illegal path.

classpath://경로 리소스를 ClassLoader.getResourceAsStream 으로 읽는다. 클래스패스만이 출처이다. 주소를 file: 이나 jar: URL 로 바꾸어 여는 일은 없으므로 클래스패스 주소로 임의 파일에 닿을 수 없고, JAR 안의 리소스도 디렉터리의 파일과 똑같이 읽힌다.

  • 경로 규칙: classpath:// 뒤의 문자열이 클래스패스 루트 기준 리소스 경로이다. 퍼센트 인코딩은 정확히 한 번 디코딩하고(공백은 %20, UTF-8 파일 이름), "." 세그먼트는 건너뛰며, ".." 는 앞 세그먼트를 지우고, 루트 위로 올라가려는 ".." 가 있으면 리소스를 찾을 수 없음으로 한다. 역슬래시, NUL, 기타 제어 문자는 거부한다. 경로가 비었거나 "/" 로 끝나면 디렉터리이므로 읽지 않는다.
  • 결과: 파일 이름으로 추정한 미디어 타입(MimeTypes)과 상태 200, 또는 리소스가 없거나 디렉터리이거나 경로가 잘못되었을 때 상태 404 와 FailureKind.NOT_FOUND.
