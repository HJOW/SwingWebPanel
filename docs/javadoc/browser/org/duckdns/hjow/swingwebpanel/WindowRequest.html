org.duckdns.hjow.swingwebpanel
Class WindowRequest

java.lang.Object
  org.duckdns.hjow.swingwebpanel.WindowRequest

public final class WindowRequest
extends java.lang.Object

A new window that a page of a SwingWebPanel asked for (extension, API contract 5.28). The component passes it to the extension points SwingWebPanel.openPopupWindow(WindowRequest), SwingWebPanel.openNewWindow(WindowRequest) and SwingWebPanel.popupBlocked(WindowRequest), always on the event dispatch thread. There are three kinds:

  • SCRIPT: a script called window.open. The component of the new window exists already (getPanel()), because the script holds its window object; the host must show it somewhere or call reject().
  • LINK: a link or a form whose target names no existing window. getPanel() creates the component of a new window (which loads the address, or receives the form) when the host decides to open one.
  • USER: the user chose to open a link elsewhere (Ctrl or middle click for a new tab, Shift click for a new window; getPlace() tells which). The host can open getUrl() in a component of its own or use getPanel().

SwingWebPanel 의 페이지가 요청한 새 창(확장, API 계약 5.28). 컴포넌트가 확장 지점 SwingWebPanel.openPopupWindow(WindowRequest), SwingWebPanel.openNewWindow(WindowRequest), SwingWebPanel.popupBlocked(WindowRequest) 에 넘기며, 항상 이벤트 디스패치 스레드에서 넘긴다. 세 종류가 있다:

  • SCRIPT: 스크립트가 window.open 을 불렀다. 스크립트가 그 창 객체를 쥐고 있으므로 새 창의 컴포넌트가 이미 있다(getPanel()). 호스트는 그것을 어딘가에 보이거나 reject() 를 불러야 한다.
  • LINK: 대상이 기존 창을 가리키지 않는 링크나 폼. 호스트가 창을 열기로 하면 getPanel() 이 새 창의 컴포넌트를 만든다(주소를 읽거나 폼을 받는다).
  • USER: 사용자가 링크를 다른 곳에서 열기로 골랐다(Ctrl 이나 가운데 클릭은 새 탭, Shift 클릭은 새 창. getPlace() 가 알려 준다). 호스트는 getUrl() 을 자기 컴포넌트에서 열거나 getPanel() 을 쓸 수 있다.

사용 예 / Example: 

 protected void openPopupWindow(WindowRequest request) {
     JFrame frame = new JFrame();
     frame.add(new JScrollPane(request.getPanel()));
     frame.setSize(600, 400);
     frame.setVisible(true);
 }

getPanel

public SwingWebPanel getPanel()
Returns the component of the new window. For a SCRIPT request it exists already. For the other kinds the first call creates it and starts loading the address (or sending the form); a LINK window counts as created by web content, so its page may close it with window.close(). The host puts the component into a window or a tab and disposes it when that is closed. Call it on the event dispatch thread.

새 창의 컴포넌트를 반환한다. SCRIPT 요청이면 이미 있다. 다른 종류이면 첫 호출이 컴포넌트를 만들고 주소 읽기(또는 폼 보내기)를 시작한다. LINK 창은 웹 콘텐츠가 만든 것으로 치므로 그 페이지가 window.close() 로 닫을 수 있다. 호스트는 컴포넌트를 창이나 탭에 넣고, 그것이 닫힐 때 컴포넌트를 폐기한다. 이벤트 디스패치 스레드에서 부른다.

Returns:
the component, or null if the request was rejected or no component could be created / 컴포넌트. 요청을 거절했거나 컴포넌트를 만들 수 없었으면 null

isBlocked

public boolean isBlocked()
Tells whether the popup blocker refused the window when the host asked for its component: getPanel() returned null and SwingWebPanel.popupBlocked(WindowRequest) was told. The page then gets no window and no other navigation.

reject

public void reject()
Declines the request: the component of the new window, if it exists, is disposed, so that the script that opened it sees the window as closed. Calling it again does nothing.

요청을 거절한다: 새 창의 컴포넌트가 있으면 폐기하여, 그 창을 연 스크립트가 창을 닫힌 것으로 보게 한다. 다시 불러도 아무 일도 없다.
