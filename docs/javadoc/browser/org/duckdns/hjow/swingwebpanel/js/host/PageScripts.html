org.duckdns.hjow.swingwebpanel.js.host
Class PageScripts

java.lang.Object
  org.duckdns.hjow.swingwebpanel.js.host.PageScripts

public final class PageScripts
extends java.lang.Object

The JavaScript side of one page (plan items P15-01, P15-04 to P15-07, P15-09, P15-11): it owns the realm, the DOM bridge, the window, the event loop (tasks, timers, microtasks, mutation observers) and the script execution model. The component builds one instance per page like this:

  1. new PageScripts(document, environment) before parsing;
  2. parse with new HtmlParser(document, text) after parser.setListener(scripts.createParserListener()): classic scripts run while the parser runs, document.write feeds the parser;
  3. completeParsing() after the parser finished: deferred and module scripts, DOMContentLoaded, async scripts, load;
  4. later tasks (timers, host events) run through runTask(Runnable) and dispatchEvent(EventTarget, Event);
  5. dispose() when the page is replaced or the component is disposed: every pending task is cancelled and callbacks that were already scheduled never touch the new page.
All JavaScript of the page is serialized by one lock, so the loader thread, the document thread and the scheduler thread may call in turn. A script that is aborted by a limit or by dispose() stops without affecting other pages. When HostEnvironment.isScriptingEnabled() is false no script, event handler attribute or timer runs (the plan item P15-10 behaviour); HTML and CSS are not affected, and switching it on again does not run scripts of an already loaded page.

한 페이지의 JavaScript 쪽(계획 P15-01, P15-04~07, P15-09, P15-11): realm, DOM 브리지, window, 이벤트 루프(작업, 타이머, 마이크로태스크, 변경 관찰자), 스크립트 실행 모델을 가진다. 컴포넌트는 페이지마다 인스턴스 하나를 이렇게 만든다: ① 해석 전에 new PageScripts(document, environment), ② parser.setListener(scripts.createParserListener()) 뒤에 해석하면 파서가 도는 동안 일반 스크립트가 실행되고 document.write 가 파서에 입력을 준다. ③ 파서가 끝나면 completeParsing(): defer/module 스크립트, DOMContentLoaded, async 스크립트, load. ④ 이후 작업(타이머, 호스트 이벤트)은 runTask(Runnable) 과 dispatchEvent(EventTarget, Event) 로 실행. ⑤ 페이지가 교체되거나 컴포넌트가 폐기되면 dispose(): 대기 중인 모든 작업이 취소되고 이미 예약된 콜백도 새 페이지를 건드리지 못한다. 페이지의 모든 JavaScript 는 잠금 하나로 직렬화되므로 로더 스레드, 문서 스레드, 스케줄러 스레드가 번갈아 호출해도 된다. 한도나 dispose() 로 중단된 스크립트는 다른 페이지에 영향을 주지 않는다. HostEnvironment.isScriptingEnabled() 가 false 이면 스크립트, 이벤트 핸들러 속성, 타이머가 실행되지 않는다(계획 P15-10 동작). HTML 과 CSS 는 영향받지 않으며 다시 켜도 이미 로드된 페이지의 스크립트는 자동으로 다시 실행되지 않는다.

taskEndBarrier

public static java.lang.Runnable taskEndBarrier()
Returns a barrier for the task that runs outermost on the calling thread now: running the returned object on another thread blocks until that task, including its microtask checkpoint, has ended. A script of a page that is still being parsed runs on the thread of its loader, not on the document thread, so work that must follow "the task of the caller" cannot rely on the order of the document queue alone; it runs this barrier first. Without a running task the barrier does nothing.

지금 호출한 스레드에서 가장 바깥에 실행 중인 작업에 대한 장벽을 반환한다: 반환된 객체를 다른 스레드에서 실행하면 그 작업이 마이크로태스크 검사점까지 끝날 때까지 막힌다. 아직 파싱 중인 페이지의 스크립트는 문서 스레드가 아니라 로더의 스레드에서 실행되므로, "호출한 작업 뒤"에 와야 하는 일은 문서 큐의 순서만으로는 보장되지 않는다. 그런 일은 먼저 이 장벽을 실행한다. 실행 중인 작업이 없으면 장벽은 아무것도 하지 않는다.

Returns:
the barrier; never null / 장벽. null 이 아니다

requestDisposal

public void requestDisposal()
Requests disposal without taking the page lock: running code notices cancellation and no new page task starts. The host can call this from the EDT, then call dispose() on a cleanup worker to release timers, listeners and wrappers. This method alone is not full resource cleanup. Repeated requests are safe.

페이지 잠금을 얻지 않고 폐기를 요청한다. 실행 중인 코드는 취소를 감지하며 새 페이지 작업은 시작되지 않는다. 호스트는 EDT에서 요청한 뒤 정리 작업자에서 dispose()를 호출하여 타이머·리스너·래퍼를 해제한다. 이 메서드만으로 전체 자원 정리가 끝나지는 않는다. 반복 요청은 안전하다.

dispose

public void dispose()
Disposes the page's scripts: every timer and frame callback is cancelled, running scripts are aborted, observers and wrappers are dropped and storage listeners are removed. Afterwards nothing runs, even tasks that were already handed to the scheduler.

페이지의 스크립트를 폐기한다: 모든 타이머와 프레임 콜백을 취소하고 실행 중인 스크립트를 중단하며 관찰자와 래퍼를 버리고 저장소 리스너를 제거한다. 그 뒤에는 이미 스케줄러에 넘긴 작업도 실행되지 않는다.
