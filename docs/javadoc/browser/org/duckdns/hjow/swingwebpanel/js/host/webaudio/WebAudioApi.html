org.duckdns.hjow.swingwebpanel.js.host.webaudio
Class WebAudioApi

java.lang.Object
  org.duckdns.hjow.swingwebpanel.js.host.webaudio.WebAudioApi

public final class WebAudioApi
extends java.lang.Object

The Web Audio API of one page (plan item P25; W3C Web Audio API 1.0 Recommendation of 2021-06-17): the script interfaces AudioContext, OfflineAudioContext, AudioNode and the nodes, AudioParam, AudioBuffer, AudioListener, PeriodicWave and the events, over the pure Java engine of org.duckdns.hjow.swingwebpanel.media.webaudio. This object installs them on the global object of the page and owns what they share: the delivery of what other threads produce (the end of a source, the end of an offline rendering, a decoded buffer) to the thread that owns the script realm as tasks of the page, the list of the contexts that are open, the limits of the page, the conversion of the engine's errors to script exceptions, and the disposal of everything when the page is replaced, its scripts are switched off or it is disposed.

Threads. The script realm belongs to the page thread: every interface call, every event and every settled promise runs there, as a task of the page (PageScripts.runTask(Runnable)), through the Scheduler of the component. The engine has its own threads (the rendering thread of a real-time context, the thread that renders an offline context, the decoding threads); they never call the script. What they have to tell the script goes through postTask(Runnable), which drops it silently after the page was disposed, so a late result never touches a new page. Control calls go the other way directly: the engine accepts them from any thread (see BaseAudioContext).

Limits. WebAudioHostLimits lists them: the number of open contexts of a page, the memory that its offline contexts may hold, and the number of pending decodings (the decoding service of the engine). Exceeding a limit is a NotSupportedError, as the specification allows an implementation-defined maximum number of contexts.

한 페이지의 Web Audio API(계획 P25. W3C Web Audio API 1.0 권고안, 2021-06-17): AudioContext, OfflineAudioContext, AudioNode 와 노드, AudioParam, AudioBuffer, AudioListener, PeriodicWave, 이벤트의 스크립트 인터페이스를 org.duckdns.hjow.swingwebpanel.media.webaudio 의 순수 Java 엔진 위에 만든다. 이 객체가 그것들을 페이지의 전역 객체에 설치하고 공유하는 것을 소유한다: 다른 스레드가 만든 결과(원천의 끝, 오프라인 렌더링의 끝, 디코딩된 버퍼)를 스크립트 realm 을 소유한 스레드에 페이지의 작업으로 전달하는 일, 열려 있는 컨텍스트의 목록, 페이지의 한도, 엔진의 오류를 스크립트 예외로 바꾸는 일, 페이지가 교체되거나 스크립트가 꺼지거나 폐기될 때 모든 것을 정리하는 일.

스레드. 스크립트 realm 은 페이지 스레드의 것이다: 모든 인터페이스 호출, 모든 이벤트, 확정되는 모든 프라미스가 컴포넌트의 Scheduler 를 거쳐 페이지의 작업 (PageScripts.runTask(Runnable))으로 거기서 실행된다. 엔진에는 자기 스레드(실시간 컨텍스트의 렌더링 스레드, 오프라인 컨텍스트를 렌더링하는 스레드, 디코딩 스레드)가 있으며 이들은 스크립트를 부르지 않는다. 스크립트에 알려야 하는 것은 postTask(Runnable) 로 가며, 페이지가 폐기된 뒤에는 조용히 버려지므로 늦은 결과가 새 페이지를 건드리지 않는다. 제어 호출은 반대 방향으로 직접 간다: 엔진은 어느 스레드에서나 받는다(BaseAudioContext 참고).

한도. WebAudioHostLimits 에 있다: 페이지의 열린 컨텍스트 수, 오프라인 컨텍스트가 쥘 수 있는 메모리, 대기 중인 디코딩 수(엔진의 디코딩 서비스). 한도를 넘으면 NotSupportedError 이다. 규격이 구현이 정하는 컨텍스트 최대 수를 허용한다.

dispose

public void dispose()
Disposes everything that the page owns here: every real-time context is closed (its rendering thread ends), every offline rendering is cancelled, every decoding service is closed (the requests that wait are dropped without a callback), and nothing is delivered to the page any more. Any thread may call it, without the lock of the page, and calling it again has no effect. The script objects that the page still holds keep working as objects but no longer produce sound or events.

페이지가 여기서 가진 모든 것을 폐기한다: 모든 실시간 컨텍스트를 닫고(렌더링 스레드가 끝난다), 모든 오프라인 렌더링을 취소하고, 모든 디코딩 서비스를 닫고(기다리는 요청은 콜백 없이 버려진다), 이후 페이지에 아무것도 전달하지 않는다. 페이지의 잠금 없이 어느 스레드에서나 부를 수 있으며 다시 불러도 효과가 없다. 페이지가 아직 쥐고 있는 스크립트 객체는 객체로는 계속 동작하나 더는 소리도 이벤트도 만들지 않는다.
