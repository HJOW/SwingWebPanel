org.duckdns.hjow.swingwebpanel.js.dom
Class DomBridge

java.lang.Object
  org.duckdns.hjow.swingwebpanel.js.dom.DomBridge

public final class DomBridge
extends java.lang.Object

The bridge between the Java host objects of one page (DOM nodes, events, collections ...) and the JavaScript realm of that page. It owns the interface table (one prototype and one constructor object per WebIDL interface), the identity-preserving wrapper cache, and the conversion of arguments and results. Interfaces are described by short specification strings (see defineInterface(String, String, Class, String[])); every described Java method is looked up once, when the interface is defined, so a wrong description fails at start-up (and in the tests) and never at run time. Only methods that are listed in a description can be reached from script: there is no reflection, class or package object visible to JavaScript.

Wrappers are cached weakly (the same Java object gives the same JavaScript object as long as the page holds it) and are pinned as soon as a script stores a property on them. All methods must be called on the thread that owns the realm.

한 페이지의 Java 호스트 객체(DOM 노드, 이벤트, 컬렉션 등)와 그 페이지의 JavaScript realm 을 잇는 다리. 인터페이스 표(WebIDL 인터페이스마다 프로토타입 하나와 생성자 객체 하나), 동일성을 유지하는 래퍼 캐시, 인수와 결과의 변환을 가진다. 인터페이스는 짧은 명세 문자열로 기술하며 (defineInterface(String, String, Class, String[]) 참고) 기술한 Java 메서드는 인터페이스를 정의할 때 한 번 찾으므로 잘못된 기술은 실행 중이 아니라 시작할 때(시험에서) 실패한다. 기술에 나열된 메서드만 스크립트에서 닿을 수 있으며 JavaScript 에 보이는 리플렉션, 클래스, 패키지 객체는 없다.

래퍼는 약하게 캐시하며(같은 Java 객체는 페이지가 붙잡고 있는 동안 같은 JavaScript 객체를 준다) 스크립트가 프로퍼티를 저장하면 고정한다. 모든 메서드는 realm 을 소유한 스레드에서 호출해야 한다.

defineInterface

public DomBridge.InterfaceInfo defineInterface(java.lang.String name,
                                               java.lang.String parent,
                                               java.lang.Class<?> javaClass,
                                               java.lang.String[] specs)
Defines an interface: creates its prototype and interface object, installs the members and puts the interface object on the global object. Member specifications (one string each):
  • a:name read-only attribute, a:name= read-write attribute; the Java accessors are getName/isName and setName; a:jsName@JavaBase uses another Java base name;
  • m:name(Type,Type*) operation with the Java method of the same name; a type followed by * is optional; ? after a type makes null and undefined mean Java null; m:jsName(Type)@javaName names the Java method; a last type Object... collects all remaining arguments;
  • c:NAME=value integer constant;
  • r:prop:attribute:type attribute reflection of a content attribute (types string, url, bool, int, uint); an empty attribute means the lower-cased property name.
Types: String, int, long, short, double, boolean, Boolean, Node, Element, Attr, Document, Event, EventTarget, Object.

인터페이스를 정의한다: 프로토타입과 인터페이스 객체를 만들고 멤버를 설치하며 인터페이스 객체를 전역 객체에 둔다. 멤버 명세(문자열 하나씩): a:name(읽기 전용 속성), a:name=(읽기/쓰기 속성, Java 접근자는 getName/isName, setName, a:jsName@JavaBase 는 다른 Java 기본 이름), m:name(Type,Type*)(같은 이름의 Java 메서드를 쓰는 연산, * 는 선택 인수, ? 는 null/undefined 를 Java null 로, m:jsName(Type)@javaName 은 Java 메서드 이름 지정, 마지막 Object... 는 나머지 인수를 모음), c:NAME=value(정수 상수), r:prop:attribute:type(콘텐츠 속성 반영).
