Interface WebRequestSource

public interface WebRequestSource

The asynchronous request service of a page, parallel to ScriptSource: the component implements it with its common request layer, so User-Agent, extra headers, cookies, SSL hook, scheme limits, cache, same-origin policy and cancellation apply to XMLHttpRequest and fetch() exactly as they do to scripts, styles and images. A request never runs on the thread that owns the page's JavaScript: start(WebRequest, Callback) returns at once and the WebRequestSource.Callback methods are called on a request thread; the page layer moves the results to its own thread as page tasks. A request that the page cancels (or that the page replacement cancels) must still end with one WebRequestSource.Callback.onComplete(WebResponse) call, but the page ignores that late result.

페이지의 비동기 요청 서비스. ScriptSource 와 나란히 있다. 컴포넌트가 공통 요청 계층으로 구현하므로 User-Agent, 추가 헤더, 쿠키, SSL 훅, 스킴 제한, 캐시, 동일 출처 정책, 취소가 XMLHttpRequest 와 fetch() 에도 스크립트·스타일·이미지와 똑같이 적용된다. 요청은 페이지의 JavaScript 를 소유한 스레드에서 실행되지 않는다. start(WebRequest, Callback) 는 곧바로 돌아오고 WebRequestSource.Callback 메서드는 요청 스레드에서 호출되며, 결과는 페이지 계층이 자기 스레드의 페이지 작업으로 옮긴다. 페이지가 취소한(또는 페이지 교체가 취소한) 요청도 WebRequestSource.Callback.onComplete(WebResponse) 를 한 번 호출하며 끝나야 하지만 페이지는 그 늦은 결과를 무시한다.
