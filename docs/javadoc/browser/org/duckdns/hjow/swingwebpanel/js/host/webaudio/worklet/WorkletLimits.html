Class WorkletLimits

  org.duckdns.hjow.swingwebpanel.js.host.webaudio.worklet.WorkletLimits

public final class WorkletLimits
extends java.lang.Object

The limits of the audio worklet. The script of a worklet runs on the rendering thread of an audio context, so its time is scarce: a render quantum of 128 frames is about 2.7 ms at 48 kHz, and the interpreter needs about a quarter of a millisecond for a simple processor (measured: 0.2 to 0.3 ms for a loop over the 128 frames). The limits below keep a runaway script from holding the rendering thread, and keep a real-time context responsive when the worklet is busy.

오디오 worklet 의 한도. worklet 의 스크립트는 오디오 컨텍스트의 렌더링 스레드에서 실행되므로 시간이 귀하다: 128 프레임의 render quantum 은 48 kHz 에서 약 2.7 ms 이며, 인터프리터는 단순한 프로세서 하나에 약 0.25 ms 가 든다(측정: 128 프레임을 도는 반복문 하나에 0.2 ~ 0.3 ms). 아래 한도는 폭주하는 스크립트가 렌더링 스레드를 붙잡지 못하게 하고, worklet 이 바쁠 때도 실시간 컨텍스트가 응답하게 한다.

PROCESS_STEP_LIMIT

public static final long PROCESS_STEP_LIMIT
The step limit of one call of process() (the engine counts statements, loop iterations and calls). A processor that exceeds it fails like one that throws (the processorerror event, silence for good). A processor that loops over 128 frames with a few statements needs a few thousand steps.

process() 호출 하나의 단계 수 한도(엔진은 문장, 반복 한 번, 호출을 센다). 넘으면 예외를 던진 것처럼 실패한다(processorerror 이벤트, 영구 무음). 128 프레임을 몇 문장으로 도는 프로세서는 수천 단계가 든다.

REALTIME_PROCESS_TIME_LIMIT_MILLIS

public static final long REALTIME_PROCESS_TIME_LIMIT_MILLIS
The time limit of one call of process() in a real-time context, in milliseconds: a call that takes longer fails like one that throws. It is about 37 render quanta at 48 kHz; a processor that needs this long cannot be played anyway.

실시간 컨텍스트에서 process() 호출 하나의 시간 한도(밀리초): 더 오래 걸리는 호출은 예외를 던진 것처럼 실패한다. 48 kHz 에서 render quantum 약 37 개이며, 이만큼 걸리는 프로세서는 어차피 재생할 수 없다.

REALTIME_LOCK_WAIT_MILLIS

public static final long REALTIME_LOCK_WAIT_MILLIS
How long the rendering thread of a real-time context waits for the script realm when the worklet thread is busy (a module is being evaluated, a message handler runs), in milliseconds. If the realm is still busy, the node outputs silence for that quantum (AudioWorkletNode.SKIPPED) and every other node of the same quantum gives up at once, so that the rendering thread loses this time once per quantum and not once per node.

worklet 스레드가 바쁠 때(모듈을 평가하거나 메시지 핸들러가 실행 중일 때) 실시간 컨텍스트의 렌더링 스레드가 스크립트 realm 을 기다리는 시간(밀리초). 그래도 realm 이 바쁘면 노드는 그 quantum 의 출력을 무음으로 하고(AudioWorkletNode.SKIPPED) 같은 quantum 의 다른 노드는 곧바로 포기하므로, 렌더링 스레드가 이 시간을 노드마다가 아니라 quantum 마다 한 번만 잃는다.
