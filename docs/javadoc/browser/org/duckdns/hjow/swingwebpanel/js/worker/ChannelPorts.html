org.duckdns.hjow.swingwebpanel.js.worker
Class ChannelPorts

java.lang.Object
  org.duckdns.hjow.swingwebpanel.js.worker.ChannelPorts

public final class ChannelPorts
extends java.lang.Object

The way for other script contexts (the audio worklet of the Web Audio API, for example) to use the channel messaging of this package: it installs the MessagePort interface into the realm of a ScriptContext and creates a channel whose two ends belong to two contexts at once. The ports behave exactly like the ports of MessageChannel: a message is serialized with the structured clone algorithm in the realm of the sender and becomes a message event as a task of the context that owns the receiving port (see ScriptContext.post(Runnable)), the port delivers after start() or after the first assignment of onmessage, and a port can be closed.

다른 스크립트 문맥(예: Web Audio API 의 오디오 worklet)이 이 패키지의 채널 메시징을 쓰는 통로: ScriptContext 의 realm 에 MessagePort 인터페이스를 설치하고, 두 끝이 두 문맥에 하나씩 속한 채널을 만든다. 포트는 MessageChannel 의 포트와 똑같이 동작한다: 메시지는 보내는 쪽 realm 에서 구조화 복제 알고리즘으로 직렬화되고 받는 포트를 소유한 문맥의 작업(ScriptContext.post(Runnable) 참고)으로 message 이벤트가 되며, 포트는 start() 나 onmessage 의 첫 지정 뒤에 전달하고, 포트를 닫을 수 있다.

newChannel

public static PortTarget[] newChannel(ScriptContext first,
                                      ScriptContext second)
Creates a channel whose ends belong to two contexts: the first port to the first context, the second port to the second one. The ports are not wrapped for scripts yet: the owner wraps its port with the DOM bridge of its realm, inside a task of its context. Callable from any thread.

두 문맥에 끝이 하나씩 속하는 채널을 만든다: 첫 포트는 첫 문맥에, 둘째 포트는 둘째 문맥에 속한다. 포트는 아직 스크립트용으로 감싸지 않았다: 소유자가 자기 문맥의 작업 안에서 자기 realm 의 DOM 브리지로 포트를 감싼다. 어느 스레드에서나 부를 수 있다.
