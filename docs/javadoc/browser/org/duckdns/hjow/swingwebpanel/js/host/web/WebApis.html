org.duckdns.hjow.swingwebpanel.js.host.web
Class WebApis

java.lang.Object
  org.duckdns.hjow.swingwebpanel.js.host.web.WebApis

public final class WebApis
extends java.lang.Object

The asynchronous web request APIs of one page (plan item P20-08): XMLHttpRequest, fetch() with Request, Response and Headers, AbortController/AbortSignal, FormData, Blob/File/FileReader, TextEncoder/TextDecoder, URL and URLSearchParams. This object installs them on the page's global object and owns what they share: the delivery of request results to the thread that owns the page's JavaScript, the list of requests that are still running, and the cancellation of all of them when the page is replaced, its scripts are switched off or it is disposed. The network itself is never touched here: every request goes through the WebRequestSource of the HostEnvironment, which is the component's common request layer.

Threads: a request runs on a request thread of the component. Its results are queued here and run one by one as page tasks (PageScripts.runTask(Runnable)) through the Scheduler of the page, so script code runs only on the page's own thread, in order, followed by the microtask checkpoint. A result that arrives after the page was disposed or its scripts were stopped never runs.

한 페이지의 비동기 웹 요청 API(계획 P20-08): XMLHttpRequest, Request/Response/Headers 를 가진 fetch(), AbortController/AbortSignal, FormData, Blob/File, URL, URLSearchParams(FileReader, TextEncoder, TextDecoder 포함). 이 객체가 이들을 페이지의 전역 객체에 설치하고 공유하는 것을 소유한다: 요청 결과를 페이지 JavaScript 소유 스레드에 전달하는 일, 아직 실행 중인 요청의 목록, 페이지가 교체되거나 스크립트가 꺼지거나 폐기될 때 모두 취소하는 일. 네트워크는 여기서 건드리지 않는다. 모든 요청은 HostEnvironment 의 WebRequestSource, 곧 컴포넌트의 공통 요청 계층을 거친다.

스레드: 요청은 컴포넌트의 요청 스레드에서 실행된다. 결과는 여기에 줄 세워졌다가 페이지의 Scheduler 를 통해 하나씩 페이지 작업 (PageScripts.runTask(Runnable))으로 실행되므로 스크립트 코드는 페이지 자신의 스레드에서만 순서대로 실행되고 마이크로태스크 검사점이 뒤따른다. 페이지가 폐기되거나 스크립트가 중단된 뒤에 도착한 결과는 실행되지 않는다.
