Class MessagingApi

java.lang.Object
  org.duckdns.hjow.swingwebpanel.js.host.MessagingApi

public final class MessagingApi
extends java.lang.Object

Messaging of a page (plan items P20-09 and P20-09-b; W3C Web Messaging REC 2015-05-19 and the HTML Standard "Web messaging" of 2026-11-17): window.postMessage(message, targetOrigin [, transfer]) and window.postMessage(message, {targetOrigin, transfer}), MessageEvent, and structuredClone(value [, {transfer}]); MessageChannel and MessagePort are installed through PortApi, because their ports are shared with workers. Messages are copied with the structured clone algorithm (StructuredClone), may carry ArrayBuffers and MessagePort objects in the transfer list (they are moved, the source is detached), and are delivered later as tasks of the page on the scheduler of the component, never while the sender runs. A postMessage to the window checks the target origin: * sends, / (the default of the options form) sends to the same origin (the only window of this component), a URL sends only if it has the origin of the page, anything else is a SyntaxError; a message to another origin is dropped silently, after it was cloned (so the transferred objects are given up as the specification says). There is one browsing context, so the target of window.postMessage is always the window of the page.

페이지의 메시징(계획 P20-09, P20-09-b. W3C Web Messaging REC 2015-05-19 와 2026-11-17 의 HTML 표준 "Web messaging"): window.postMessage(message, targetOrigin [, transfer]), window.postMessage(message, {targetOrigin, transfer}), MessageEvent, structuredClone(value [, {transfer}]). MessageChannel 과 MessagePort 는 포트를 worker 와 공유하므로 PortApi 로 설치한다. 메시지는 구조화 복제 알고리즘(StructuredClone)으로 복사하며 전달 목록에 ArrayBuffer 와 MessagePort 객체를 실을 수 있고(옮겨지고 원본은 분리된다), 보내는 쪽이 실행되는 동안이 아니라 나중에 컴포넌트의 스케줄러에서 페이지의 작업으로 전달된다. window 에 대한 postMessage 는 대상 오리진을 검사한다: * 은 보내고, /(옵션 형식의 기본값)는 같은 오리진에 보내며(이 컴포넌트의 유일한 window), URL 은 페이지의 오리진과 같을 때만 보내고, 그 밖은 SyntaxError 이다. 다른 오리진으로 가는 메시지는 복제한 뒤 조용히 버려진다(그래서 규격대로 전달한 객체는 내놓는다). 브라우징 문맥이 하나뿐이므로 window.postMessage 의 대상은 언제나 페이지의 window 이다.
