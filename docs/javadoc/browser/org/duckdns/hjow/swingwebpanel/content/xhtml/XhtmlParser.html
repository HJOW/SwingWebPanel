org.duckdns.hjow.swingwebpanel.content.xhtml
Class XhtmlParser

java.lang.Object
  org.duckdns.hjow.swingwebpanel.content.xhtml.XhtmlParser

public final class XhtmlParser
extends java.lang.Object

The parser for application/xhtml+xml documents (plan item P17-05): XML syntax in, the project's own DOM (org.duckdns.hjow.swingwebpanel.dom) out. The tokenizing is done by the XML parser of the Java platform through the public JAXP/SAX API (javax.xml.parsers, org.xml.sax); everything the document can name from outside is switched off, and the tree is built by XhtmlBuilder into the same node classes that the HTML parser produces.

Rules that this class guarantees:

  • No error recovery. XML names are case sensitive and the first well-formedness error ends the parse with a structured XmlParseError (line, column, message, source line) in the result. There is no fall back to the forgiving HTML parser.
  • Nothing outside the text is read. The external DTD subset and external entities are never loaded, XInclude is off, and every request that reaches the entity resolver gets an empty answer (and is listed in XhtmlResult.getRefusedReferences()). The external identifiers of the DOCTYPE are removed from the text before the XML parser sees it (the DOCTYPE node of the DOM keeps them), so the parser cannot even try to open them. The default limits that the JRE puts on entity expansion (64,000 references in JDK 6, less in newer JREs) are lifted (secure-processing off, and the jdk.xml properties where the JRE has them) because XhtmlLimits replaces them, with a count of every entity reference.
  • Named references. See XhtmlEntities: XHTML, HTML, MathML and SVG DTD identifiers get the HTML character reference names; any other undeclared entity is an error.
  • Bounded work. XhtmlLimits bound input size, depth, node count, attribute count, expanded text size and time; an entity bomb ends with XmlParseError.Kind.LIMIT_EXCEEDED.
  • Document. The document has the content type application/xhtml+xml, is not an HTML document (names are case sensitive), is in no-quirks mode and gets its character set from the encoding decision (XmlDecoder). The XML declaration is not a node; comments, processing instructions (xml-stylesheet included, which this class does not interpret) and the document type are.
Typical use: 
 XhtmlParser p = new XhtmlParser();
 p.setListener(scripts.createParserListener());              // optional, same callbacks as HtmlParser
 XhtmlResult r = p.parse(bytes, "UTF-8", "http://host/page.xhtml");
 if (!r.isWellFormed()) { show an error page from r.getError(); } else { use r.getDocument(); }
Threading: an instance is used by one thread and parses once; the listener is called on that thread in document order. Because an XML parse cannot be suspended, the ParserControl that the listener receives ignores pause() and insertAtInsertionPoint; an external script cannot hold up the parse and must be handled after it.

application/xhtml+xml 문서의 파서(계획 P17-05): XML 구문을 받아 프로젝트 자체 DOM(org.duckdns.hjow.swingwebpanel.dom)을 만든다. 토큰화는 Java 플랫폼의 XML 파서를 공개 JAXP/SAX API(javax.xml.parsers, org.xml.sax)로 써서 하며, 문서가 바깥에서 가져올 수 있는 모든 것은 꺼 두고, 트리는 XhtmlBuilder 가 HTML 파서가 만드는 것과 같은 노드 클래스로 만든다.

이 클래스가 보장하는 규칙:

  • 오류 복구 없음. XML 이름은 대소문자를 구분하고 첫 well-formed 오류가 해석을 끝내며 결과에 구조화된 XmlParseError(줄, 열, 메시지, 소스 줄)가 담긴다. 관대한 HTML 파서로 되돌아가지 않는다.
  • 텍스트 밖은 읽지 않는다. 외부 DTD 서브셋과 외부 엔티티는 절대 읽지 않고, XInclude 는 꺼져 있으며, 엔티티 해석기에 닿는 모든 요청에는 빈 답을 준다(XhtmlResult.getRefusedReferences() 에 기록). DOCTYPE 의 외부 식별자는 XML 파서가 보기 전에 텍스트에서 제거하므로(DOM 의 DOCTYPE 노드는 그대로 가진다) 파서가 열어 보려는 시도조차 하지 못한다. JRE 가 엔티티 확장에 두는 기본 상한(JDK 6 은 6만 4천 번, 새 JRE 는 더 적다)은 풀어 둔다(secure-processing 끄기와, 있는 JRE 에서는 jdk.xml 속성). 모든 엔티티 참조를 세는 XhtmlLimits 가 대신하기 때문이다.
  • 이름 있는 참조. XhtmlEntities 참조: XHTML, HTML, MathML, SVG DTD 식별자에는 HTML 문자 참조 이름을 주고 그 밖의 선언되지 않은 엔티티는 오류이다.
  • 한정된 작업. XhtmlLimits 가 입력 크기, 깊이, 노드 수, 속성 수, 펼친 텍스트 크기, 시간을 제한한다. 엔티티 폭탄은 XmlParseError.Kind.LIMIT_EXCEEDED 로 끝난다.
  • 문서. 문서의 콘텐츠 타입은 application/xhtml+xml, HTML 문서가 아니며(이름은 대소문자 구분), no-quirks 모드이고, 문자셋은 인코딩 판정(XmlDecoder)에서 얻는다. XML 선언은 노드가 아니다. 주석, 처리 명령(이 클래스가 해석하지 않는 xml-stylesheet 포함), 문서 유형은 노드이다.
사용 예는 위의 영문 코드와 같다.

스레드: 인스턴스는 한 스레드가 쓰며 한 번만 해석한다. 리스너는 그 스레드에서 문서 순서대로 호출된다. XML 해석은 중단할 수 없으므로 리스너가 받는 ParserControl 은 pause() 와 insertAtInsertionPoint 를 무시한다. 외부 스크립트가 해석을 붙잡을 수 없으므로 해석이 끝난 뒤에 처리해야 한다.
