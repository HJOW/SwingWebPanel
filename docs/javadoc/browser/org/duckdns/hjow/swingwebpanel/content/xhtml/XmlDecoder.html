Class XmlDecoder

public final class XmlDecoder
extends java.lang.Object

Decodes the bytes of an XML or XHTML document (plan item P17-05). The order of the decision follows XML 1.0 Appendix F and RFC 7303 with the usual browser behaviour:

  1. a byte order mark (UTF-8, UTF-16LE, UTF-16BE) wins;
  2. otherwise the charset parameter of the transport layer (HTTP Content-Type), if the label is a known and decodable encoding;
  3. otherwise a UTF-16 document without byte order mark is recognized by its first bytes (3C 00 3F 00, 00 3C 00 3F);
  4. otherwise the encoding of the XML declaration (a UTF-16 label on bytes that are ASCII compatible is ignored and UTF-8 is used, as the HTML Standard does for such a label);
  5. otherwise UTF-8, the default of XML.
Unlike HTML, malformed byte sequences are not replaced by U+FFFD: an XML document that is not valid in its encoding is not well-formed, so the result carries an error with the line and column where the text stops. Labels are matched by the Encoding Standard table of EncodingLabels (euc-kr, windows-949, utf8 and so on).

XML/XHTML 문서의 바이트를 디코딩한다(계획 P17-05). 판정 순서는 XML 1.0 부록 F 와 RFC 7303 에 일반적인 브라우저 동작을 더한 것이다.

  1. 바이트 순서 표시(UTF-8, UTF-16LE, UTF-16BE)가 이긴다;
  2. 없으면 전송 계층(HTTP Content-Type)의 charset 매개변수. 라벨이 알려진, 디코딩 가능한 인코딩일 때;
  3. 없으면 바이트 순서 표시가 없는 UTF-16 문서를 첫 바이트(3C 00 3F 00, 00 3C 00 3F)로 알아본다;
  4. 없으면 XML 선언의 encoding(ASCII 호환 바이트에 UTF-16 라벨이 붙었으면 무시하고 UTF-8 을 쓴다. HTML 표준이 그런 라벨을 다루는 방식과 같다);
  5. 없으면 XML 의 기본값 UTF-8.
HTML 과 달리 잘못된 바이트 순서를 U+FFFD 로 바꾸지 않는다: 인코딩에 맞지 않는 XML 문서는 well-formed 가 아니므로 결과가 텍스트가 멈춘 줄과 열이 있는 오류를 가진다. 라벨은 EncodingLabels 의 Encoding 표준 표로 맞춘다(euc-kr, windows-949, utf8 등).
