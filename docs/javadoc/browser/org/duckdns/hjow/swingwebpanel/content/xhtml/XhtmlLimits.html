org.duckdns.hjow.swingwebpanel.content.xhtml
Class XhtmlLimits

java.lang.Object
  org.duckdns.hjow.swingwebpanel.content.xhtml.XhtmlLimits

public final class XhtmlLimits
extends java.lang.Object

Upper bounds for parsing one XHTML document (plan item P17-05). They make every attack on the parser end with a bounded error (XmlParseError.Kind.LIMIT_EXCEEDED) instead of an endless loop or an exhausted heap: an entity expansion bomb ("billion laughs" or one huge entity used many times), a very deep nesting, millions of nodes or attributes, or a parse that simply takes too long. The defaults suit real documents with a large margin; a host that needs other values changes them with the setters before the parse. The values are copied when a parse starts, so changing an instance during a parse has no effect on it.

XHTML 문서 하나를 해석할 때의 상한(계획 P17-05). 파서에 대한 모든 공격이 무한 반복이나 힙 고갈이 아니라 한정된 오류 (XmlParseError.Kind.LIMIT_EXCEEDED)로 끝나게 한다: 엔티티 확장 폭탄("billion laughs", 또는 큰 엔티티 하나를 여러 번 쓰는 경우), 아주 깊은 중첩, 수백만 개의 노드나 속성, 단순히 너무 오래 걸리는 해석. 기본값은 실제 문서에 넉넉하며 다른 값이 필요한 호스트는 해석 전에 setter 로 바꾼다. 해석을 시작할 때 값을 복사하므로 해석 도중에 인스턴스를 바꿔도 영향이 없다.

setMaxEntityExpansions

public XhtmlLimits setMaxEntityExpansions(int value)
Sets the maximum number of entity expansions. Every reference to a general entity counts, &nbsp; as well as the references inside the replacement text of an entity; this is what stops "billion laughs" style documents.

엔티티 확장의 최대 수를 지정한다. 일반 엔티티 참조는 모두 센다. &nbsp; 도, 엔티티의 치환 텍스트 안의 참조도 센다. 이것이 "billion laughs" 형태의 문서를 막는다.
