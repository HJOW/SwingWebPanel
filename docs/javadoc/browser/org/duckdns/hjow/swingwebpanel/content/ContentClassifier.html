org.duckdns.hjow.swingwebpanel.content
Class ContentClassifier

java.lang.Object
  org.duckdns.hjow.swingwebpanel.content.ContentClassifier

public final class ContentClassifier
extends java.lang.Object

Decides which processor shows a body (plan items P17-01, P01-17, P01-18). One decision table serves the network (a response with a Content-Type and maybe Content-Disposition: attachment) and setContent (a MIME argument), so both paths use the same content handling.

Policy for responses (classifyResponse(String, boolean, byte[])):

  1. Content-Disposition: attachment always means a download.
  2. A missing or malformed Content-Type is not an error: the type is found by looking at the first bytes (sniff(byte[]), the "unknown MIME type" algorithm of the WHATWG MIME Sniffing Standard in a reduced form: HTML tags, <?xml, PDF, image/audio/video signatures, archives, then "text or binary"). The result is text/html, text/plain or a binary type, never an error page.
  3. text/html is HTML, application/xhtml+xml is XHTML, text/markdown (and the older text/x-markdown) is Markdown, text/plain is plain text.
  4. Every other text/* type, JavaScript types, application/json and +json types and application/xml, +xml types (RSS, Atom, ...) are shown as plain text, so their source is readable. Two exceptions: the text/* types that Chromium does not show as text (calendar, vCard, CSV, RTF and similar: the list kUnsupportedTextTypes of third_party/blink/common/mime_util/mime_util.cc, read on 2026-11-16, current development revision of the Chromium repository) go to the download path; and an application/xml or text/xml body whose root element is html in the XHTML namespace is XHTML, as in browsers.
  5. image/* is an image (image/svg+xml included), audio/* and application/ogg are audio, video/* is video (shown as an unsupported-video placeholder).
  6. Everything else (application/octet-stream, PDF, archives, fonts, multipart/*, ...) is a download.
Policy for setContent (classifySetContent(String)): the MIME argument must be one of text/html, text/plain, text/markdown, application/xhtml+xml; parameters are removed and the type is compared ignoring case; null, empty and every other type is an IllegalArgumentException (not a download).

Not covered: the "text or binary" check for servers that send binary data as text/plain, and the X-Content-Type-Options: nosniff header.

본문을 어느 처리기가 보여 줄지 정한다(계획 P17-01, P01-17, P01-18). 결정 표 하나가 네트워크(Content-Type 과 경우에 따라 Content-Disposition: attachment 가 있는 응답)와 setContent(MIME 인수)를 함께 맡으므로 두 경로가 같은 콘텐츠 처리를 쓴다.

응답 정책(classifyResponse(String, boolean, byte[])):

  1. Content-Disposition: attachment 는 언제나 다운로드이다.
  2. 없거나 잘못된 Content-Type 은 오류가 아니다: 첫 바이트를 살펴 타입을 알아낸다(sniff(byte[]). WHATWG MIME Sniffing 표준의 "unknown MIME type" 알고리즘을 줄인 것: HTML 태그, <?xml, PDF, 이미지/오디오/비디오 시그니처, 압축 파일, 그 뒤 "텍스트인지 바이너리인지"). 결과는 text/html, text/plain 또는 바이너리 타입이며 오류 페이지가 아니다.
  3. text/html 은 HTML, application/xhtml+xml 은 XHTML, text/markdown(과 옛 text/x-markdown)은 Markdown, text/plain 은 일반 텍스트이다.
  4. 그 밖의 text/* 타입, JavaScript 타입, application/json 과 +json 타입, application/xml 과 +xml 타입(RSS, Atom 등)은 소스를 읽을 수 있도록 일반 텍스트로 보인다. 예외 둘: Chromium 이 텍스트로 보이지 않는 text/* 타입(캘린더, vCard, CSV, RTF 등. third_party/blink/common/mime_util/mime_util.cc 의 kUnsupportedTextTypes 목록, 2026-11-16 에 Chromium 저장소의 당시 개발 판에서 확인)은 다운로드 경로로 가고, 루트 요소가 XHTML 네임스페이스의 html 인 application/xml, text/xml 본문은 브라우저처럼 XHTML 이다.
  5. image/* 는 이미지(image/svg+xml 포함), audio/* 와 application/ogg 는 오디오, video/* 는 비디오(미지원 비디오 대체 표시)이다.
  6. 그 밖의 모든 것(application/octet-stream, PDF, 압축 파일, 글꼴, multipart/* 등)은 다운로드이다.
setContent 정책(classifySetContent(String)): MIME 인수는 text/html, text/plain, text/markdown, application/xhtml+xml 중 하나여야 한다. 매개변수는 제거하고 대소문자를 무시하여 비교한다. null, 빈 값, 그 밖의 모든 타입은 IllegalArgumentException 이다(다운로드가 아니다).

다루지 않는 것: 서버가 바이너리를 text/plain 으로 보내는 경우의 "텍스트인지 바이너리인지" 검사, X-Content-Type-Options: nosniff 헤더.

sniff

public static java.lang.String sniff(byte[] head)
Finds the media type of a body that came without a usable Content-Type ("identifying a resource with an unknown MIME type" of the WHATWG MIME Sniffing Standard, reduced). The steps, in order, on at most SNIFF_LENGTH bytes: an HTML tag after optional white space (<!DOCTYPE HTML, <html, <head, <script, <iframe, <h1, <div, <font, <table, <a, <style, <title, <b, <body, <br, <p or <!--, each followed by a space or >, ignoring case) is text/html; <?xml is text/xml; %PDF- is PDF; a byte order mark means text/plain; then the signatures of GIF, PNG, JPEG, BMP, WebP, ICO and AVIF images, of WAVE, AIFF, AU, MIDI, MP3 (ID3), Ogg, FLAC and MP4/M4A/WebM media and of gzip, ZIP and RAR archives; finally a body that contains binary control bytes is application/octet-stream and everything else is text/plain.

쓸 만한 Content-Type 없이 온 본문의 미디어 타입을 찾는다(WHATWG MIME Sniffing 표준의 "identifying a resource with an unknown MIME type"을 줄인 것). 최대 SNIFF_LENGTH 바이트에 대해 순서대로: 공백이 있을 수 있는 앞부분 뒤의 HTML 태그(영문 설명의 목록. 모두 뒤에 공백 또는 > 가 오며 대소문자 무시)는 text/html, <?xml 은 text/xml, %PDF- 는 PDF, 바이트 순서 표시는 text/plain, 이어서 GIF, PNG, JPEG, BMP, WebP, ICO, AVIF 이미지와 WAVE, AIFF, AU, MIDI, MP3(ID3), Ogg, FLAC, MP4/M4A/WebM 미디어와 gzip, ZIP, RAR 압축 파일의 시그니처, 마지막으로 바이너리 제어 바이트가 있으면 application/octet-stream, 나머지는 text/plain 이다.

Parameters:
head - the first bytes of the body or null (treated as empty, which gives text/plain) / 본문의 첫 바이트. null 은 빈 배열로 보며 text/plain 이 된다
Returns:
the media type in lower case / 소문자 미디어 타입
