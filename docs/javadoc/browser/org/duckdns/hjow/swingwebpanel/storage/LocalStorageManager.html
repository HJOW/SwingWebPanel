org.duckdns.hjow.swingwebpanel.storage
Class LocalStorageManager

java.lang.Object
  org.duckdns.hjow.swingwebpanel.storage.LocalStorageManager

public final class LocalStorageManager
extends java.lang.Object

The process-wide localStorage: one store per origin shared by all components of the JVM process, kept in one temporary file that is private to this process (the name contains the process id, a time stamp and a random number; files of other processes are never read, changed or deleted). The file is the source of truth: before every operation the manager checks whether the file changed or vanished since it last wrote or read it, and reloads it; a missing file simply means an empty store, and a file that cannot be parsed (damaged, truncated, unknown version) resets the store (plan items P16-03 to P16-06). Nothing watches the file and nothing tries to restore data that someone deleted. Writes go to a temporary file first and replace the real file in a way that never loses both versions on JRE 6 (where renaming over an existing file fails on Windows). The manager keeps no strong reference to components or documents (listeners are weak), so it never prevents garbage collection of a component. The OS is expected to delete old temporary files.

프로세스 공용 localStorage: JVM 프로세스의 모든 컴포넌트가 공유하는 오리진별 저장소이며, 이 프로세스 전용의 임시 파일 하나에 보관한다(이름에 프로세스 id, 시각, 난수가 들어 있어 다른 프로세스의 파일은 읽거나 바꾸거나 지우지 않는다). 파일이 원본이다: 매 연산 전에 파일이 마지막으로 쓰거나 읽은 뒤 바뀌었거나 사라졌는지 확인하고 다시 읽는다. 파일이 없으면 빈 저장소로 보고, 해석할 수 없는 파일(손상, 잘림, 알 수 없는 버전)은 저장소를 초기화한다(계획 P16-03~P16-06). 파일을 감시하지도, 누가 지운 데이터를 복구하려 하지도 않는다. 쓰기는 먼저 임시 파일에 한 뒤 실제 파일을 교체하며, JRE 6(Windows 에서 기존 파일 위로 이름 바꾸기가 실패함)에서도 두 판을 모두 잃지 않는 방식을 쓴다. 관리자는 컴포넌트나 문서를 강한 참조로 붙잡지 않으므로(리스너는 약한 참조) 컴포넌트의 가비지 컬렉션을 막지 않는다. 오래된 임시 파일은 OS 가 지우는 것으로 가정한다.
