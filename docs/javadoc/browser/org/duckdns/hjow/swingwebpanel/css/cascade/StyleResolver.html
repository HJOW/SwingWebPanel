DomMutationListener
public final class StyleResolver
extends java.lang.Object
implements DomMutationListener

The style engine of a document: it finds the rules that match an element, orders their declarations by the cascade (origin and importance, then specificity, then source order), computes the values and caches the ComputedStyle of every element. It subscribes to the DOM mutations of the document and drops exactly the cached styles a change can affect: an attribute change invalidates the subtree of the element (the whole parent subtree if the style sheets use sibling combinators, the whole document if they use :has()), a change of the child list does so only when structural selectors (:first-child, :empty, + ...) exist, and a change of the dynamic state (hover, focus, form state) only recomputes the styles whose computation consulted that state. A change of the media environment or of the style sheets rebuilds the rule index.

Cascade order (ascending): user agent normal, user normal, presentational hints, author normal (the style attribute last), author important, user important, user agent important. Threading: a resolver belongs to the thread that owns the document (the document thread of the browser session); it is not synchronized.

문서의 스타일 엔진: 요소와 일치하는 규칙을 찾고, 선언을 캐스케이드(출처와 중요도, 구체성, 소스 순서)로 정렬하고, 값을 계산하고, 요소마다 ComputedStyle 을 캐시한다. 문서의 DOM 변경을 구독하여 변경이 영향을 줄 수 있는 캐시된 스타일만 버린다: 속성 변경은 요소의 서브트리를(스타일 시트가 형제 결합자를 쓰면 부모 서브트리 전체, :has() 를 쓰면 문서 전체), 자식 목록 변경은 구조 선택자(:first-child, :empty, + 등)가 있을 때만, 동적 상태(hover, focus, 폼 상태) 변경은 계산에서 그 상태를 조회한 스타일만 다시 계산한다. 미디어 환경이나 스타일 시트가 바뀌면 규칙 색인을 다시 만든다.

캐스케이드 순서(오름차순): 사용자 에이전트 일반, 사용자 일반, 표현 힌트, 작성자 일반(style 속성이 마지막), 작성자 중요, 사용자 중요, 사용자 에이전트 중요. 스레드: 리졸버는 문서를 소유한 스레드(브라우저 세션의 문서 스레드)에 속하며 동기화하지 않는다.

updateContainerSizes

public boolean updateContainerSizes(java.util.Map<Element,double[]> measured)
Records the sizes of the query containers that a layout measured. A container whose size differs from the recorded one (or that is new, or gone) has its descendants' styles dropped, because the @container rules they match may have changed; no listener is notified, as this happens while the layout runs: the caller lays out again if the result is true.

레이아웃이 잰 질의 컨테이너의 크기를 기록한다. 기록과 크기가 다른(또는 새로 생겼거나 사라진) 컨테이너는 자손의 스타일을 버린다. 자손이 일치하는 @container 규칙이 바뀌었을 수 있기 때문이다. 레이아웃이 도는 중에 일어나는 일이므로 리스너에는 알리지 않으며, 결과가 true 이면 호출한 쪽이 다시 배치한다.

Parameters:

Returns:
