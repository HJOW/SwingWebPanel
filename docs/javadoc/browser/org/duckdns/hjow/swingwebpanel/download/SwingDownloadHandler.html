Class SwingDownloadHandler

java.lang.Object

All Implemented Interfaces:
DownloadHandler
public class SwingDownloadHandler
extends java.lang.Object
implements DownloadHandler

The download manager of a browser component (plan item P11-09, API contract section 7): it receives the navigations that must be downloaded, shows one non-modal popup per download, transfers the data on a background thread through the component's request layer (user agent, extra headers, cookies, the SSL extension point and the scheme restrictions of the ResourceFetcher) and saves it as a file. Several downloads can run at the same time.

How a transfer goes: the data is written to a partial file name.part-xxxxxxxx in the directory of the target (by default the Downloads folder of the user, or the home directory) and renamed when it is complete; an existing target is replaced only after the user confirmed it in the popup, and replacing never loses either file. A cancelled or failed download deletes its partial file; a completed file is never deleted, not even by cancelAll() or dispose().

Hosts and tests replace the popup by overriding createDownloadPopup(org.duckdns.hjow.swingwebpanel.download.DownloadRequest, org.duckdns.hjow.swingwebpanel.download.DownloadControl). In a headless environment (no screen) a download is cancelled at once and the reason is reported through the DownloadStatusSink.

Usage (inside the component): new SwingDownloadHandler(this, fetcher, cookies, sink) and install it with the session's setDownloadHandler; call dispose() when the component is disposed and cancelAll() on clean().

브라우저 컴포넌트의 다운로드 관리자(계획 P11-09, API 계약 7절): 내려받아야 하는 이동을 받아 다운로드마다 모달이 아닌 팝업을 하나씩 보여 주고, 컴포넌트의 요청 계층(User-Agent, 추가 헤더, 쿠키, SSL 확장 지점, ResourceFetcher 의 스킴 제한)으로 백그라운드 스레드에서 데이터를 전송하여 파일로 저장한다. 여러 다운로드를 동시에 처리할 수 있다.

전송 방식: 데이터는 대상이 있는 디렉터리(기본은 사용자의 Downloads 폴더, 없으면 홈 디렉터리)의 부분 파일 name.part-xxxxxxxx 에 쓰고 끝나면 이름을 바꾼다. 기존 대상은 팝업에서 사용자가 확인한 뒤에만 교체하며 교체 중에도 어느 쪽 파일도 잃지 않는다. 취소되거나 실패한 다운로드는 부분 파일을 지우고, 완료된 파일은 cancelAll() 이나 dispose() 로도 지우지 않는다.

호스트와 시험은 createDownloadPopup(org.duckdns.hjow.swingwebpanel.download.DownloadRequest, org.duckdns.hjow.swingwebpanel.download.DownloadControl) 을 재정의하여 팝업을 바꾼다. 헤드리스 환경(화면 없음)에서는 다운로드를 즉시 취소하고 이유를 DownloadStatusSink 로 알린다.

사용법(컴포넌트 안에서): new SwingDownloadHandler(this, fetcher, cookies, sink) 를 만들어 세션의 setDownloadHandler 로 설치하고, 컴포넌트가 폐기될 때 dispose(), clean() 때 cancelAll() 을 호출한다.

cancelAll

public void cancelAll()
Cancels every running download and closes its popup. Finished downloads and their files are not touched. The partial files are deleted by the transfer threads; use awaitIdle(long) to wait for that.

실행 중인 모든 다운로드를 취소하고 팝업을 닫는다. 끝난 다운로드와 그 파일은 건드리지 않는다. 부분 파일은 전송 스레드가 지우며, 기다리려면 awaitIdle(long) 을 쓴다.
