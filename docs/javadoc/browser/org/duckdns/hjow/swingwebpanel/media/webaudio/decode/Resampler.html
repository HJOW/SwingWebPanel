Class Resampler

java.lang.Object
  org.duckdns.hjow.swingwebpanel.media.webaudio.decode.Resampler

public final class Resampler
extends java.lang.Object

A streaming sample rate converter for one channel of floating point audio (plan item P25-05: the resampling of decodeAudioData to the sample rate of the context). It is a windowed sinc interpolator in the polyphase form: every output sample is the sum of the input samples around its position, weighted by a Kaiser windowed sinc low-pass kernel whose cut-off sits at the Nyquist frequency of the lower of the two rates (so an up-conversion removes the images and a down-conversion removes what would alias).

Design and quality. The kernel is designed for STOPBAND_ATTENUATION_DB (100 dB, better than the 16 bit resolution of the decoders that feed it) with a transition band of TRANSITION_FRACTION of the lower Nyquist frequency: the pass band is flat (the Kaiser ripple is about 10-5, 0.0001 dB) up to 90 % of that Nyquist frequency and everything at or above it is attenuated by the stop band attenuation. The Kaiser window gives the specified attenuation with the fewest taps of the common window families (the formula of Kaiser: N = (A - 7.95) / (14.36 * df) with df the transition width in cycles per input sample); that is about 130 taps per output sample at the same rate and proportionally more when the output rate is lower (the kernel is stretched by the ratio). Each phase of the kernel is normalised to a gain of exactly 1 at DC.

Phases. When both rates are whole numbers the ratio is reduced to up / down and, if up is at most MAX_EXACT_PHASES and the table is small enough, every output sample uses one of up exact precomputed phases (no interpolation error at all, e.g. 44100 to 48000 uses 160 phases). Otherwise (large up, non-integer rates) the table has INTERPOLATED_PHASES rows (fewer for a very wide kernel) and the two nearest rows are interpolated linearly; the error of that is about -120 dB for the 1024 rows (measured: at most 8.3e-7 for full scale noise against the exact phases; it shrinks with the square of the ratio of the sample rates, so fewer rows suffice for a wide kernel).

Position and length. Output sample n is at the time n / outputRate, i.e. at the input position n * inputRate / outputRate; the filter is symmetric around that position, so there is no delay. The input before the first sample and after the last one is taken as zero. The output has ceil(inputFrames * outputRate / inputRate) samples (see outputLength(long)): every output sample whose time lies inside the duration of the input is produced, so the duration is preserved to less than one output sample and no tail of the input is cut off. The result near the two ends is the response of the filter to the zero extension, as with any finite signal.

Streaming. Samples are given in chunks of any size with process(float[], int, int, float[], int), then the tail is flushed with finish(float[], int); the result does not depend on how the input is split (it is bit for bit the same). Only a window of the input of the kernel length is kept, so memory does not grow with the length of the signal. One instance converts one channel; use one instance per channel. An instance is not thread-safe (no sharing between threads without a lock), but instances share nothing, so different instances may run in different threads.

부동 소수점 오디오 한 채널용 스트리밍 표본율 변환기(계획 P25-05: decodeAudioData 를 컨텍스트의 표본율로 바꾸기). 다상(polyphase) 형태의 창 함수를 씌운 sinc 보간기이다. 출력 표본마다 자기 위치 둘레의 입력 표본을 Kaiser 창을 씌운 sinc 저역 통과 커널로 가중해 더한다. 커널의 차단 주파수는 두 표본율 중 낮은 쪽의 나이퀴스트 주파수이다(그래서 올릴 때는 이미지를 없애고 내릴 때는 앨리어싱될 성분을 없앤다).

설계와 품질. 커널은 STOPBAND_ATTENUATION_DB(100 dB, 입력을 만드는 디코더의 16비트 해상도보다 좋다)에 낮은 쪽 나이퀴스트 주파수의 TRANSITION_FRACTION 만큼의 전이 대역으로 설계한다. 통과 대역은 그 나이퀴스트 주파수의 90 % 까지 평탄하고(Kaiser 리플은 약 10-5, 0.0001 dB) 그 이상은 정지 대역 감쇠만큼 줄어든다. Kaiser 창은 흔한 창 함수 중 정해진 감쇠를 가장 적은 탭으로 얻는다(Kaiser 의 식 N = (A - 7.95) / (14.36 * df), df 는 입력 표본당 주기로 잰 전이 폭). 같은 표본율에서는 출력 표본당 약 130 탭이고 출력 표본율이 낮으면 그 비율만큼 늘어난다(커널을 비율만큼 늘린다). 커널의 각 위상은 DC 이득이 정확히 1 이 되도록 정규화한다.

위상. 두 표본율이 모두 정수이면 비율을 up / down 으로 약분하고, up 이 MAX_EXACT_PHASES 이하이며 표가 충분히 작으면 출력 표본마다 미리 계산한 up 개의 정확한 위상 중 하나를 쓴다(보간 오차가 전혀 없다. 예: 44100 에서 48000 은 160 위상). 그렇지 않으면(큰 up, 정수가 아닌 표본율) 표는 INTERPOLATED_PHASES 행(아주 넓은 커널이면 더 적게)이고 가장 가까운 두 행을 선형 보간한다. 그 오차는 1024 행에서 약 -120 dB 이다(실측: 정확한 위상과 비교해 풀 스케일 잡음에서 최대 8.3e-7. 표본율 비율의 제곱에 비례해 줄어들기 때문에 넓은 커널에는 더 적은 행으로 충분하다).

위치와 길이. 출력 표본 n 은 시간 n / outputRate, 곧 입력 위치 n * inputRate / outputRate 에 있다. 필터는 그 위치에 대칭이므로 지연이 없다. 첫 표본 앞과 마지막 표본 뒤의 입력은 0 으로 본다. 출력은 ceil(inputFrames * outputRate / inputRate) 개이다(outputLength(long) 참조). 입력의 재생 시간 안에 시간이 드는 출력 표본을 모두 만들므로 재생 시간이 출력 표본 하나보다 작은 오차로 보존되고 입력의 끝이 잘리지 않는다. 양 끝 근처의 결과는 유한한 신호가 늘 그렇듯 0 으로 연장한 신호에 대한 필터의 응답이다.

스트리밍. 표본은 어떤 크기의 덩어리로든 process(float[], int, int, float[], int) 에 주고 마지막에 finish(float[], int) 로 꼬리를 비운다. 결과는 입력을 어떻게 나누었는지와 무관하다(비트 단위로 같다). 커널 길이만큼의 입력 창만 보관하므로 신호가 길어도 메모리가 늘지 않는다. 인스턴스 하나가 채널 하나를 변환한다. 채널마다 인스턴스를 쓴다. 인스턴스는 스레드 안전하지 않지만(잠금 없이 스레드 사이에 공유하지 말 것) 인스턴스끼리는 아무것도 공유하지 않으므로 서로 다른 인스턴스는 서로 다른 스레드에서 돌려도 된다.
