org.duckdns.hjow.swingwebpanel.media.image
Class ImageDecoders

java.lang.Object
  org.duckdns.hjow.swingwebpanel.media.image.ImageDecoders

public final class ImageDecoders
extends java.lang.Object

The registry and entry point of all image decoders (plan items P18-01, P18-02, P18-03). decode(byte[], java.lang.String, org.duckdns.hjow.swingwebpanel.media.DecodeLimits) looks at the first bytes of the data (file signature) to choose the decoder; a MIME type given by the caller is only a hint that breaks ties between decoders that accept the same bytes, so a wrong extension or Content-Type does not decide the format. The built-in decoders are PNG/APNG, GIF, JPEG, BMP and ICO/CUR. Decoders written elsewhere are found by name through reflection when their class is present: org.duckdns.hjow.swingwebpanel.media.image.webp.WebpDecoder, org.duckdns.hjow.swingwebpanel.media.image.avif.AvifDecoder and org.duckdns.hjow.swingwebpanel.media.image.svg.SvgDecoder; a missing or broken class is skipped silently. More decoders can be added with register(org.duckdns.hjow.swingwebpanel.media.image.ImageDecoder). All methods are thread-safe.

모든 이미지 디코더의 등록부이자 진입점(계획 P18-01, P18-02, P18-03). decode(byte[], java.lang.String, org.duckdns.hjow.swingwebpanel.media.DecodeLimits) 는 데이터의 첫 바이트(파일 시그니처)로 디코더를 고르며, 호출자가 준 MIME 타입은 같은 바이트를 받아들이는 디코더가 여럿일 때 승부를 가르는 힌트로만 쓰므로 잘못된 확장자나 Content-Type 이 형식을 결정하지 못한다. 내장 디코더는 PNG/APNG, GIF, JPEG, BMP, ICO/CUR 이다. 다른 곳에서 만든 디코더는 클래스가 있으면 이름으로 리플렉션해 찾는다: org.duckdns.hjow.swingwebpanel.media.image.webp.WebpDecoder, org.duckdns.hjow.swingwebpanel.media.image.avif.AvifDecoder, org.duckdns.hjow.swingwebpanel.media.image.svg.SvgDecoder. 클래스가 없거나 깨져 있으면 조용히 건너뛴다. register(org.duckdns.hjow.swingwebpanel.media.image.ImageDecoder) 로 디코더를 더 추가할 수 있다. 모든 메서드는 스레드 안전하다.
