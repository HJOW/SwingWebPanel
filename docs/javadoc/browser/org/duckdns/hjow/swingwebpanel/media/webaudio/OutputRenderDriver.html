Class OutputRenderDriver

java.lang.Object

All Implemented Interfaces:
java.lang.Runnable, RealtimeAudioContext.Driver
public final class OutputRenderDriver
extends java.lang.Object
implements RealtimeAudioContext.Driver, java.lang.Runnable

The driver of a real-time context that plays through a sound output (plan item P25-07): it replaces the ClockRenderDriver when the audio should be heard. One daemon rendering thread (swingwebpanel-audio-render-N, a high priority) renders chunks of the context and writes each chunk to an AudioOutput; the output makes the write wait while its buffer is full, which paces the thread to real speed and keeps the buffer full. The class is pure Java; the OutputFactory decides which device is used (the default is the Java Sound line of SystemOutputFactory).

Segments. The thread lives from the first start(org.duckdns.hjow.swingwebpanel.media.webaudio.RealtimeAudioContext.Renderer) to close() and works in segments: each time the context runs (after start(org.duckdns.hjow.swingwebpanel.media.webaudio.RealtimeAudioContext.Renderer) or a resume) it opens the output, renders chunks until a pause() or close(), and releases the output. A suspended context therefore holds no sound device (and a pause is silent at once: the queued audio is discarded, the context time continues from the rendered frame when it resumes). If the device cannot be opened, or cannot play, the segment plays into a NullOutput instead: nothing is heard, the context time still advances at real speed and the graph works (the same role as the ClockRenderDriver, but through the same code path and with the same lead of the time as a real device); the next segment tries the device again, so a device that appears later is used. getOutputProblem() tells why the device was not used.

Buffers and latency. The latency in seconds that the context was created with decides two sizes. The chunk is the number of render quanta that are rendered before one write, half of the latency in quanta, from 1 to 16 (10 ms: 1 quantum, 20 ms: 3, 100 ms: 16 at 44100 Hz); it is the unit of the base latency of the thread. The buffer is the audio that is kept queued for the device, the larger of 0.05 seconds and 4 times the latency, rounded up to a whole number of chunks (at least two). A Java Sound line is not reliable with a buffer of a few milliseconds, which is why the buffer is not the latency itself. After every write the thread reports the queued audio in seconds to the context (RealtimeAudioContext.reportOutputLatency(double)), which is what outputLatency shows. currentTime counts the rendered frames, so it leads the sound that is heard by that queue; getOutputTimestamp() tells which context time is heard now.

Underruns. If rendering is slower than real time (a heavy graph, a busy computer, a late ScriptProcessorNode handler) the device runs dry. The thread then renders and writes as fast as it can until the buffer is full again: no audio is dropped or repeated, the latency does not grow, and the gap in the sound lasts as long as the shortage. getUnderrunCount() counts the writes that found the output empty.

Threads. start(org.duckdns.hjow.swingwebpanel.media.webaudio.RealtimeAudioContext.Renderer), pause() and close() return at once and may be called from any thread (the context serializes them); they only set flags, wake the thread and stop the output so that a write that waits returns. The thread is the only caller of the renderer and of the output, and it never calls a script.

소리 출력으로 재생하는 실시간 컨텍스트의 드라이버(계획 P25-07): 소리가 들려야 할 때 ClockRenderDriver 를 대신한다. 데몬 렌더링 스레드 하나(swingwebpanel-audio-render-N, 높은 우선순위)가 컨텍스트를 청크 단위로 렌더링해 AudioOutput 에 쓴다. 출력은 버퍼가 가득 차 있으면 쓰기를 기다리게 하며, 이것이 스레드를 실제 속도로 맞추고 버퍼를 가득 채워 둔다. 클래스는 순수 Java 이며 어떤 장치를 쓸지는 OutputFactory 가 정한다 (기본은 SystemOutputFactory 의 Java Sound 라인).

구간. 스레드는 처음 start(org.duckdns.hjow.swingwebpanel.media.webaudio.RealtimeAudioContext.Renderer) 부터 close() 까지 살며 구간으로 일한다: 컨텍스트가 도는 구간마다(start(org.duckdns.hjow.swingwebpanel.media.webaudio.RealtimeAudioContext.Renderer) 나 재개 뒤) 출력을 열고, pause() 나 close() 까지 청크를 렌더링하고, 출력을 해제한다. 그래서 일시정지된 컨텍스트는 소리 장치를 붙잡지 않는다(일시정지는 곧바로 조용해진다: 큐의 오디오는 버려지고, 컨텍스트 시간은 재개할 때 렌더링한 프레임에서 이어진다). 장치를 열 수 없거나 재생할 수 없으면 그 구간은 대신 NullOutput 으로 재생한다: 아무것도 들리지 않지만 컨텍스트 시간은 실제 속도로 진행하고 그래프는 동작한다(ClockRenderDriver 와 같은 역할이지만 같은 코드 경로를 지나고 실제 장치와 같은 시간의 앞섬을 가진다). 다음 구간은 장치를 다시 시도하므로 나중에 나타난 장치를 쓴다. getOutputProblem() 이 장치를 쓰지 못한 이유를 알려 준다.

버퍼와 지연. 컨텍스트를 만들 때의 지연(초)이 두 크기를 정한다. 청크는 한 번 쓰기 전에 렌더링하는 render quantum 의 수로, 지연(quantum 수)의 절반이며 1 ~ 16 이다(44100 Hz 에서 10 ms: 1, 20 ms: 3, 100 ms: 16). 스레드의 기본 지연의 단위이다. 버퍼는 장치를 위해 쌓아 두는 오디오로, 0.05 초와 지연의 4 배 중 큰 값을 청크의 정수 배(최소 둘)로 올림한 것이다. Java Sound 라인은 수 밀리초의 버퍼에서 믿을 수 없으므로 버퍼는 지연 그 자체가 아니다. 스레드는 쓸 때마다 큐의 오디오(초)를 컨텍스트에 알리며(RealtimeAudioContext.reportOutputLatency(double)) 이것이 outputLatency 로 보인다. currentTime 은 렌더링한 프레임을 세므로 들리는 소리보다 그 큐만큼 앞선다. getOutputTimestamp() 는 지금 들리는 컨텍스트 시간을 알려 준다.

언더런. 렌더링이 실시간보다 느리면(무거운 그래프, 바쁜 컴퓨터, 늦은 ScriptProcessorNode 핸들러) 장치가 빈다. 그러면 스레드는 버퍼가 다시 가득 찰 때까지 가능한 한 빨리 렌더링하고 쓰므로 오디오가 버려지거나 반복되지 않고 지연이 커지지 않으며, 소리의 끊김은 부족했던 시간만큼 이어진다. getUnderrunCount() 는 출력이 비어 있는 것을 발견한 쓰기의 횟수를 센다.

스레드. start(org.duckdns.hjow.swingwebpanel.media.webaudio.RealtimeAudioContext.Renderer), pause(), close() 는 곧바로 돌아오며 어느 스레드에서나 부를 수 있다(컨텍스트가 직렬화한다). 플래그를 정하고 스레드를 깨우고, 기다리는 쓰기가 돌아오도록 출력을 멈출 뿐이다. 렌더러와 출력을 부르는 것은 이 스레드뿐이며 스크립트는 부르지 않는다.

restart

public void restart()
Ends the segment that runs now and starts the next one at once, so that a new factory (see setOutputFactory(org.duckdns.hjow.swingwebpanel.media.webaudio.output.OutputFactory)) is used from now on: the output of the old segment is released (the audio that was queued in it is discarded, at most one buffer of it, 50 to 80 ms) and the next segment opens a new output. The time of the context goes on from the rendered frames, as at a pause and a resume, but the state of the context is not touched. It has no effect while the driver is paused, not started or closed (the next start uses the new factory anyway). The script layer calls it for setSinkId of a running context.

지금 돌고 있는 구간을 끝내고 곧바로 다음 구간을 시작해 새 팩터리(setOutputFactory(org.duckdns.hjow.swingwebpanel.media.webaudio.output.OutputFactory) 참고)를 이제부터 쓰게 한다: 이전 구간의 출력은 해제되고(그 안에 큐에 있던 오디오는, 많아야 버퍼 하나 분량인 50 ~ 80 ms, 버려진다) 다음 구간이 새 출력을 연다. 컨텍스트의 시간은 일시정지와 재개 때처럼 렌더링한 프레임에서 이어지지만 컨텍스트의 상태는 건드리지 않는다. 드라이버가 일시정지, 시작 전, 닫힘이면 효과가 없다(다음 시작이 어차피 새 팩터리를 쓴다). 스크립트 계층이 실행 중인 컨텍스트의 setSinkId 에 쓴다.

getOutputTimestamp

public OutputRenderDriver.Timestamp getOutputTimestamp()
Returns the context time that the output plays now and the clock reading at which that is true. While nothing plays it is the rendered time. The value is an estimate from the output queue at the last write plus the time that has passed since, never beyond the rendered time.

출력이 지금 재생하는 컨텍스트 시간과 그것이 참인 시계 값을 반환한다. 아무것도 재생하지 않으면 렌더링한 시간이다. 값은 마지막 쓰기 때의 출력 큐에 그 뒤로 지난 시간을 더한 추정이며 렌더링한 시간을 넘지 않는다.

Returns:
the timestamp / 타임스탬프
