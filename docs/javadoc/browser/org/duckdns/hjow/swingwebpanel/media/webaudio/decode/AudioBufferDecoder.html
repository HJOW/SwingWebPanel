org.duckdns.hjow.swingwebpanel.media.webaudio.decode
Class AudioBufferDecoder

java.lang.Object
  org.duckdns.hjow.swingwebpanel.media.webaudio.decode.AudioBufferDecoder

public final class AudioBufferDecoder
extends java.lang.Object

The decoding pipeline of decodeAudioData (plan item P25-05): encoded audio file data in, an AudioBuffer at the sample rate of the context out. It reuses the audio decoders of the media layer through their wide path (AudioDecoders.openWide(byte[], java.lang.String, org.duckdns.hjow.swingwebpanel.media.DecodeLimits)), which choose the decoder from the signature of the data (the MIME type is only a hint, the specification says the type is determined by sniffing), so every format the media elements play is decoded here too: WAV (PCM, float, mu-law, A-law, ADPCM), AIFF/AIFF-C, AU, FLAC (native and in Ogg), MP3, AAC (ADTS and MP4), Ogg Vorbis, Opus and WebM audio.

Channels and samples. The buffer has every channel of the file (up to 32; a 5.1 file gives six channels) with the precision of the file: an N bit integer sample is exactly sample / 2^(N-1), floating point samples are kept, and a lossy codec delivers its own float output without the rounding to 16 bits and without clipping (so a value can leave the range -1 to 1, as it can in a browser). The channel order is the canonical one of the Web Audio speaker layouts (front left, front right, front centre, LFE, back left, back right, back centre, side left, side right; mono and stereo as they are), which is also the order of FFmpeg and of the WAVEFORMATEXTENSIBLE mask: formats that code the channels in another order (Vorbis, Opus mapping family 1 and AAC) are mapped to it (see FloatPcmSource). No mix is applied. Samples that are not finite numbers (what a decoder can produce from damaged data) are replaced by silence and reported in the warning.

Resampling. If the rate of the file differs from the wanted rate, every channel is converted with a Resampler while it is decoded (block by block, so the whole file is never held in memory in float form before the conversion). The converted length is ceil(frames * wanted / rate).

Errors and damaged data. Data that cannot be decoded at all is an EncodingError (AudioException.Kind#ENCODING) with the cause attached (unknown format, a header that is damaged or a format variant that is not supported, a file with no samples, a sample rate that cannot be converted, data over the limits, no memory, more than 32 channels). Data that is damaged or cut off after frames were decoded is not an error: the frames before the damage are the result and DecodeResult.isTruncated() tells that it is only a part (as in a browser, which plays what it can decode; the Web Audio API 1.1 draft encourages a warning in that case, which DecodeResult.getWarning() and DecodeWarningCallback carry). A decoder that fails before it delivered the first frame gives an EncodingError. A cancelled decoding ends with a CancellationException instead (no error: the result is simply not wanted). Arguments that the caller controls (a null array, a sample rate outside 3000 to 768000 Hz) are errors of the caller.

Limits. The input is limited by DecodeLimits (64 MB by default), the output by WebAudioLimits.MAX_BUFFER_SAMPLES samples (all channels together), the number of decoded input samples by MAX_INPUT_SAMPLES. The class has no state: it can be used from any number of threads at once.

decodeAudioData 의 디코딩 파이프라인(계획 P25-05): 인코딩된 오디오 파일 데이터가 들어가고 컨텍스트의 표본율인 AudioBuffer 가 나온다. 미디어 계층의 오디오 디코더를 넓은 경로(AudioDecoders.openWide(byte[], java.lang.String, org.duckdns.hjow.swingwebpanel.media.DecodeLimits))로 재사용하며, 그 디코더는 데이터의 시그니처로 디코더를 고른다(MIME 타입은 힌트일 뿐이며 규격도 타입을 스니핑으로 정한다고 한다). 그래서 미디어 요소가 재생하는 모든 형식을 여기서도 디코딩한다: WAV(PCM, 부동 소수점, mu-law, A-law, ADPCM), AIFF/AIFF-C, AU, FLAC(네이티브와 Ogg), MP3, AAC(ADTS와 MP4), Ogg Vorbis, Opus, WebM 오디오.

채널과 표본. 버퍼는 파일의 모든 채널(최대 32개. 5.1 파일은 채널 여섯 개)을 파일의 정밀도로 가진다. N비트 정수 표본은 정확히 표본 / 2^(N-1), 부동 소수점 표본은 그대로이고, 손실 코덱은 16비트 반올림과 클리핑 없이 자기 float 출력을 준다(그래서 값이 브라우저에서처럼 -1 ~ 1 범위를 벗어날 수 있다). 채널 순서는 Web Audio 스피커 배치의 표준 순서(앞 왼쪽, 앞 오른쪽, 앞 중앙, LFE, 뒤 왼쪽, 뒤 오른쪽, 뒤 중앙, 옆 왼쪽, 옆 오른쪽. 모노와 스테레오는 그대로)이며 이는 FFmpeg 와 WAVEFORMATEXTENSIBLE 마스크의 순서이기도 하다. 채널을 다른 순서로 부호화하는 형식(Vorbis, Opus 매핑 군 1, AAC)은 이 순서로 바꾼다(FloatPcmSource 참조). 믹스는 하지 않는다. 유한하지 않은 수의 표본(디코더가 손상된 데이터에서 만들 수 있다)은 무음으로 바꾸고 경고에 알린다.

리샘플링. 파일의 표본율이 원하는 표본율과 다르면 디코딩하는 동안 채널마다 Resampler 로 변환한다(블록 단위이므로 변환 전의 float 형태 전체를 메모리에 두지 않는다). 변환한 길이는 ceil(프레임 수 * 원하는 표본율 / 파일 표본율) 이다.

오류와 손상된 데이터. 전혀 디코딩할 수 없는 데이터는 원인을 붙인 EncodingError(AudioException.Kind#ENCODING)이다(알 수 없는 형식, 손상된 헤더나 지원하지 않는 형식 변형, 표본이 없는 파일, 변환할 수 없는 표본율, 한도를 넘는 데이터, 메모리 부족, 32개보다 많은 채널). 프레임을 디코딩한 뒤에 손상되거나 잘린 데이터는 오류가 아니다: 손상 앞의 프레임이 결과이고 DecodeResult.isTruncated() 가 일부뿐임을 알려 준다(디코딩할 수 있는 것을 재생하는 브라우저처럼. Web Audio API 1.1 초안은 이때 경고를 권장하며 DecodeResult.getWarning() 과 DecodeWarningCallback 이 그것을 전한다). 첫 프레임을 내기 전에 실패한 디코더는 EncodingError 이다. 취소된 디코딩은 대신 CancellationException 으로 끝난다(오류가 아니다. 결과가 필요하지 않을 뿐이다). 호출한 쪽이 정하는 인수(null 배열, 3000 ~ 768000 Hz 밖의 표본율)는 호출한 쪽의 오류이다.

한도. 입력은 DecodeLimits(기본 64 MB)로, 출력은 WebAudioLimits.MAX_BUFFER_SAMPLES 표본(모든 채널 합)으로, 디코딩한 입력 표본 수는 MAX_INPUT_SAMPLES 로 제한한다. 클래스에 상태가 없으므로 여러 스레드에서 동시에 써도 된다.

MAX_INPUT_SAMPLES

public static final long MAX_INPUT_SAMPLES
The largest number of samples (all channels together) that may be decoded from the file, before the conversion: four times the size limit of a buffer, which lets a file at a high sample rate be reduced to a buffer at the largest allowed size.

변환 전에 파일에서 디코딩할 수 있는 표본 수(모든 채널 합)의 최댓값: 버퍼 크기 한도의 4배. 표본율이 높은 파일을 허용되는 가장 큰 크기의 버퍼로 줄일 수 있게 한다.
