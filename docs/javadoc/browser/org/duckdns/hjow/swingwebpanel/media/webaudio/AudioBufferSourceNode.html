public final class AudioBufferSourceNode
extends AudioScheduledSourceNode

A source that plays an AudioBuffer (Web Audio API 1.9). The playback follows the algorithm of section 1.9.6: the playhead starts at offset and advances by the computed playback rate playbackRate * 2^(detune / 1200) (both k-rate; the sample rate of the buffer is taken into account) for every output frame; between two sample frames the signal is interpolated linearly. With loop the region from loopStart to loopEnd is repeated (the endpoints are in seconds of the buffer; invalid endpoints mean the whole buffer), in the direction of the sign of the rate. A duration given to start limits the content that is played, in seconds of the buffer and independent of the rate. The node ends when the buffer has been played to its end (without loop), the duration has been reached, or the stop time has been reached. The output has the channels of the buffer, and is a single channel of silence while the node does not play. The loop endpoints are fractional frame positions; a fraction between two frame positions at the splice of the loop is interpolated between the neighbouring frames of the region (exact for endpoints on whole frames).

AudioBuffer 를 재생하는 원천(Web Audio API 1.9). 재생은 1.9.6절의 알고리즘을 따른다: 재생 헤드는 offset 에서 시작해 출력 프레임마다 계산된 재생 속도 playbackRate * 2^(detune / 1200) (둘 다 k-rate, 버퍼의 샘플링 주파수를 반영)만큼 나아가며, 두 샘플 프레임 사이의 신호는 선형 보간한다. loop 이면 loopStart 에서 loopEnd 까지의 구간을 속도 부호의 방향으로 반복한다(끝점은 버퍼의 초 단위이며 올바르지 않은 끝점은 버퍼 전체를 뜻한다). start 에 준 duration 은 재생할 내용을 제한하며 버퍼의 초 단위이고 속도와 무관하다. 노드는 버퍼를 끝까지 재생했거나(loop 가 아닐 때) duration 에 이르렀거나 정지 시간에 이르면 끝난다. 출력은 버퍼의 채널을 가지며 노드가 재생하지 않는 동안은 무음 채널 하나이다. 루프 끝점은 소수 프레임 위치이며, 루프 이음매에서 두 프레임 위치 사이의 소수는 구간의 이웃 프레임 사이로 보간한다(끝점이 정수 프레임이면 정확하다).

acquireBuffer

public void acquireBuffer(AudioBuffer snapshot)
Replaces the content that the node plays by an acquired copy (Web Audio API 1.4.3, "acquire the content"). The script layer owns the rule that a script can set its buffer once and keeps its own array that the script may change; whenever the content is acquired (when start is called, or when the buffer is set after that) it hands a snapshot of the data to this method, so the node plays the data of that moment even if the script changes the array later. Unlike setBuffer(org.duckdns.hjow.swingwebpanel.media.webaudio.AudioBuffer) it can be called again and has no once-only rule. The snapshot must not be changed by the caller afterwards (the rendering thread reads it); share it only with other readers.

노드가 재생하는 내용을 가져온(acquire) 복사본으로 바꾼다(Web Audio API 1.4.3, "acquire the content"). 스크립트가 buffer 를 한 번만 정할 수 있다는 규칙과 스크립트가 바꿀 수 있는 자기 배열은 스크립트 계층이 맡는다. 내용을 가져오는 순간(start 를 부를 때, 또는 그 뒤에 버퍼를 정할 때) 그 순간의 데이터 스냅샷을 이 메서드에 넘기므로, 스크립트가 나중에 배열을 바꿔도 노드는 그 순간의 데이터를 재생한다. setBuffer(org.duckdns.hjow.swingwebpanel.media.webaudio.AudioBuffer) 와 달리 다시 부를 수 있고 한 번만 정한다는 규칙이 없다. 호출자는 스냅샷을 나중에 바꾸면 안 된다(렌더링 스레드가 읽는다). 읽기만 하는 다른 쪽과만 공유한다.

Parameters:
snapshot - the content to play, or null for none / 재생할 내용. 없으면 null
