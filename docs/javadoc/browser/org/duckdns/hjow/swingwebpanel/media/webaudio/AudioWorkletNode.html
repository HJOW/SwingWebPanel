org.duckdns.hjow.swingwebpanel.media.webaudio
Class AudioWorkletNode

java.lang.Object
  org.duckdns.hjow.swingwebpanel.media.webaudio.AudioNode
      org.duckdns.hjow.swingwebpanel.media.webaudio.AudioWorkletNode

public final class AudioWorkletNode
extends AudioNode

The engine side of an AudioWorkletNode (Web Audio API 1.0, 1.32): a node with a configurable number of inputs and outputs and a set of named AudioParams whose audio is produced by a AudioWorkletNode.Processor, code that lives outside the engine (the script layer runs a JavaScript AudioWorkletProcessor there). The class is plain Java: it knows nothing about scripts, it only runs the processor on the rendering thread once per render quantum and keeps the rules of the specification around it.

  • Channels. Defaults are channelCount 2, mode max, interpretation speakers. The number of channels of an output is the matching outputChannelCount entry; without the list it is 1, except when the node has exactly one input and one output, when it follows the number of channels of the input (computedNumberOfChannels). The constructor refuses a node without inputs and outputs and an outputChannelCount list that does not fit (1.32.3.3.2).
  • The processor. It is created by a AudioWorkletNode.ProcessorFactory that runs on the rendering thread as a control message, at the start of the next render quantum (the specification queues "a control message to invoke the constructor"). A factory that is not ready may return null; it is asked again at the next quantum, up to 2000 times. Until the processor exists, and after it failed, the output is silence.
  • Processing. In every quantum in which the node is actively processing, AudioWorkletNode.Processor.process(org.duckdns.hjow.swingwebpanel.media.webaudio.AudioWorkletNode, int) reads the active inputs with getInput(int) (null while nothing active is connected to the input), writes the outputs (getOutput(int), zero filled with the right number of channels) and reads the parameter values (copyParameter(int, float[]): one value when the block is constant, a value per frame otherwise). Its result is the active source flag: ACTIVE keeps the node processing without active inputs (the node is retained by the context, 1.32.3), INACTIVE makes the node process only while an input is active, SKIPPED means the processor could not run in time: silence for this quantum and nothing else changes.
  • Failure. A RuntimeException of the processor (a WorkletProcessorException carries the report of a script error) ends it for good: the active source flag becomes false, the output of that quantum and of every later one is silence, and the AudioWorkletNode.ErrorListener is told on the control side (the processorerror event, 1.32.3.2).

AudioWorkletNode 의 엔진 쪽(Web Audio API 1.0, 1.32): 입력과 출력의 수를 정할 수 있고 이름 있는 AudioParam 을 가진 노드이며, 오디오는 엔진 밖에 있는 코드인 AudioWorkletNode.Processor 가 만든다(스크립트 계층이 그 자리에서 JavaScript AudioWorkletProcessor 를 실행한다). 클래스는 순수 Java 이다: 스크립트를 모르고, render quantum 마다 렌더링 스레드에서 프로세서를 실행하며 그 둘레의 규격 규칙만 지킨다.

  • 채널. 기본값은 channelCount 2, 모드 max, 해석 speakers 이다. 출력의 채널 수는 outputChannelCount 의 해당 항목이다. 목록이 없으면 1 이고, 입력과 출력이 정확히 하나씩일 때만 입력의 채널 수(computedNumberOfChannels)를 따른다. 생성자는 입력과 출력이 모두 없는 노드와 맞지 않는 outputChannelCount 목록을 거부한다(1.32.3.3.2).
  • 프로세서. AudioWorkletNode.ProcessorFactory 가 만들며, 렌더링 스레드에서 제어 메시지로 다음 render quantum 시작에 실행된다(규격은 "생성자를 호출하는 제어 메시지"를 쌓는다). 준비되지 않은 팩터리는 null 을 반환할 수 있고 다음 quantum 에서 다시 부르며, 최대 2000 번 시도한다. 프로세서가 생기기 전과 실패한 뒤의 출력은 무음이다.
  • 처리. 노드가 활성으로 처리하는 quantum 마다 AudioWorkletNode.Processor.process(org.duckdns.hjow.swingwebpanel.media.webaudio.AudioWorkletNode, int) 가 getInput(int) 으로 활성 입력을 읽고(입력에 활성인 것이 연결되어 있지 않으면 null), 출력(getOutput(int), 알맞은 채널 수로 0 을 채움)을 쓰고, 파라미터 값(copyParameter(int, float[]): 블록이 일정하면 값 하나, 아니면 프레임마다 하나)을 읽는다. 결과는 active source flag 이다: ACTIVE 는 활성 입력이 없어도 노드가 계속 처리하게 하고(컨텍스트가 노드를 붙잡는다. 1.32.3), INACTIVE 는 입력이 활성인 동안만 처리하게 하며, SKIPPED 는 프로세서가 제때 실행하지 못했다는 뜻이다(이번 quantum 은 무음이고 다른 것은 바뀌지 않는다).
  • 실패. 프로세서의 RuntimeException(WorkletProcessorException 이 스크립트 오류의 보고를 담는다)은 프로세서를 영구히 끝낸다: active source flag 가 false 가 되고, 그 quantum 과 이후 모든 quantum 의 출력은 무음이며, 제어 쪽에서 AudioWorkletNode.ErrorListener 가 통지받는다(processorerror 이벤트, 1.32.3.2).
