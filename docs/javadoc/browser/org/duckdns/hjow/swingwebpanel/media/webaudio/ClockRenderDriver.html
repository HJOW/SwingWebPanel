Class ClockRenderDriver

java.lang.Object

All Implemented Interfaces:

public final class ClockRenderDriver
extends java.lang.Object
implements RealtimeAudioContext.Driver, java.lang.Runnable

The driver of a real-time context that has no sound device (or does not use one): a daemon thread renders the graph at the pace of the wall clock and throws the output away, so the currentTime of the context advances like the time of a context that plays, the sources start and end on time, the analysers and the script processors see the audio, and nothing is heard. It is the default driver of the script layer and the fallback of a driver that cannot open a device.

Pacing: the thread renders a quantum when the number of frames rendered is behind the number of frames that the wall clock has produced since the driver started (plus a small lead of LEAD_QUANTA quanta, so that the thread does not wake up exactly at the end of a quantum), and sleeps otherwise. After a pause (a suspended context or a long stop of the process) it renders the frames that are due at once and then keeps the pace, but never more than MAX_CATCH_UP_QUANTA quanta in a row, so that a stall does not starve the other threads. Suspending resets the base of the clock, so the time does not jump when the context is resumed.

The thread is created when the driver starts for the first time and ends when the driver is closed. A driver renders one context.

소리 장치가 없는(또는 쓰지 않는) 실시간 컨텍스트의 드라이버: 데몬 스레드가 벽시계의 속도로 그래프를 렌더링하고 출력을 버린다. 그래서 컨텍스트의 currentTime 이 소리를 내는 컨텍스트의 시간처럼 흐르고, 원천이 제때 시작하고 끝나며, 분석기와 스크립트 프로세서가 오디오를 보지만 아무 소리도 나지 않는다. 스크립트 계층의 기본 드라이버이며 장치를 열지 못하는 드라이버의 대체이다.

속도 맞춤: 렌더링한 프레임 수가 드라이버가 시작한 뒤 벽시계가 만든 프레임 수(와 작은 여유 LEAD_QUANTA quantum, 스레드가 quantum 끝에 정확히 깨지 않도록)보다 뒤처지면 quantum 을 렌더링하고, 아니면 잠든다. 멈춤(일시 중단된 컨텍스트나 프로세스의 긴 정지) 뒤에는 밀린 프레임을 한꺼번에 렌더링한 뒤 속도를 유지하되, 정지가 다른 스레드를 굶기지 않도록 연달아 MAX_CATCH_UP_QUANTA quantum 을 넘지 않는다. 일시 중단하면 시계의 기준을 다시 잡으므로 재개할 때 시간이 튀지 않는다.

스레드는 드라이버가 처음 시작할 때 만들고 드라이버를 닫을 때 끝난다. 드라이버 하나가 컨텍스트 하나를 렌더링한다.
