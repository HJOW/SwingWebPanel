Class JpegDecoder

ImageDecoder
public final class JpegDecoder
extends java.lang.Object
implements ImageDecoder

A JPEG decoder (plan items P18-02, P18-03; FEATURE_MATRIX IMG-04) that combines its own parsing of the markers with the sample decoding of the JRE's javax.imageio JPEG reader. Our code reads the headers first (size, precision, process, component count, JFIF, Adobe and EXIF segments), checks the size limits before any decoding, asks ImageIO only for the raw component samples (readRaster, no colour conversion, so no ICC surprises), and does the colour conversion itself.

Supported: baseline, extended sequential and progressive Huffman JPEG with 8-bit samples; 1 component (grey), 3 components (YCbCr or RGB, chosen as libjpeg does: Adobe transform 0 = RGB, JFIF = YCbCr, component ids R, G, B = RGB, otherwise YCbCr), 4 components (CMYK or YCCK; with an Adobe marker the values are inverted as Photoshop writes them, without it they are plain ink amounts); the EXIF orientation (1 to 8) is applied to the pixels and the size (ExifOrientation). An embedded ICC profile (the APP2 segments, possibly in several pieces) of the matrix/TRC or gray kind converts the pixels of grey and RGB images to sRGB (ColorProfile); other profiles (look-up table profiles, CMYK) are ignored and the samples are taken as sRGB. Not supported and reported as UNSUPPORTED_FORMAT: arithmetic coding, lossless and hierarchical processes, 12-bit samples, 2 components. A truncated file gives the part that could be decoded (like browsers; the rest is grey); damaged headers give CORRUPT.

마커 해석은 직접 하고 샘플 디코딩은 JRE 의 javax.imageio JPEG 리더에 맡기는 JPEG 디코더(계획 P18-02, P18-03; FEATURE_MATRIX IMG-04). 먼저 헤더(크기, 정밀도, 방식, 성분 수, JFIF, Adobe, EXIF 세그먼트)를 직접 읽고, 디코딩 전에 크기 제한을 확인하며, ImageIO 에는 성분 원시 샘플(readRaster, 색 변환 없음이므로 ICC 문제 없음)만 요청하고, 색 변환은 직접 한다.

지원: 8비트 샘플의 baseline, extended sequential, progressive 허프만 JPEG. 성분 1개(회색), 3개(YCbCr 또는 RGB, libjpeg 와 같은 규칙: Adobe 변환 0 = RGB, JFIF = YCbCr, 성분 id 가 R, G, B = RGB, 그 밖에는 YCbCr), 4개(CMYK 또는 YCCK. Adobe 표지가 있으면 Photoshop 처럼 값이 반전되어 있고 없으면 일반 잉크량으로 본다). EXIF 방향(1~8)을 픽셀과 크기에 적용한다(ExifOrientation). 내장 ICC 프로파일(APP2 세그먼트, 여러 조각일 수 있음)이 행렬/TRC 나 회색조 종류이면 회색/RGB 이미지의 픽셀을 sRGB 로 바꾼다(ColorProfile). 다른 프로파일(룩업 테이블 프로파일, CMYK)은 무시하고 샘플을 sRGB 로 본다. 지원하지 않아 UNSUPPORTED_FORMAT 로 보고하는 것: 산술 부호화, 무손실/계층 방식, 12비트 샘플, 성분 2개. 잘린 파일은 디코딩된 부분만 반환하고(브라우저처럼. 나머지는 회색) 헤더가 손상되면 CORRUPT 이다.
