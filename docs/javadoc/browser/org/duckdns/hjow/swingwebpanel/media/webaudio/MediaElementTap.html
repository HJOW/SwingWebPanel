Class MediaElementTap

All Implemented Interfaces:
AudioOutputFactory, MediaElementPcmSource
public final class MediaElementTap
extends java.lang.Object
implements MediaElementPcmSource, AudioOutputFactory

The connection between the player of a media element (an audio element of the page, see MediaPlayer) and a MediaElementAudioSourceNode of an audio graph (plan item P25-04, P25-07): the player of the element plays into this object instead of into the speakers, and the node of the graph pulls what the player produced, one render quantum at a time. The object plays both roles: it is the AudioOutputFactory of the player (it opens a pipe, the "output" that the player writes 16 bit PCM to) and the MediaElementPcmSource of the node (it converts the PCM of the pipe to floating point at the sample rate of the context and delivers it on request).

  • The clock of the element is the graph. The player derives the position of the media from the frames that it wrote minus the frames that are still queued in its output (MediaPlayer documents it); here the output is the pipe, which the graph drains at the pace of the rendering of the context. So the position, the timeupdate events and the ended event of the element follow the audio that the graph has consumed, and the element stands still while the pipe is not drained: while the context is suspended, or while the element is paused (the player stops the pipe). This is also what a browser does (the output of the element is taken by the graph, and the media stalls when nobody takes it).
  • Volume and muting are the business of the player: it multiplies the samples by the volume of the element (0 while it is muted) before it writes them, so the volume and muted of the element also apply to the audio that enters the graph (a browser does the same: the volume of the element is applied to the audio that it provides to the node).
  • Sample rate. If the media was recorded at another rate than the context runs at, the pipe converts it with the streaming Resampler (one instance per channel; it takes from the ring only as many frames as the quantum needs, but the filter looks about 65 source frames ahead, so the position of the media leads the audio that the graph has delivered by about 1.5 ms, which is not noticeable; the tail of the converter is delivered when the player closes the pipe at the end of the media).
  • Cross-origin media that the page may not read (fetched without the permission of the server): the host says so; the pipe is then drained at the normal pace but the node receives silence, so the element is not stalled and the page learns nothing of the audio.
  • After the node is released (release(), called when the context is closed): the element stays bound to the node for good (a browser cannot restore the normal output of an element either); the pipe then drains in real time by the wall clock and delivers nothing, so the element goes on playing, silently.
The methods of the player are called by its playback thread, the methods of the source by the rendering thread of the context, and MediaElementTap.Pipe.getQueuedFrames() by any thread; a lock that is held only while a few thousand samples are copied makes it safe (the playback thread never holds it while it decodes or waits).

미디어 요소(페이지의 audio 요소. MediaPlayer 참고)의 재생기와 오디오 그래프의 MediaElementAudioSourceNode 를 잇는 것(계획 P25-04, P25-07): 요소의 재생기는 스피커 대신 이 객체로 재생하고, 그래프의 노드는 재생기가 만든 것을 render quantum 하나씩 가져간다. 객체는 두 역할을 한다: 재생기의 AudioOutputFactory(재생기가 16비트 PCM 을 쓰는 "출력"인 파이프를 연다)이며 노드의 MediaElementPcmSource(파이프의 PCM 을 컨텍스트의 샘플링 주파수의 부동 소수점으로 바꿔 요청에 따라 준다).

  • 요소의 시계는 그래프이다. 재생기는 쓴 프레임에서 출력에 아직 큐에 있는 프레임을 뺀 값으로 미디어의 위치를 구한다(MediaPlayer 에 적혀 있다). 여기서 출력은 컨텍스트의 렌더링 속도로 그래프가 비우는 파이프이다. 그래서 요소의 위치, timeupdate 이벤트, ended 이벤트는 그래프가 소비한 오디오를 따르고, 파이프를 비우지 않는 동안(컨텍스트가 일시정지된 동안, 또는 요소가 일시정지되어 재생기가 파이프를 멈춘 동안) 요소는 멈춰 있다. 브라우저도 마찬가지이다(요소의 출력을 그래프가 가져가며 아무도 가져가지 않으면 미디어가 멈춘다).
  • 음량과 음소거는 재생기의 일이다: 재생기가 샘플을 쓰기 전에 요소의 음량(음소거이면 0)을 곱한다. 그래서 요소의 volume 과 muted 는 그래프로 들어가는 오디오에도 적용된다(브라우저도 요소가 노드에 주는 오디오에 요소의 음량을 적용한다).
  • 샘플링 주파수. 미디어가 컨텍스트가 도는 것과 다른 주파수로 녹음되었으면 파이프가 스트리밍 Resampler(채널마다 인스턴스 하나)로 바꾼다. quantum 이 필요로 하는 만큼만 링에서 가져오지만 필터는 원본 프레임을 약 65 개 앞서 보므로, 미디어의 위치는 그래프가 전달한 오디오보다 약 1.5 ms 앞선다(들리지 않는다). 변환기의 꼬리는 미디어가 끝나 재생기가 파이프를 닫을 때 내보낸다.
  • 페이지가 읽을 수 없는 교차 오리진 미디어(서버의 허가 없이 가져온 것): 호스트가 알린다. 파이프는 그래도 보통 속도로 비워지지만 노드는 무음을 받으므로 요소는 멈추지 않고 페이지는 오디오에 대해 아무것도 알 수 없다.
  • 노드를 놓은 뒤(release(). 컨텍스트가 닫힐 때 부른다): 요소는 영원히 노드에 묶인 채로 남는다(브라우저도 요소의 보통 출력을 되돌릴 수 없다). 파이프는 그때부터 벽시계 속도로 비워지고 아무것도 주지 않으므로 요소는 소리 없이 계속 재생된다.
재생기의 메서드는 재생 스레드가, 원천의 메서드는 컨텍스트의 렌더링 스레드가, MediaElementTap.Pipe.getQueuedFrames() 는 어느 스레드든 부른다. 몇천 개의 표본을 복사하는 동안에만 쥐는 잠금이 안전하게 해 준다(재생 스레드는 디코딩하거나 기다리는 동안에는 쥐지 않는다).
