Class MediaSpool

      org.duckdns.hjow.swingwebpanel.media.audio.MediaSpool
All Implemented Interfaces:
java.io.Closeable, java.io.Flushable
public final class MediaSpool
extends java.io.OutputStream

The receiver of the body of a media response while it streams in (plan item P18-08): the first MEMORY_LIMIT bytes stay in memory; when the body grows beyond that, everything moves to a temporary file (File.createTempFile in the default temporary directory) and the rest is appended there, so a long recording never sits in the heap. A body larger than MAX_BYTES fails with an IOException, which aborts the request. finish() turns the received bytes into a MediaData that owns the file; discard() deletes a partial file (failure, cancellation). Used by one fetching thread.

미디어 응답의 본문이 흘러 들어오는 동안의 받는 쪽(계획 P18-08): 처음 MEMORY_LIMIT 바이트는 메모리에 두고, 본문이 그보다 커지면 모두 임시 파일(기본 임시 디렉터리의 File.createTempFile)로 옮겨 나머지를 거기에 붙이므로 긴 녹음이 힙에 놓이지 않는다. MAX_BYTES 보다 큰 본문은 IOException 으로 실패하여 요청을 중단한다. finish() 는 받은 바이트를 파일을 소유하는 MediaData 로 바꾸고 discard() 는 덜 받은 파일을 지운다(실패, 취소). 가져오는 스레드 하나가 쓴다.
