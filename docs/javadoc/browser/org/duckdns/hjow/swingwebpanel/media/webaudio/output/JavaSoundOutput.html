Class JavaSoundOutput

All Implemented Interfaces:
AudioOutput
public final class JavaSoundOutput
extends java.lang.Object
implements AudioOutput

The output on a Java Sound SourceDataLine of the default mixer (public API javax.sound.sampled only), playing 16-bit signed little-endian PCM. The line is opened with a buffer of the capacity that the context asks for, and the write(float[][], int) method hands the audio to the line in pieces that fit the free room of the line buffer, so it never blocks inside the Java Sound call: when the buffer is full it sleeps for about the time in which the device plays one piece, and a close() or a stop at that point is noticed within a few milliseconds. The sample of a float is rounded to the nearest 16-bit value (an error of at most 1/65536 of the full scale) and clipped; no dither is added.

If the device does not play the sample rate of the context, the output tries other rates in the order 48000, 44100, 96000, 32000, 24000, 22050, 16000, 12000, 11025, 8000 Hz and converts the audio with the streaming Resampler (a windowed sinc of 100 dB stop band attenuation) before it is written; the queue is still reported in frames of the context rate. A device that cannot play the number of channels is tried with 2 and then 1 channel, and getChannels() reports what was opened. Because the sample rate of the context never depends on the device, a page sees the same sampleRate on every computer.

기본 믹서의 Java Sound SourceDataLine 위의 출력(공개 API javax.sound.sampled 만 사용)이며 16비트 부호 있는 리틀 엔디언 PCM 을 재생한다. 라인은 컨텍스트가 요청한 용량의 버퍼로 열리고, write(float[][], int) 는 라인 버퍼의 빈 자리에 들어가는 조각으로 오디오를 라인에 넘기므로 Java Sound 호출 안에서 절대 블록하지 않는다: 버퍼가 가득 차면 장치가 한 조각을 재생하는 시간만큼 잠자고, 그 사이의 close() 나 정지는 몇 밀리초 안에 알아챈다. float 샘플은 가장 가까운 16비트 값으로 반올림되고(오차는 풀 스케일의 1/65536 이하) 잘리며 디더는 더하지 않는다.

장치가 컨텍스트의 샘플링 주파수를 재생하지 못하면 출력은 48000, 44100, 96000, 32000, 24000, 22050, 16000, 12000, 11025, 8000 Hz 순서로 다른 주파수를 시도하고 쓰기 전에 스트리밍 Resampler(저지 대역 감쇠 100 dB 의 창 sinc)로 오디오를 변환한다. 큐는 여전히 컨텍스트 주파수의 프레임으로 보고한다. 장치가 채널 수를 재생하지 못하면 2채널, 1채널을 시도하며 getChannels() 는 연 값을 알린다. 컨텍스트의 샘플링 주파수는 장치에 의존하지 않으므로 페이지는 어떤 컴퓨터에서나 같은 sampleRate 를 본다.

getConversionDelayFrames

public int getConversionDelayFrames()
Returns the delay that the conversion of the sample rate adds, in frames of the data rate: the converter is a linear phase filter, so the first frames that it can compute need that many frames of input, and everything that is written comes out that much later (0 if the device plays the rate of the data). For 44100 Hz to 48000 Hz it is about 64 frames, 1.5 ms.

표본율 변환이 더하는 지연을 데이터 주파수의 프레임으로 반환한다: 변환기는 선형 위상 필터이므로 처음 계산할 수 있는 프레임에 그만큼의 입력 프레임이 필요하고, 쓴 모든 것이 그만큼 늦게 나온다(장치가 데이터의 주파수를 재생하면 0). 44100 Hz 에서 48000 Hz 로는 약 64 프레임, 1.5 ms 이다.

Returns:
the delay in frames / 지연(프레임)
