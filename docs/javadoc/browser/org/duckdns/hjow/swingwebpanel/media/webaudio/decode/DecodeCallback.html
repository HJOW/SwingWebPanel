org.duckdns.hjow.swingwebpanel.media.webaudio.decode
Interface DecodeCallback

All Known Subinterfaces:
DecodeWarningCallback
public interface DecodeCallback

The receiver of the result of an asynchronous decoding (DecodeSuccessCallback and DecodeErrorCallback of the specification; the script layer turns the pair into the resolution or the rejection of a promise). Exactly one of the two methods is called, once, for a request that is not cancelled, on the thread of the callback executor given with the request or, without one, on the decoding thread. An exception that a method throws is caught and dropped by the service: it does not affect other requests. A callback that wants to be told when a buffer holds only the part of a damaged or cut-off file that could be decoded implements DecodeWarningCallback.

비동기 디코딩의 결과를 받는 쪽(규격의 DecodeSuccessCallback 과 DecodeErrorCallback. 스크립트 계층이 이 한 쌍을 promise 의 이행이나 거부로 바꾼다). 취소되지 않은 요청에 대해 두 메서드 중 정확히 하나가 한 번 불리며, 요청과 함께 준 콜백 실행기의 스레드에서, 없으면 디코딩 스레드에서 불린다. 메서드가 던진 예외는 서비스가 잡아서 버리며 다른 요청에 영향을 주지 않는다. 손상되었거나 잘린 파일에서 디코딩할 수 있었던 부분만 버퍼에 담겼을 때 그것을 알고 싶은 콜백은 DecodeWarningCallback 을 구현한다.
