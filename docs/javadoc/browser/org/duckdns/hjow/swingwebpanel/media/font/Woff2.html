Class Woff2

java.lang.Object
  org.duckdns.hjow.swingwebpanel.media.font.Woff2

public final class Woff2
extends java.lang.Object

The decoder of WOFF 2.0 web fonts (plan item P10-08-e, W3C Recommendation "WOFF File Format 2.0", https://www.w3.org/TR/WOFF2/, last modified 2024-08-05, read with tools/webfetch on 2026-11-18): a WOFF2 file holds the tables of an sfnt font in one Brotli stream (Brotli) after a table directory with known-tag codes and variable-length numbers. toSfnt(byte[]) reads the header, the table directory (the 63 known tags, the UIntBase128 lengths, the transform versions), checks the structure of the file (lengths, padding, no extraneous data), decompresses the stream and rebuilds an ordinary sfnt file that the JRE can read with Font.createFont: the transformed glyf table (section 5.1: the seven streams, the triplet coordinates of section 5.2 with their 128 flag values, composite glyphs, instructions, the bounding box bitmap and the overlap bitmap), the loca table that is rebuilt with it (5.3) and the transformed hmtx table (5.4, the left side bearings come from the glyph boxes) are reconstructed; every table gets a new checksum and the head table a new checkSumAdjustment. The tables are sorted by tag as an sfnt requires. Everything that the specification says a decoder must reject (a wrong signature, extraneous data, overlapping or out-of-range data, a UIntBase128 with leading zeros or longer than five bytes, an unknown transform version, a transformed loca with a length, an empty glyph with a box, a composite glyph without a box, a size that does not match the sum of the table lengths, a Brotli failure) is rejected with an IOException, and so is what this decoder cannot represent safely (font collections ttcf, output over MAX_SFNT_SIZE, a glyph point that leaves the 16 bit range, a contour without points). The extended metadata and the private data blocks are checked for their place and ignored.

Verification: there was no WOFF2 file made by a browser or another independent encoder on the machine of the author, so the decoder is tested with files that were made by encoders written for the tests from the same specification text (a script for real JRE fonts and a builder for synthetic fonts and invalid files): an error in how the specification was read would be in both the encoder and the decoder and stay unseen. What protects against that is that the encoders use the table of section 5.2 as data (the decoder uses the closed formulas), that the result of real fonts is compared with the original font table by table and glyph by glyph (also with Java2D), and that the Brotli part is verified against the reference encoder separately.

WOFF 2.0 웹 글꼴 디코더(계획 P10-08-e, W3C 권고안 "WOFF File Format 2.0", https://www.w3.org/TR/WOFF2/, 최종 수정 2024-08-05, 2026-11-18 에 tools/webfetch 로 읽음): WOFF2 파일은 알려진 태그 코드와 가변 길이 수가 있는 테이블 디렉터리 뒤에 sfnt 글꼴의 테이블을 Brotli 스트림(Brotli) 하나로 담는다. toSfnt(byte[]) 는 헤더, 테이블 디렉터리(알려진 태그 63 개, UIntBase128 길이, 변환 버전)를 읽고 파일 구조(길이, 패딩, 불필요한 데이터 없음)를 검사하고 스트림의 압축을 풀어 JRE 가 Font.createFont 로 읽을 수 있는 평범한 sfnt 파일을 다시 만든다. 변환된 glyf 테이블(5.1 절: 스트림 일곱 개, 5.2 절의 삼중 좌표와 128 개 플래그 값, 합성 글리프, 명령, 경계 상자 비트맵과 겹침 비트맵), 그것과 함께 다시 만드는 loca 테이블(5.3), 변환된 hmtx 테이블(5.4, 왼쪽 여백은 글리프 상자에서 온다)을 복원하고, 모든 테이블에 새 체크섬을, head 테이블에 새 checkSumAdjustment 를 준다. 테이블은 sfnt 가 요구하는 대로 태그 순으로 정렬한다. 규격이 디코더가 거부해야 한다고 한 모든 것(틀린 서명, 불필요한 데이터, 겹치거나 범위를 벗어난 데이터, 앞이 0 이거나 다섯 바이트보다 긴 UIntBase128, 모르는 변환 버전, 길이가 있는 변환된 loca, 상자가 있는 빈 글리프, 상자가 없는 합성 글리프, 테이블 길이의 합과 다른 크기, Brotli 실패)과 이 디코더가 안전하게 나타낼 수 없는 것(글꼴 컬렉션 ttcf, MAX_SFNT_SIZE 를 넘는 출력, 16 비트 범위를 벗어난 글리프 점, 점이 없는 윤곽선)은 IOException 으로 거부한다. 확장 메타데이터와 비공개 데이터 블록은 위치만 검사하고 무시한다.

검증: 작성자의 PC 에는 브라우저나 다른 독립 인코더가 만든 WOFF2 파일이 없었으므로 이 디코더는 같은 규격 텍스트로 시험용으로 쓴 인코더(실제 JRE 글꼴용 스크립트와 합성 글꼴· 잘못된 파일용 생성기)가 만든 파일로 시험한다. 규격을 잘못 읽었다면 그 오류는 인코더와 디코더에 함께 들어 보이지 않을 수 있다. 이를 줄이는 것은 인코더가 5.2 절의 표를 자료로 쓰고(디코더는 닫힌 식을 쓴다), 실제 글꼴의 결과를 원본 글꼴과 테이블별, 글리프별(Java2D 로도) 비교하고, Brotli 부분을 참조 인코더로 따로 검증한 것이다.
