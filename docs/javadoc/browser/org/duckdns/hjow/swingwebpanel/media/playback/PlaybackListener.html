org.duckdns.hjow.swingwebpanel.media.playback
Interface PlaybackListener

public interface PlaybackListener

Receives what a MediaPlayer reports (plan items P18-08, P18-05-c). Every method is called on the playback thread of the player, outside its internal locks, so an implementation must only record the fact or queue work for the owner of the page and return quickly. Nothing is reported after MediaPlayer.close() returned. The player holds its listener weakly: the owner keeps the listener reachable for as long as it wants reports.

MediaPlayer 가 알리는 것을 받는다(계획 P18-08, P18-05-c). 모든 메서드는 재생기의 재생 스레드에서 내부 잠금 밖에서 호출되므로, 구현은 사실을 기록하거나 페이지 소유자에게 작업을 올리기만 하고 빨리 돌아와야 한다. MediaPlayer.close() 가 돌아온 뒤에는 아무것도 알리지 않는다. 재생기는 리스너를 약하게 참조하므로, 보고를 원하는 동안은 소유자가 리스너를 도달 가능하게 유지해야 한다.

started

void started()
The sound began: the output was opened and accepted the first data after a play request (also a resume after a pause, and the restart after the end). Reported once per start, so a page can tell that play() really worked.

소리가 시작되었다: 재생 요청(일시정지 뒤의 재개와 끝난 뒤의 재시작 포함)에 이어 출력이 열리고 첫 데이터를 받아들였다. 시작마다 한 번 알리므로 페이지는 play() 가 정말 동작했음을 알 수 있다.

failed

void failed(MediaException error)
Playback failed and stopped: the data turned out to be damaged, or the output device cannot be opened. The player stays loaded; a later MediaPlayer.play() tries again.

재생이 실패하여 멈췄다: 데이터가 손상된 것으로 드러났거나 출력 장치를 열 수 없다. 재생기는 로드된 채로 있으며 이후의 MediaPlayer.play() 가 다시 시도한다.

Parameters:
error - the reason (ACCESS_FAILED for the device, CORRUPT for damaged data) / 이유(장치는 ACCESS_FAILED, 손상된 데이터는 CORRUPT)
