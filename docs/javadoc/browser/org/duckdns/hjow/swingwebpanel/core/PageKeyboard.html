Class PageKeyboard

public final class PageKeyboard
extends java.awt.event.KeyAdapter
implements java.awt.event.FocusListener

Keyboard and focus input of the rendered component (plan items P11-01 and P11-02): AWT key events become DOM keydown, keypress and keyup events for the element that has the focus (the body if none has it), a key that is not cancelled does what the browser does (Tab moves the focus along the tab order and leaves the component after the last element, Enter follows a link or presses a button, Space releases a button), and the focus of the component itself is passed on to the document so that its focused element gets focus and blur. The scrolling keys are not consumed: the scroll pane that holds the component handles them.

렌더링 컴포넌트의 키보드와 포커스 입력(계획 P11-01, P11-02): AWT 키 이벤트가 포커스를 가진 요소(없으면 body)의 DOM keydown, keypress, keyup 이벤트가 되고, 취소되지 않은 키는 브라우저가 하는 일을 한다(Tab 은 Tab 순서대로 포커스를 옮기고 마지막 요소 다음에서는 컴포넌트를 떠나며, Enter 는 링크를 따라가거나 단추를 누르고, Space 는 단추를 뗀다). 컴포넌트 자신의 포커스는 문서에 전달되어 포커스를 가진 요소가 focus 와 blur 를 받는다. 스크롤 키는 소비하지 않으며 컴포넌트를 담은 스크롤 창이 처리한다.

editCommand

public void editCommand(java.lang.String command)
Runs an edit command of the host (a menu item, a tool bar button) on the page, as the matching key does, but without sending key events to the page: the clipboard events (copy, cut, paste) are still sent. Call it on the event dispatch thread (the clipboard is read there for a paste); the command itself runs on the document queue for the element that has the keyboard focus. Text controls of forms have an editor of their own and are not handled here.

호스트의 편집 명령(메뉴 항목, 도구 모음 단추)을 해당 키와 같게 페이지에서 실행하되 페이지에 키 이벤트는 보내지 않는다. 클립보드 이벤트(copy, cut, paste)는 그대로 보낸다. 이벤트 디스패치 스레드에서 부른다(붙여넣기의 클립보드를 거기서 읽는다). 명령 자체는 문서 큐에서 키보드 포커스를 가진 요소에 대해 실행한다. 폼의 텍스트 컨트롤은 자기 편집기가 있어 여기서 다루지 않는다.

Parameters:
command - one of the COMMAND_ constants / COMMAND_ 상수 가운데 하나
