org.duckdns.hjow.swingwebpanel.html
Class HtmlTokenizer

java.lang.Object
  org.duckdns.hjow.swingwebpanel.html.HtmlTokenizer

public final class HtmlTokenizer
extends java.lang.Object

The tokenizer of the HTML Standard ("tokenization", 13.2.5) as an explicit state machine with all of its 80 states: data, RCDATA, RAWTEXT, script data (with its escaped and double escaped variants), PLAINTEXT, tags and attributes, comments, DOCTYPE, CDATA sections and the character reference states. It is pull based: nextToken() runs the machine just far enough to produce the next token, so the tree builder can change the state (setState(int), e.g. after <script>) between two tokens exactly as the standard describes.

The input must already be normalized (InputPreprocessor.normalize(String): only LF line ends). All parse errors are reported to the ParseErrorLog with the standard's error codes; tokenization never stops because of an error. Characters are emitted as runs (NUL characters stay inside a run in the data and CDATA states and are dealt with by the tree builder; in the other states they are already replaced by U+FFFD). Text can be inserted at the current position (insertText(String)), which is what document.write needs.

The processing instruction states that the newest draft of the standard adds (<?target ...?>) are not implemented: as in the 2014 recommendation and in the browsers, <? starts a bogus comment (documented deviation).

HTML 표준의 토큰화("tokenization", 13.2.5)를 80 개 상태 전부를 갖춘 명시적 상태 기계로 구현한다: data, RCDATA, RAWTEXT, script data(escaped 와 double escaped 변형 포함), PLAINTEXT, 태그와 속성, 주석, DOCTYPE, CDATA 섹션, 문자 참조 상태. 당겨 가는(pull) 방식이다: nextToken() 이 다음 토큰을 만들 만큼만 기계를 돌리므로, 트리 생성기가 표준에 적힌 대로 두 토큰 사이에(예: <script> 뒤에) 상태를 바꿀 수 있다 (setState(int)).

입력은 이미 정규화되어 있어야 한다(InputPreprocessor.normalize(String): 줄 끝은 LF 뿐). 모든 파싱 오류는 표준의 오류 코드로 ParseErrorLog 에 보고되며, 오류 때문에 토큰화가 멈추지 않는다. 문자는 연속 구간으로 내보낸다(NUL 문자는 data 와 CDATA 상태에서는 구간 안에 남겨 트리 생성기가 처리하고, 다른 상태에서는 이미 U+FFFD 로 바뀐다). 현재 위치에 문자열을 삽입할 수 있다(insertText(String)). document.write 가 필요로 하는 기능이다.

표준 최신 초안이 추가한 처리 명령 상태(<?target ...?>)는 구현하지 않았다. 2014 권고안과 브라우저처럼 <? 는 bogus 주석을 시작한다(문서화된 차이).
