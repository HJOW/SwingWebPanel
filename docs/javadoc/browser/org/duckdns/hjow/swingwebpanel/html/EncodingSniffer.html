org.duckdns.hjow.swingwebpanel.html
Class EncodingSniffer

java.lang.Object
  org.duckdns.hjow.swingwebpanel.html.EncodingSniffer

public final class EncodingSniffer
extends java.lang.Object

The encoding sniffing algorithm of the HTML Standard ("determining the character encoding") for documents that arrive as bytes. The order of decision is:

  1. a byte order mark (UTF-8, UTF-16LE, UTF-16BE) - certain;
  2. the charset label of the transport layer (HTTP Content-Type) - certain, if the label is known;
  3. the prescan of the first 1024 bytes for <meta charset> or <meta http-equiv="content-type"> - tentative (the tree builder confirms or corrects it later);
  4. an extension of this implementation: if none of the above applies and the whole text is valid UTF-8 that contains multi-byte sequences, UTF-8 is assumed (tentative); this avoids garbled Korean text in pages that declare nothing;
  5. the fallback encoding, windows-1252 unless the caller names another one - tentative.
Decoding never fails: malformed input becomes U+FFFD. Pages declared as UTF-16 by a meta element are decoded as UTF-8 and x-user-defined as windows-1252, as the standard requires.

바이트로 도착하는 문서에 대한 HTML 표준의 인코딩 판정 알고리즘("determining the character encoding"). 판정 순서는 다음과 같다.

  1. 바이트 순서 표시(UTF-8, UTF-16LE, UTF-16BE) - 확실;
  2. 전송 계층(HTTP Content-Type)의 charset 라벨 - 라벨을 알 수 있으면 확실;
  3. 처음 1024 바이트에서 <meta charset> 또는 <meta http-equiv="content-type"> 를 찾는 사전 검사 - 잠정적 (트리 생성기가 나중에 확인하거나 바로잡는다);
  4. 이 구현의 확장: 위 어느 것도 해당하지 않고 전체 텍스트가 멀티바이트 순서가 있는 올바른 UTF-8 이면 UTF-8 로 가정(잠정적). 아무것도 선언하지 않은 페이지에서 한글이 깨지는 것을 막는다;
  5. 대체 인코딩. 호출자가 다른 것을 지정하지 않으면 windows-1252 - 잠정적.
디코딩은 실패하지 않는다: 잘못된 입력은 U+FFFD 가 된다. meta 요소가 UTF-16 으로 선언한 페이지는 표준대로 UTF-8 로, x-user-defined 는 windows-1252 로 디코딩한다.
