WebFontSource
public final class WebFontSet
extends java.lang.Object

The @font-face faces of a page (plan item P10-05, CSS Fonts Level 3 section 4 https://www.w3.org/TR/css-fonts-3/ edition (edition of the feature table); WOFF 1.0 https://www.w3.org/TR/WOFF/): the faces are made from the rules, the sources of a face are tried in order, and a face that is loaded is chosen for a request by the font matching of CSS Fonts 3 section 5.2 (the style first, then the weight in the order that depends on the requested weight). Formats: TrueType (0x00010000, true), WOFF 1.0 (rebuilt to TrueType with Woff) and WOFF 2.0 (decompressed with the own Brotli decoder and rebuilt with Woff2, including the transformed glyf, loca and hmtx tables; font collections are refused) are read with Font.createFont(int, java.io.InputStream), which is a public JRE API; OpenType with CFF outlines (OTTO) is attempted and, where the JRE cannot read it (JDK 6u45 throws FontFormatException, checked by the tests of the project), the source counts as failed and the next one is tried; Embedded OpenType, SVG fonts and Type 1 are not supported: a format() hint that names them (or any other unknown format) skips the source, and a file with such a signature fails. local() sources use an installed font family. Loading: the bytes come from a WebFontSet.Loader (the common request layer of the page with the cache, the headers and the same-origin rule); while they are pending the face is not used, so the text takes the next family of font-family and the page is laid out again when the bytes arrive (the swap behavior of font-display; a font that arrives after the periods of fallback or optional is not used, see late(java.lang.String, long[]); while a pending face is in its block period the text is laid out with the fallback font but not painted, see blockedUntil(java.lang.String, int, boolean, java.lang.String)). The unicode-range of a face applies to a whole text segment: the face is used only if all characters of the text are in the ranges (a segment that is split between two faces with different ranges takes the next family). A synthetic bold or italic is made by the JRE when the face lacks the requested one. At most MAX_FACES faces are read per page; the file size is limited by Woff.MAX_SFNT_SIZE. The JRE writes the fonts that it creates to temporary files that it removes when the font is collected or the JVM ends. The class is thread-safe (the layout helper thread asks, the document thread sets the rules).

페이지의 @font-face 글꼴 면(계획 P10-05, CSS Fonts Level 3 4 절 https://www.w3.org/TR/css-fonts-3/ (기능 표의 판본), WOFF 1.0 https://www.w3.org/TR/WOFF/): 글꼴 면은 규칙에서 만들고, 면의 소스는 차례로 시도하며, 읽힌 면은 CSS Fonts 3 5.2 절의 글꼴 맞춤(스타일 먼저, 그다음 요청한 굵기에 따라 정해지는 순서의 굵기)으로 요청에 골라진다. 형식: TrueType(0x00010000, true), WOFF 1.0(Woff 로 TrueType 으로 다시 만든다), WOFF 2.0(자체 Brotli 디코더로 풀고 Woff2 로 변환된 glyf, loca, hmtx 테이블까지 복원해 다시 만든다. 글꼴 컬렉션은 거부한다)은 JRE 공개 API Font.createFont(int, java.io.InputStream) 로 읽는다. CFF 외곽선의 OpenType(OTTO)은 시도하며 JRE 가 읽지 못하면(JDK 6u45 는 FontFormatException 을 던진다. 프로젝트 시험이 확인한다) 소스는 실패로 세고 다음 소스를 시도한다. Embedded OpenType, SVG 글꼴, Type 1 은 지원하지 않는다: 이들을 가리키는(또는 그 밖의 모르는 형식의) format() 힌트는 소스를 건너뛰고 그런 서명의 파일은 실패한다. local() 소스는 설치된 글꼴 패밀리를 쓴다. 로딩: 바이트는 WebFontSet.Loader(캐시, 헤더, 같은 오리진 규칙이 있는 페이지의 공통 요청 계층)에서 오며, 아직 오지 않은 동안 그 면은 쓰이지 않아 텍스트는 font-family 의 다음 패밀리를 쓰고 바이트가 오면 페이지를 다시 배치한다(font-display 의 swap 동작. fallback 나 optional 의 기간이 지난 뒤 도착한 글꼴은 쓰지 않는다(late(java.lang.String, long[]) 참조). 대기 중인 면이 block 기간에 있으면 텍스트는 대체 글꼴로 배치하되 그리지 않는다(blockedUntil(java.lang.String, int, boolean, java.lang.String) 참조)). 면의 unicode-range 는 텍스트 세그먼트 전체에 적용된다: 텍스트의 모든 글자가 범위 안일 때만 그 면을 쓴다(범위가 다른 두 면에 걸치는 세그먼트는 다음 패밀리를 쓴다). 면에 요청한 굵기나 이탤릭이 없으면 JRE 가 합성 굵게/기울임을 만든다. 페이지마다 최대 MAX_FACES 개의 면을 읽고 파일 크기는 Woff.MAX_SFNT_SIZE 로 제한한다. JRE 는 만든 글꼴을 임시 파일에 쓰고 글꼴이 수거되거나 JVM 이 끝날 때 지운다. 클래스는 스레드 안전하다(레이아웃 보조 스레드가 묻고 문서 스레드가 규칙을 정한다).

blockedUntil

public long blockedUntil(java.lang.String family,
                         int weight,
                         boolean italic,
                         java.lang.String text)
Tells until when a text that asks for a family must be invisible because the face that would show it is still loading and in the block period of its font-display (CSS Fonts 4 section 4.8: "If the font face is not loaded, any element attempting to use it must render an invisible fallback font face"). The block period starts when the request of the font starts, as measured by a WebFontSet.TimedLoader; with another loader there is no block period (the text uses the next family at once, like swap). The answer is also kept for takeBlockDeadline(), so that the page can be painted again when the period ends. Call it after find(java.lang.String, int, boolean, java.lang.String, float) returned null for the same request.

패밀리를 요청한 텍스트가 언제까지 보이지 않아야 하는지 알려 준다: 그 텍스트를 보일 면이 아직 읽는 중이고 font-display 의 block 기간에 있을 때이다(CSS Fonts 4 4.8 절: "글꼴 면을 읽지 않았으면 그것을 쓰려는 요소는 보이지 않는 대체 글꼴 면으로 그려야 한다"). block 기간은 WebFontSet.TimedLoader 가 잰 글꼴 요청의 시작부터이다. 다른 로더에서는 block 기간이 없다(텍스트는 swap 처럼 곧바로 다음 패밀리를 쓴다). 답은 takeBlockDeadline() 를 위해서도 보관하여 기간이 끝날 때 페이지를 다시 그릴 수 있게 한다. 같은 요청에 대해 find(java.lang.String, int, boolean, java.lang.String, float) 가 null 을 반환한 뒤에 부른다.
