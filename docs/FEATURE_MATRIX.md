# SwingWebPanel 기능 표

작성 시작: 2026-11-16 (P00-02 ~ P00-08, P00-10). 최종 갱신: 2026-11-17(P20-10/11/12, P22-14: 낡은 행을 현재 구현과 시험에 맞추고, `T-...`/`C-...` 계획용 번호를 실제 시험 이름으로 바꾸고, 11~14절을 더했다). 현재 상태의 요약은 13절(축별 대조)과 14절(검증 환경과 남은 차이)이다. 시험은 모두 JDK 6u45 에서 `scripts/pkgtest.sh` 로 실행한 것이다.

열: `기능 ID` · `요구사항` · `규격 URL 및 판본` · `구현 클래스`(계획된 기본안, 패키지는 `org.duckdns.hjow.swingwebpanel.*`) · `검증 사례` · `지원 상태` · `제약`.
지원 상태: **미구현 / 부분 구현 / 검증 완료**, 그리고 요구사항으로 명시된 **예외**(지원하지 않음, 3절 참조). 구현과 해당 검증이 모두 끝나야 `검증 완료`로 바꾼다.
클래스 이름은 구현 중 바뀔 수 있으며, 바뀌면 `ARCHITECTURE.md` 와 이 표를 함께 갱신한다.

## 8. 미디어: 이미지·오디오·비디오 (MED) (P00-07)

판정 대상 목록의 원칙: HTML 표준이 모든 코덱 지원을 강제한다고 가정하지 않는다. 프로젝트의 "모두 지원" 목표는 **Chromium 이 `<img>`/`<audio>` 로 재생하는 주요 컨테이너·코덱**(아래 표)을 판정 대상으로 정한다. 표에 없는 형식(JPEG XL, HEIC, TIFF, JPEG 2000, Opus 이외의 희귀 코덱 등)은 목록에 추가하기 전에는 대상이 아니다.
JRE 6 가 제공하는 것: `ImageIO` = PNG, JPEG(기본/프로그레시브 일부), GIF, BMP, WBMP / Java Sound = WAV, AU, AIFF(PCM, μ-law, A-law). (**실제 JRE 6 에서의 지원은 P18-02 에서 확인**하기 전까지 추정이다.)

**JRE 6u45 실측(MEDIA-IMG-A, 2026-11-16):** `ImageIO` 읽기 형식은 bmp, gif, jpeg(jpg), png, wbmp 뿐이며 WebP/AVIF/SVG/ICO 리더가 없다. APNG 는 기본 이미지만 읽고, GIF 프레임은 합성되지 않은 부분 이미지이며, ICO 는 WBMP 리더가 헤더(`00 00 01 00`)를 가로채 "Empty region!" 으로 실패하므로 형식 판별을 ImageIO 에 맡기지 않는다. JPEG 는 `readRaster` 로 1/3/4 성분 원시 값을 읽을 수 있으나 잘린 파일을 예외 없이 앞부분만 디코딩한다. 자체 디코더(PNG/APNG/GIF/JPEG 색·EXIF/BMP/ICO)는 `media.image` 에 구현했고 색 관리(ICC/gamma/CICP)는 MEDIA-B 가 추가했다(`media.image.color`, 2026-11-18).
