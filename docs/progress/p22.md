## 6. P22-16-c1 디코딩 취소 회귀 (2026-11-26)

`AudioDecodeServiceTest.testRandomCancellationKeepsTheBooks`는 요청을 만드는 쪽이 작업자보다 빠르면 의도하지 않게 제품 기본 64건 한도에 도달했다. 시험 전용 한도를 150건과 입력 WAV 최대 크기의 합으로 설정했다. 별도의 `testLimitsOfPendingRequests`는 요청 수와 바이트 한도 및 취소에 따른 용량 반환을 계속 확인한다. 취소 회귀는 `finally`에서 서비스를 닫는다.

JDK 8u202에서 `mvn -B -o -Dtest.filter=AudioDecodeServiceTest test`를 실행해 JDK/JRE 6u45 브라우저 시험 19건이 통과했다. 단일 취소 회귀는 JRE 6u45에서 독립 실행 12회 모두 통과했다. 이어 실행한 `JavaSoundDeviceTest`에서 형식 거부 사례는 통과했고 실제 라인 사례 2건은 믹서가 없어 건너뛰었다.

## 7. P22-16-e1 화면 다단의 강제 분할 (2026-11-26)

[CSS Fragmentation Level 3 CR, 2018-12-04 §3.4·§4.3](https://www.w3.org/TR/2018/CR-css-break-3-20181204/#forced-breaks)을 저장소의 webfetch로 2026-11-26에 조회했다. 화면 다단 레이아웃에서 `break-before/after: page`, `left`, `right`, `recto`, `verso`, `region`은 새 열을 만들지 않는다. `page-break-before/after: always`와 `-webkit-column-break-before/after: always`는 각각 `page`와 `column`으로 해석하고, `var()` 치환 전에는 원래 속성 이름을 보존한다. 기존의 `break-before/after: always`와 `all` 확장은 계속 동작한다. 중첩 분할과 인쇄 분할은 별도 제약이다.

JDK 6u45로 변경 클래스와 `FragmentationBreakTest`를 별도 디렉터리에 컴파일하고 기존 제품·시험에 앞서 로드했다. `FragmentationBreakTest`, `MulticolLayoutTest`, `MulticolCloneLayoutTest`, `BoxDecorationBreakLayoutTest`, `MulticolPaintTest`, `PropertyTest`, `CssomModelTest`, `StyleSheetTest`를 JRE 6u45로 실행해 68건이 통과했다. 이 실행은 CSSOM에서 저장한 `var()` 선언을 다시 사용한 경우를 포함한다.

## 8. P22-16-e2 블록 가장자리의 분할 값 전파 (2026-11-26)

같은 CSS Fragmentation 3 CR의 §3.1.1과 §4.3에 따라 첫째·마지막 정상 흐름 자식의 값을 조상 블록 가장자리의 값과 합친다. 열 강제 값은 회피·쪽 값에 의해 가려지지 않는다. 별도 다단 컨테이너의 자식에게 지정된 열 분할은 해당 컨테이너 내부에서 다룬다. 그리드·플렉스의 분할 전파 규칙과 중첩 컨테이너 자체의 분할은 구현 제약으로 남는다.

JRE 6u45에서 12겹 블록의 첫 자식, 쪽 값이 붙은 부모의 마지막 자식, 중첩 다단의 안쪽·바깥쪽 좌표를 검증했다. 위 7절과 같은 스위트에 사례 2건을 추가한 집중 실행은 총 70건이 통과했다.
