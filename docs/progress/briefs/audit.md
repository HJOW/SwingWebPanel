# AUDIT 작업자 브리프 (P22-16 준비: 기능 표의 `부분 구현` 행 정리)

## 목적
AGENTS.md P22-16 은 "상단 요구사항의 각 행이 구현 파일과 성공한 검증 사례에 연결되고, 명시된 비디오, 3D 가속/WebGL/WebGPU 예외와 런타임 제약 외의 미완료 목표가 없는지" 를 최종 대조한다. 지금 `docs/FEATURE_MATRIX.md` 13절에는 `부분 구현` 행이 많다. 이 작업자는 맡은 축의 `부분 구현` 행을 **하나씩** 근거를 가지고 정리한다.

## 행마다 할 일
1. 행의 `제약`/상태 문구를 읽고, 남은 차이를 항목별로 나눈다.
2. 각 차이를 다음 중 하나로 분류한다.
   - **(가) 낡은 기록**: 이미 구현되고 시험이 있다(다른 계획 항목에서 끝났는데 행 문구가 갱신되지 않음). 해당 시험 클래스·메서드를 찾아 JDK 6u45 로 **직접 돌려 통과를 확인**하고 행에 연결한다.
   - **(나) 목표 판본 안의 미구현**: 기능 표 0절/해당 절에 고정한 규격 판본(예: HTML5 2014 REC, CSS 모듈의 고정 판본, ECMA-262 6판)이 요구하는데 없다 → **구현하고 시험한다**(우선). 규격 조회는 `tools/webfetch`.
   - **(다) 목표 판본 밖**: 고정 판본 이후에 생긴 기능(현행 WHATWG/Level 4 이상/WD 의 신규 기능 등)이다 → 그 근거(판본, 절)를 적고 확장 목록(EXT)이나 행의 "목표 밖" 메모로 옮긴다. 목표 판본에 있는 기능을 여기에 넣지 않는다.
   - **(라) 런타임·플랫폼 제약**: JRE 6/Java2D/OS 가 공개 API 로 제공하지 않아 순수 Java 로도 합리적으로 불가능하다(예: JRE 6 의 TLS 1.0) → 근거(시도한 것, API 부재)를 적는다. 쉽게 이 범주로 미루지 않는다.
   - **(마) 구조적 불가/요구사항 충돌** → 명시적 예외 후보(근거)로 적고 조정자가 3절에 넣을지 정한다.
3. (나)를 모두 처리했고 남은 것이 (다)/(라)뿐이면 상태를 `검증 완료(제약 있음)` 로, 아무것도 남지 않으면 `검증 완료` 로 바꾸고, (나)가 남으면 `부분 구현` 을 유지한다. **돌려 보지 않은 시험을 근거로 쓰지 않는다.**

## 규칙
- 맡은 축의 행(브리프에서 지정)의 `상태`/`제약`/`검증 사례` 칸은 **이 작업자가 직접 고쳐도 된다**(다른 행, 0~3절, 13~14절은 조정자 몫). 그 밖에 `AGENTS.md`, `docs/PROGRESS.md`, `docs/ARCHITECTURE.md`, `scripts/**` 는 고치지 않는다.
- 공통 규칙은 `docs/progress/briefs/common.md`(Java 6, 영어+한국어 Javadoc, 한국어 주석, JDK 6u45 검증, `tools/sourcecheck` 0 위반, 한 줄 커밋, push 금지, 정직). 동시에 도는 작업자는 2명이다.
- 기록: `docs/progress/audit-<축>.md` 에 행별 표(행 ID, 차이 항목, 분류(가~마), 근거(시험 이름과 실행 결과/규격 절/시도), 처리, 새 상태). 끝에 전체 회귀 한 번(`BUILD_DIR=build/full sh test.sh`)과 결과 줄.
