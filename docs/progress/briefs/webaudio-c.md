# WEBAUDIO C 단계 브리프 (P25 JavaScript 바인딩과 출력·수명)

먼저 `docs/progress/briefs/common.md`(공통 규칙)와 `docs/progress/briefs/webaudio.md`(P25 전체 구조), `docs/progress/webaudio.md`(A1/A2 기록), `docs/progress/webaudio-b.md`(디코딩 기록)를 읽는다. AGENTS.md 의 "P25. Web Audio API"(특히 P25-05/07)를 그대로 읽는다. 빌드/시험 구조는 P26 이후의 것이다: JavaScript 엔진은 `engine/`, 브라우저는 `src/`. `scripts/pkgtest.sh` 가 두 곳을 모두 찾는다.

A1/A2/B(B2)로 **순수 Java 엔진**(`media.webaudio`, `media.webaudio.dsp`, `media.webaudio.decode`)이 끝났다. 이 단계는 그 위의 **JavaScript 바인딩**과 **실시간 출력·수명 관리**이다. 크므로 C1, C2 로 나눈다(조정자가 단계마다 따로 맡긴다).

## C1: JavaScript 바인딩과 오프라인 렌더링/디코딩의 연결 (`js.host.webaudio`, 새 패키지)
1. **전역 객체와 인터페이스**: `AudioContext`, `OfflineAudioContext`, `BaseAudioContext`(프로토타입 체인), `AudioNode`(+ 각 노드 생성자 `GainNode` 등과 `createXxx` 팩터리 전부), `AudioParam`, `AudioBuffer`(생성자와 `AudioBufferOptions`), `AudioListener`, `PeriodicWave`, `AudioDestinationNode`, 이벤트 타입(`AudioProcessingEvent`, `OfflineAudioCompletionEvent`, `MediaStream*` 이름은 노출하지 않음 — EXC-14), `EventTarget` 상속(`statechange`, `ended`, `complete`, 노드의 `onended` 등 속성 핸들러). 규격(1.0 REC 와 `docs/progress/webaudio.md` 의 대상 표)의 속성/메서드 이름, WebIDL 인수 변환(필수 인수 누락 `TypeError`, 숫자 변환 `ToNumber`/`unrestricted float`, 열거형 문자열 검사), `AudioException` → `DOMException`(이름 `IndexSizeError` 등 — 기존 `DOMException` 구현 재사용), 노드/파라미터 wrapper 의 동일성(같은 Java 객체는 항상 같은 JS 객체), `instanceof`, `Symbol.toStringTag`, 접근자 프로퍼티 속성(enumerable/configurable)을 기존 바인딩(`js/host/canvas/**`, `js/host/MessagingApi`, `js/host/web/**` 가 좋은 예)과 같은 방식으로.
2. **`AudioBuffer` 와 `getChannelData`(중심 설계 문제)**: JavaScript 의 `Float32Array` 는 `ArrayBufferObject`(Java `byte[]`)를 본다(`engine/.../js/builtins/typed/ArrayBufferObject.java`). 엔진의 `AudioBuffer` 는 `float[][]` 이다. `getChannelData(i)` 는 규격상 **같은 `Float32Array` 객체를 매번 돌려주고** 그 내용이 버퍼의 내용이다. 해결을 직접 설계해 `docs/progress/webaudio-c.md` 에 근거와 함께 기록하라. 권장 방향: JS 쪽 wrapper 가 채널별 `byte[]` 와 안정된 `Float32Array` 를 가지고, 엔진 `AudioBuffer`(float)와는 **규격의 "acquire the content" 시점**(소스 노드 `start()`, 컨볼버 `buffer` 설정, 웨이브셰이퍼 곡선 설정 등)에 복사·변환해 연결한다. 그러면 재생 중 배열을 바꿔도 이미 시작한 소리에 영향이 없는 규격 동작이 된다(A1 이 한계 5.3-2 로 적은 "배열 공유"는 JS 에 노출될 때 규격대로 복사로 바뀐다 — 필요하면 `AudioBufferSourceNode` 쪽을 수정해 acquire 복사를 구현하라. A1 파일 수정이 필요하면 그 사실과 이유를 기록). `copyFromChannel/copyToChannel` 은 같은 byte[] 를 기준으로.
3. **`decodeAudioData`**: Promise 와 콜백 형식(둘 다), `ArrayBuffer` 분리(detach, 이미 분리된 것은 `DataCloneError`), 결과는 `AudioDecodeService`(B 단계, 컨텍스트마다 하나) 를 써서 **문서 큐**로 전달하는 `Executor`(`PageScripts` 의 문서 큐 규칙을 읽을 것)로 콜백, 컨텍스트 `close`/페이지 이탈 시 취소, 문서가 활성이 아니면 `InvalidStateError`, 실패는 `EncodingError`(`DOMException`). Promise/마이크로태스크는 기존 엔진의 것을 쓴다(`js/builtins/meta/PromiseJobs`, `CanvasPromises` 가 예).
4. **`OfflineAudioContext`**: 생성자(두 형식), `startRendering()`(Promise, 결과 `AudioBuffer`), `complete` 이벤트, `suspend(time)`/`resume()`, `length`, 상태 전이(`suspended` → `running` → `closed`), 오류(이미 시작함 등)를 규격대로. 렌더링은 EDT/문서 스레드를 막지 않는 **백그라운드 스레드**에서 하고 결과와 `suspend` 콜백은 문서 큐로 전달한다.
5. **프로토콜**: 컨텍스트별 최대 노드/버퍼 한도를 `WebAudioLimits` 로 연결, 같은 페이지의 컨텍스트 수 상한(예: 6, Chrome 은 6 정도이며 초과 시 `NotSupportedError` 로 할지 결정하고 근거 기록).
6. `AudioContext`(실시간)의 **생성자/속성 접근은 이번 C1 에서 JS 쪽 형태까지 만들되**(상태 `suspended`/`running`/`closed`, `currentTime`, `sampleRate`, `baseLatency`, `outputLatency`, `resume/suspend/close` Promise) **장치로 소리를 내는 부분은 C2**이다. C1 에서는 출력 장치를 쓰지 않는 구현(시계만 진행)으로 연결해 두고 C2 가 바꿔 끼울 수 있게 인터페이스를 둔다.

## C2: 실시간 출력과 수명 (`media.webaudio` 의 실시간 컨텍스트 + 연결)
1. **실시간 `AudioContext`**: 오디오 렌더링 스레드(이름 `swingwebpanel-audio-render-N`, 데몬, 우선순위 높게)가 render quantum 을 계속 만들어 Java Sound `SourceDataLine`(P18 의 `media/playback` 이 쓰는 장치 열기/닫기·"장치 없음" 처리 코드를 읽고 재사용)으로 쓴다. 장치가 없거나 열 수 없으면 소리 없이 **시계만 진행**한다(`currentTime` 이 실시간으로 증가). `latencyHint`(`interactive`/`balanced`/`playback`/숫자)와 버퍼 크기, `baseLatency`/`outputLatency` 값, `suspend/resume/close` 가 렌더링 스레드를 멈추고 시작함, `statechange` 이벤트, 결정 e 의 자동 재생 정책(없음)과 `sinkId` 규칙을 구현한다. 렌더링 스레드는 JavaScript 를 부르지 않는다(제어 메시지만). 렌더링이 시간에 쫓길 때(노드가 너무 많음) 끊김(underrun)이 나지 않도록 버퍼 설계를 하고 측정해 기록한다.
2. **`ScriptProcessorNode`**(결정 c): `bufferSize` 프레임을 모아 문서 큐로 `audioprocess` 이벤트를 보내고 이벤트 핸들러가 채운 `outputBuffer` 를 출력으로 되돌리는 지연 있는 노드. 입력/출력 채널 수 1~32, 문서 큐가 늦으면 무음.
3. **`MediaElementAudioSourceNode`**: A2 가 만든 `MediaElementPcmSource`(이름은 A2 문서를 확인)를 P18 의 `<audio>` 재생기(`media/playback/MediaPlayer`, `js/host/MediaElements`)에 연결하는 어댑터. 요소가 이 노드에 연결되면 요소의 소리는 그래프를 거쳐 나가고 요소 자신의 직접 출력은 끈다(규격). 교차 오리진 원천은 무음(요청 오리진 정책 `OriginPolicy` 재사용). `<video>` 는 `NotSupportedError`. 재생 제어(`play/pause/seek`)와 그래프의 상호작용을 시험.
4. **수명과 정리(P21)**: 페이지 이동/`clean()`/`dispose()`/`setJavascriptEnabled(false)` 때 해당 페이지의 모든 컨텍스트를 닫고(렌더링 스레드와 오디오 라인 정리, 진행 중 디코딩 취소, 보류 중인 Promise 처리), 이전 페이지의 늦은 콜백이 새 페이지를 바꾸지 못하게 한다. `docs/ARCHITECTURE.md` 의 "자원 소유 목록과 정리 담당(P21-01)" 표와 `PageRuntime` 의 정리 경로를 읽고 같은 방식으로 연결하라(표 갱신은 "조정자 요청"). 여러 컴포넌트·여러 컨텍스트가 동시에 출력할 때 한 장치를 같이 쓰는지 각자 라인을 여는지 정하고 근거를 기록. `StaticStateAuditTest`/`ThreadCreationAuditTest` 규칙을 지킨다(정적 상태·스레드 이름 접두사 `swingwebpanel-`).
5. 한도: 활성 노드/버퍼 한도 초과 시 동작, 컨텍스트 수 상한, 오래 쓰지 않는 컨텍스트의 자원 해제(GC 에서 스레드/라인이 컨텍스트를 붙잡지 않게 WeakReference/수명 토큰 사용).

## 검증
- C1: 실제 `SwingWebPanel` 페이지(`tests` 의 `PageFixture`/`TestHttpServer`)에서 JavaScript 로 그래프를 만들고 `OfflineAudioContext` 로 렌더링해 결과 PCM 을 JS 로 읽어 **해석적 기대값**과 비교(오실레이터→게인→필터, 자동화, `decodeAudioData` 로 시험 WAV 를 디코딩해 값 확인), 모든 인터페이스의 존재/프로토타입/`instanceof`/오류 종류/WebIDL 변환, 분리된 ArrayBuffer, Promise 와 콜백 순서, 페이지 이동 중 취소, JavaScript 비활성(`AudioContext` 가 생기지 않음), 콘솔 이벤트(P24)와 예외 보고.
- C2: 장치 없음 경로(이 PC 에 Java Sound 믹서가 없다 — 기존 `JavaSoundDeviceTest` 가 건너뛰는 이유), 가짜 `SourceDataLine`(대체한 protected 메서드 또는 주입 지점)으로 쓴 PCM 의 정확성과 끊김, 상태 전이, 스레드/라인 수 누수(반복 생성·폐기 100회), 여러 컴포넌트, 이동/clean/dispose 도중 재생, `ScriptProcessorNode` 의 왕복, `<audio>` 요소 연결. 실제 스피커 청취는 하지 못하므로(사람 확인, P22-10) 자동 검증과 분리해 기록하고 `docs/progress/media-play.md` 의 "미확인" 표에 항목을 추가하라고 요청한다.
- 각 하위 단계의 완료 보고에 실제 실행한 명령과 통과/실패/건너뜀 수, 확인하지 못한 것, FEATURE_MATRIX WAU-01/07/08 행 갱신 초안, 체크박스 후보를 적는다.

## 소유 경로(충돌 방지)
- C1: `src/.../js/host/webaudio/**`(새), `tests/src/.../js/host/webaudio/**`(새), `docs/progress/webaudio-c.md`(새 기록), 그리고 `media/webaudio/**` 의 **작은 보강**(acquire 복사 등)은 필요한 최소만 하고 기록. 이미 있는 `js/host/Window*.java`/`PageScripts.java` 등에 전역을 설치하는 **한두 줄의 연결**이 필요하면 하되 목록으로 기록(다른 작업자가 같은 파일을 건드리지 않도록 조정자가 조율한다).
- C2: `media/webaudio/**` 의 실시간 컨텍스트 클래스, `js/host/webaudio/**`, 요소 연결용 `js/host/MediaElements.java` 등 최소 연결.
- 커밋 번호는 조정자가 대역을 알려 준다.
