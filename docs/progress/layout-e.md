### 2026-11-17 P10-04 배경 레이어/그라디언트/둥근 모서리/그림자/생성 콘텐츠(의사 요소)
현재 작업 번호: P10-04(부분: `::first-line` 과 이미지 로딩 후 재배치의 실제 컴포넌트 확인이 남음)
완료한 내용: 상자 장식을 "바깥 그림자 → 배경색 → 배경 레이어(이미지/그라디언트) → 안쪽 그림자 → border" 순서의 새 파이프라인으로 다시 만들었다(CSS Backgrounds 3). 둥근 모서리가 있는 상자는 배경, 레이어, border, `overflow` 클립 모두 둥근 도형을 쓴다.
- `render/RoundedBox`(신규): `border-radius` 의 8 반지름(모서리마다 가로/세로)을 border box 에 대해 풀고(길이/백분율/calc) 5.5 절의 계수 `f = min(L_i/S_i)` 로 함께 줄인다. `inset`(border/padding 만큼 안쪽 가장자리: 반지름은 너비만큼 줄고 0 미만은 아님, 5.2), `spread`(그림자 퍼짐: 각진 모서리는 각진 채), `translate`, `toShape()`(사분 타원을 베지어로 이은 경로).
- `render/BoxCommands`(신규): `ShapeFill`(둥근 배경색), `RoundedBorder`(고리 = 바깥 둥근 도형 − 안쪽 둥근 도형, 변마다 대각선으로 잘라 자기 색/스타일: solid, inset/outset, double, groove/ridge(두 띠), dashed/dotted(고리 가운데를 따라가는 선); 네 변이 같은 solid 면 한 번에 채움), `Shadow`, `RoundedClip`(`overflow` 의 둥근 padding 가장자리 클립. `DisplayCommand.getClipShape()` 와 `PagePainter` 한 줄), `Layer`(클립 도형 안의 타일: 이미지 또는 그라디언트, 간격/반복 포함). 도형은 안티앨리어싱으로 그린다.
- `render/BoxShadows`(신규): `box-shadow` 여러 개(첫 그림자가 위), 오프셋, 블러, 퍼짐, `inset`, 색(currentcolor 포함). 바깥 그림자 = border box 실루엣을 퍼짐만큼 키워 옮기고 흐린 뒤 border box 바깥으로 자른다. 안쪽 그림자 = padding box 에서 (줄이고 옮긴) 구멍 바깥을 흐린 뒤 padding box 로 자른다. 블러는 표준 편차 = 블러 반지름/2 의 가우시안을 박스 흐림 3 번(SVG 필터 방식)으로 근사하고 디스플레이 리스트를 만들 때(문서 스레드) 이미지로 계산하므로 그리기는 이미지 그리기이다. `extent()` 는 불투명도 그룹 경계에 그림자를 포함시킨다(`DisplayListBuilder.grow`).
- `render/GradientSpec`(신규): `linear-gradient`, `radial-gradient`, `conic-gradient` 와 `repeating-` 형태를 `CssFunctionValue` 구조에서 읽는다. 각도, `to` 변/모서리 키워드(마법 모서리), 색 정지점(길이/백분율, 위치 둘, 빠진/줄어드는 위치 보정 3.4.3), 색 힌트(3.4.4), **사전 곱셈 보간**(투명 정지점을 12 단계로 쪼갬, 3.4.2), 방사형의 모양/크기 키워드/명시적 반지름/`at` 위치, 원뿔형 `from`/`at`. 선형/방사형은 `LinearGradientPaint`/`RadialGradientPaint`, 원뿔형은 자체 `Paint`(`ConicPaint`, 2048 단계 표).
- `render/BackgroundLayers`(신규): `background-image` 레이어별 `origin`/`clip`/`size`/`position`/`repeat` 를 읽고 목록 반복(3.1), 위치 1~4 값과 `calc()`(예 `right 10px bottom 20px`), `repeat`/`no-repeat`/`space`/`round`, `cover`/`contain`/`auto`(그라디언트는 위치 기준 영역 크기), 레이어마다 자기 클립 도형(둥글 수 있음). 준비되지 않은(PENDING/FAILED) 이미지 레이어는 건너뛰고 다시 만들 때 나타난다. 배경색은 마지막 레이어의 `background-clip` 으로 자른다(3.7). 캔버스 배경(루트/body)도 같은 경로.
- `render/DisplayListBuilder`: `decorate` 재구성, 옛 `backgroundImages`/`tileSize`/`tilePosition`/`repeatFlags` 제거(문자열 파싱 방식 → 구조 값), `beginClip` 이 둥근 상자의 padding 가장자리 클립이면 `RoundedClip` 을 쓰고 `subtreeBounds` 가 그림자 범위를 포함. `DisplayCommand`: `Type.SHADOW`, `getClipShape()`.
- `layout/GeneratedContent`(신규), `layout/BoxBuilder`(훅): **CSS 카운터**(`counter-reset`/`counter-increment`/`counter-set`, `counter()`, `counters()`, 스타일, 중첩/형제 범위, 플렉스/그리드 컨테이너의 의사 요소도), `content` 의 문자열/`attr()`/따옴표, **`::first-letter`**(앞뒤 문장 부호를 포함한 첫 글자 단위를 의사 요소 스타일의 인라인 요소로, `float` 이면 드롭 캡 float 상자로 떼어 내고 나머지 텍스트는 원본 오프셋 `InlineItem.srcOffset` 을 유지), **`::marker`**(색/글꼴과 `content` 로 표식 교체, 안쪽 표식은 텍스트로). `ListMarkers.numeral` 추가.

미해결 사항(문서화된 한계):
1. **`::first-line` 은 구현하지 않았다**(첫 줄의 실제 줄바꿈 뒤에 그 줄의 텍스트를 다시 꾸미고 다시 배치해야 하는 줄 단위 작업. 스타일은 계산되지만 레이아웃이 쓰지 않는다). `::selection`/`::placeholder`/`::backdrop` 도 그리지 않는다.
2. `::first-letter` 는 컨테이너의 첫 인라인 텍스트에만 적용한다. 첫 자식이 블록이면 그 블록 안으로 내려가 적용하지 않는다. 세로쓰기 컨테이너에서는 글자 방향 분류와 함께 동작하나 시험하지 않았다. 블록 아닌 `display` 값의 `::first-letter` 는 인라인으로만 처리한다.
3. `content` 의 `url()`/이미지, 중첩 따옴표(`open-quote` 깊이, `quotes` 속성), `counter-*` 를 표 행/행 그룹/열 요소에 쓴 경우는 지원하지 않는다. 암시적 `list-item` 카운터는 별도 번호 매기기(목록 항목 번호)라 `counter(list-item)` 은 지원하지 않는다.
4. `background-attachment: fixed|local` 은 `scroll` 처럼 그린다. `background-clip: text` 는 그 레이어를 그리지 않는다. `image-set()`/`cross-fade()`/`element()` 는 그리지 않는다. `border-image`, `background-blend-mode`, `mix-blend-mode`, `text-shadow` 는 이 작업의 범위가 아니다(미구현).
5. 반복 방사형 그라디언트의 첫 정지점이 0 이 아니면 첫 정지점 안쪽을 반복 무늬가 아니라 패딩 색으로 그린다. 원뿔형의 길이 정지점은 무시한다. 디더링 없음(그라디언트 밴딩 가능).
6. 둥근 상자의 `border-style` 중 `groove`/`ridge`/`double`/`inset`/`outset` 은 띠/음영으로 근사한다(각진 상자와 같은 규칙). `dashed`/`dotted` 둥근 border 는 변마다 고리 가운데 선을 따라 그리므로 모서리에서 대시가 변마다 따로 시작한다. 표의 `border-collapse: collapse` 와 `border-radius` 는 함께 쓰지 않는다(radius 무시).
7. 블러 그림자는 한 그림자당 6,000,000 화소까지만 계산하고 더 크면 블러 없이 그린다. 블러/그라디언트는 확대(`scale`) 때 이미지를 확대하므로 흐릿할 수 있다(그라디언트 Paint 는 해상도 독립). 둥근 클립/도형 클립은 안티앨리어싱되지 않는다(Java2D 클립은 화소 단위). 히트 테스트는 둥근 모서리를 고려하지 않는다(모서리 바깥 화소도 상자로 인식).
8. 실제 Swing 창에서의 눈 확인과 Chromium 과의 화소 비교는 하지 않았다. 이미지 로딩 완료 후 재배치 경로(`PageResources` → `PageView`)는 기존 P09-07-b 의 시험으로 검증된 것을 그대로 쓰며 이 작업에서 새로 확인한 것은 PENDING → LOADED 시 레이어가 나타나는 렌더링 단계뿐이다.

미해결 사항(문서화된 한계, `VerticalText`/`InlineLayouter` 클래스 Javadoc 과 같음):
1. 똑바로 선 문장 부호와 괄호(UAX #50 의 `Tu`, `Tr`: `、`, `。`, `「`, `」` 등)의 **세로 자형(OpenType `vert`)은 적용하지 않는다**. 평범한 가로 글리프를 칸에 놓으므로 `「` 가 `﹁` 모양이 아니고 `、` 가 칸 오른쪽 위에 오지 않는다. 규격 5.1.1 은 `Tr` 의 대체 자형이 없으면 눕혀서 합성해도 된다고 하나 합성하지 않았다.
2. 똑바로 선 글자의 칸은 글꼴의 세로 advance 가 아니라 1em 이다(규격은 세로 메트릭 합성 방법을 정하지 않는다).
3. 조합(`text-combine-upright`)은 텍스트 노드 하나(텍스트 구간) 안에서만 한다. 요소 안의 여러 텍스트 노드나 상자 경계로 끊긴 숫자 연속(`12<span>34</span>`)은 규격 9.1.1 이 요구하는 "전체 연속이 조합 가능하면 조합하지 않음"을 지키지 않고 따로 조합한다. 조합 묶음의 공백 처리는 규격 3 에서 미정이라 그대로 둔다. 압축은 가로 스케일만 쓴다(`hwid/twid/qwid` 자형 없음, 전각 → 반각 변환 없음).
4. 한 줄의 서로 다른 글꼴 크기/글꼴은 논리적 줄의 알파벳 기준선에 맞춘다(규격 4.2 의 중앙 기준선 정렬은 한 줄이 같은 글꼴일 때만 일치).
5. `text-orientation: upright` 는 줄 단위(컨테이너) 방향 강제만 한다(인라인 요소가 `mixed` 로 되돌리는 경우의 ltr 처리 없음). 양방향 문자(아랍어/히브리어)를 `mixed` 세로 줄에 쓰면 이전처럼 눕혀서 양방향 재배열한다.
6. 블록 내용 안에서 텍스트 노드 경계의 줄바꿈 기회는 그대로 없다(조합 묶음과 한글 음절 사이만 추가). 한글 음절 사이 줄바꿈 기회 추가는 기본 `word-break: normal` 의 가로쓰기 한글 문단에도 적용되어 줄바꿈 결과가 달라질 수 있다(Chromium 과 같은 방향의 수정).
7. 실제 Swing 창에서의 눈 확인은 하지 않았다(헤드리스 이미지 PNG 만 확인).
