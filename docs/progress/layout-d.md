미해결 사항(문서화된 한계, `GridLayouter` 클래스 Javadoc 과 같음):
1. subgrid(Level 2)와 masonry(Level 3)는 지원하지 않는다(`subgrid` 키워드는 `auto` 트랙 하나로 취급된다).
2. 항목의 기준선 정렬(`baseline`, `first/last baseline`)은 `start` 로 취급한다(11.5 의 shim 과 기준선 공유 그룹 없음). 컨테이너의 기준선은 첫 행 첫 항목의 기준선이다.
3. 11.1 의 둘째 패스(행 크기를 정한 뒤 항목의 min-content 기여가 바뀌면 열을 한 번 다시 푸는 것)가 없다. 높이가 너비에 영향을 주는 항목(직교 흐름, 다단, 종횡비 항목)이 있는 그리드에서 열이 규격 결과와 다를 수 있다.
4. `calc()` 트랙 크기는 `auto` 로 취급한다. 이름 있는 `span`(`span NAME 2`)은 이름을 무시하고 트랙 수로만 센다. 자동 반복 묶음 끝의 선 이름(`repeat(auto-fill, [a] 100px [b])` 의 `[b]`)은 반복마다 합쳐지지 않는다(숫자 반복은 합쳐짐).
5. 항목의 백분율 padding/margin 은 그리드 영역이 아니라 컨테이너 너비에 대해 푼다(영역을 안 뒤의 재해석 없음). 백분율 높이는 최종 배치에서 영역 높이에 대해 풀린다.
6. 그리드 영역이 포함 블록이 되는 것은 위치 지정 그리드 컨테이너의 **직접 자식인** 절대 배치 상자뿐이다(후손은 padding box).
7. `visibility:collapse` 항목은 접히지 않는다. 그리드 컨테이너는 열이나 쪽 사이에서 나뉘지 않는다(`break-*` 속성이 CSS 엔진에 없다).
8. 큰 점유 영역(256 칸 초과)은 사각형으로 저장하므로 겹침 검사는 사각형 수에 비례한다(극단 값에서만 해당).

### 2026-11-16 P10-03-a CSS Flexible Box Layout Level 1 (플렉스 컨테이너)
현재 작업 번호: P10-03-a (P10-03 의 첫 모듈)
완료한 내용:
- `BoxBuilder.fillFlex`: `display:flex|inline-flex`(와 `-webkit-` 별칭)의 자식을 플렉스 항목으로 만든다. 자식 요소는 블록화(`block()`)하고 float 는 무시(`floatSide = NONE`), 연속된 공백 아닌 텍스트는 **익명 블록 항목**(공백뿐이면 만들지 않음), `display:none` 건너뜀, `display:contents` 는 자식이 그 자리에 들어옴, `br/wbr/input[hidden]` 은 항목이 아님, `::before/::after` 는 항목, **절대 배치/fixed 자식은 항목이 아닌 흐름 밖 상자**(포함 블록 목록에 등록하고 컨테이너의 자식 뒤에 둠). 항목은 항상 BFC 루트이며 위치 지정이 없어도 `z-index` 가 정수이면 쌓임 맥락(`hasZ`, `stackingContext`). 항목은 `order` 로 **안정 정렬**하고(`LayoutBox.children` 이 order 를 반영한 문서 순서 = 그리기/히트 순서) 항목 하위 상자의 생성 번호(`LayoutBox.order`)를 같은 집합 안에서 치환해 트리 순서 타이브레이크가 order 를 따르게 한다.
- `FlexLayouter`(신규): CSS Flexbox 9장 알고리즘. 항목 준비(margin/padding/border 를 주축·교차축의 시작/끝으로 옮김, auto margin, 정렬), flex base size(`flex-basis: auto|content|max-content|min-content|<길이/%>`, 지정 크기, 내용 크기; 열 방향은 교차축 너비에서 **지정 높이를 무시하고 잰** 내용 높이 — `LayoutBox.measureContent`), 자동 최소 크기(내용 크기 제안과 지정 크기 제안 중 작은 값, 스크롤 컨테이너/`min-*` 지정은 제외), min/max, 가상 주축 크기, 줄 나누기(`nowrap|wrap|wrap-reverse`, 높이가 정해지지 않은 열은 `max-height` 한계), 컨테이너 주축 크기 결정(정해진 값 또는 가상 크기 합을 min/max 로 제한), **유연한 길이 풀이**(9.7: 고정, 초기 남는 공간, 계수 합 < 1 처리, grow/shrink 분배(shrink 는 base size 로 가중), min/max 위반 고정 반복), 가상 교차축 크기, 줄 교차축 크기(한 줄 컨테이너의 정해진 교차축 크기, 기준선 정렬 묶음, min/max 제한), `align-content`(stretch/start/end/center/space-between/around/evenly, 음수 남는 공간 대체, `safe`), `align-self`/`align-items`(stretch(재배치), start, end, center, first baseline; `safe`), 교차축 auto margin, 주축 auto margin, `justify-content`(flex-start/end, start/end/left/right(쓰기 방향 기준), center, space-between/around/evenly, 음수 대체, `safe`), `gap`/`row-gap`/`column-gap`(백분율 포함), `row-reverse`/`column-reverse`/`wrap-reverse`/`direction:rtl`(축을 뒤집는 방식: 플렉스 좌표로 계산한 뒤 물리 좌표로 거울 반사; margin 은 물리 쪽을 유지), 컨테이너 기준선(첫 줄의 기준선 정렬 항목 또는 첫 항목; `inline-flex` 가 줄 안에서 사용), 고유 너비(`intrinsic`: 행은 항목 합+gap, 줄바꿈하는 행의 min-content 는 가장 넓은 항목, 열은 가장 넓은 항목), 절대 배치 자식의 정적 위치(컨테이너 content box 를 사각형으로, `justify-content`/`align-self` 로 시작/가운데/끝 정렬 — `AbsoluteLayouter` 가 `LayoutBox.staticW/H/AlignX/Y` 를 사용). 항목은 `BlockLayouter.finish` 로 사용 너비/강제 높이에서 배치하며 같은 크기로는 다시 배치하지 않는다.
- `BlockLayouter`: `finish` 가 플렉스 컨테이너를 `FlexLayouter.layout` 으로 보내고 기준선을 보존, `intrinsic` 이 `FlexLayouter.intrinsic` 으로 보냄, `toContent` 공개(패키지), `finish` 가 `measureContent` 에서 지정/최소/최대 높이를 무시.
- `PaintWalker`: 플렉스 항목은 inline-block 처럼 **통째로**(배경+내용) 인라인 콘텐츠 단계에서 자식(= order 반영) 순서로 그린다(CSS Flexbox 4.2). `z-index` 정수 항목은 쌓임 맥락. `PaintSequence`(히트)는 같은 순회를 쓴다.
- `LayoutBox`: `flexContainer`, `flexItem`, `measureContent`, `staticW/H/AlignX/AlignY` + 공개 `isFlexContainer()`, `isFlexItem()`(추가만).

미해결 사항(문서화된 한계, 완료를 막지 않는 세부 동작):
1. `visibility:collapse` 항목은 접히지 않고 `hidden` 처럼 그리지 않기만 한다(미구현).
2. `last baseline` 은 `end` 로 대체, 열 컨테이너와 `wrap-reverse` 에서의 기준선 정렬은 `start` 로 대체(규격의 합성 기준선 규칙 없음).
3. 표 항목은 stretch 하지 않고(자신의 너비/높이 규칙 유지) 표의 너비는 `flex` 로 강제할 수 없다(사용 가능한 너비만 전달).
4. `aspect-ratio` 속성은 레이아웃 전체에서 아직 지원하지 않는다(치환 요소의 고유 비율만 사용).
5. 절대 배치 자식의 정적 위치는 자식 크기를 안 상태에서 가운데/끝 정렬하지만, 너비가 shrink-to-fit 인 경우 사용 가능한 너비를 정적 위치 사각형이 아닌 포함 블록 기준으로 계산한다.
6. 항목 높이가 `height: <백분율>` 이고 컨테이너 높이가 정해지지 않은 경우 auto 로 처리한다(규격과 같음). 항목 안의 백분율 높이 자손은 stretch 된 항목의 높이를 정해진 것으로 보지 않는다(Chromium 은 보는 경우가 있음).
7. 항목이 스크롤 컨테이너(`overflow` ≠ visible)일 때 자신의 스크롤 범위는 레이아웃에 반영하지 않는다(자르기만).
8. 중첩 플렉스 컨테이너는 항목마다 최대 2회(측정/최종) 배치하므로 깊은 중첩은 지수적으로 느려질 수 있다(12단 시험 통과).
